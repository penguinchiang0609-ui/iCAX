# 通用可编辑刀路组件规格

日期：2026-10-26。状态：目标规格，供实现与验收使用；本次补充刀路图层契约。

## 1. 定位

`IntentToolpath` 是独立、可复用的刀路领域组件。刀路是可编辑的加工对象；精确几何是其组成部分，工艺是作用于刀路的操作能力。

原始刀路、绘制刀路、打断结果、合并结果和工艺结果使用统一的刀路身份、选择与编辑契约。刀路不因来自某种工艺就变成只能显示的计算缓存。没有工艺、机床或加工参数的刀路，也可以绘制、编辑、删除、复制、保存和撤销。

通用组件提供对象、操作关系与一致性机制。几何计算通过中性服务实现；材料和设备相关的工艺由注册的算法模块提供。FiveAxisCAM、TubeDesigner 等产品通过适配器接入。

基础数据结构及其行为契约一次完整确立并交付：对象身份、精确几何、操作与端口、来源映射、派生结果继续编辑、删除与替代、图层及刀路归属、工艺注册、局部并行计算、事务、撤销和保存属于同一验收范围。不得以缺失其中一部分的中间模型接管产品，或留给各产品另建数据分支补齐；未来扩展通过既定能力和注册接口完成。

## 2. 模块边界

| 归属 | 职责 |
| --- | --- |
| IntentToolpath | 可编辑刀路、几何段与锚点、图层目录与归属、基础编辑命令、操作图、来源映射、稳定输出身份、有效输出解析、通用校验与增量调度 |
| 几何服务/工艺模块 | 精确几何算法、微联/引线/补偿等计算、适用条件、材料语义及专用校验 |
| 产品适配器 | CAD/识别结果接入、工件与装夹上下文、工艺预设来源、产品能力声明、编程业务流程 |
| 共享编辑 UI | 刀路与区段选择、编辑控制器、参数描述呈现、操作与来源显示、交互状态保护 |
| ProcessPath、作业规划与 Machine | 编译执行路径、加工排序、连接空移、时间规划、机床轴轨迹、碰撞验证和后置输出 |

刀路核心不包含激光功率、某台机床轴名、管型分类或特定产品面板分支。通用语义可以表达“加工/不加工区间”；激光插件将其解释为开关光，其他切割插件提供各自的执行解释。

机床显示姿态和视图变换不能反向改写刀路源几何。跨工件运算必须明确采用哪个坐标系以及哪些摆放变换，不能读取隐含的当前显示矩阵。

## 3. 对象及身份

### 3.1 刀路文档与加工方案

文档属于宿主工程，容纳刀路、操作和分组。加工方案明确当前采用的操作分支及输出根。工件归属与文档组织分开；一条共边结果可以服务多个工件。

同一方案内，一个可替代的完整输出只能由一个启用的替代操作消费。对同一输入做多个加工方案时，应复制或建立独立方案。只读分析可以多次引用输入，不形成替代。

### 3.2 刀路

刀路具有稳定 `PathId`。名称、用户编号和显示顺序均不作为引用标识。

刀路至少包含或关联：

- 当前几何与语义版本、当前操作输出位置。
- 精确曲线段、连接顺序、遍历方向、起点与开闭状态。
- 明确的坐标系、可选承载面、工件归属和保留材料侧。
- 来源和精确区间映射。
- 当前方案中的加工图层、显示图层归属及其继承/显式指定规则。
- 启用、删除、来源有效性、结果新旧状态。
- 可选姿态、工艺参数、加工事件等扩展数据。

几何修改和来源更新不会重新分配 `PathId`。打断、合并等改变对象数量时，按操作语义创建或匹配输出刀路身份。

### 3.3 精确几何、段和锚点

基本曲线链是有序、连续的精确曲线集合；开闭判定使用明确的几何容差。分离曲线通过多条刀路或刀路组组织。显示采样点不作为权威几何，也不作为持久选择地址。

每段具有稳定段标识和原生参数域。锚点引用段、参数、方向及必要的左右侧/接缝语义。闭合曲线的起终点别名、跨接缝区间和反向遍历必须可区分。

二维平面、曲面 UV 和三维曲线声明各自的权威表达及映射关系。不得把彼此独立编辑的二维、三维副本同时当作同一刀路的权威值。投影或近似表达需声明精度与来源。

几何段来源可以是输入段的区间，也可以是由某操作构造的新段。引线、连接圆角等构造段不能伪装成原 CAD 边上的参数位置。

### 3.4 刀路身份与计算版本

例如给 C 加引线，可以保持 C 的逻辑身份，得到 C 的新版本。操作输入指向加引线之前的明确输出位置，输出指向加引线之后的位置。依赖图建立在操作及其输出上，不以“C 引用当前 C”表达。

版本用于并发校验、缓存和来源定位，不要求永久保存每次编辑的整份几何副本。活动操作图、当前结果、必要的最近有效结果与框架撤销日志分别管理。

### 3.5 图层与刀路归属

图层是通用刀路文档中的持久对象，具有稳定 `LayerId`。每条刀路在当前方案中分别属于一个加工图层和一个显示图层，可单独或批量设置；层名、颜色和列表顺序不能充当引用标识。

| 图层 | 职责 |
| --- | --- |
| 加工图层（ProcessingLayer；切割适配器中称 CuttingLayer） | 加工工艺分组、工程内工艺绑定；方案可明确控制该层是否参与加工，并向规划提供排序要求 |
| 显示图层（VisibleLayer） | 颜色、显示/隐藏、锁定、选择过滤及按层批量选择；不决定是否加工 |

无工艺的绘制刀路也有图层归属，不要求先绑定切割工艺。新建文档提供 8 个可编辑显示层及一个默认加工层，创建刀路时将当前默认层写入定义；此后改变默认层只影响新建刀路。共享源被多个方案引用时，换层只修改指定方案的归属，不串改其他方案。

图层目录和归属不依靠组织树、操作父子关系、工艺参数里的字符串键或前端显示缓存表达。移动刀路到另一层不改变 `PathId`、几何、来源或分组，不增加几何编辑操作；加工绑定变化仍须使实际读取该工艺的后继失效。

### 3.6 编辑和衍生中的图层规则

| 场景 | 图层规则 |
| --- | --- |
| 反向、改起点、一对一几何/工艺编辑、固化 | 保留当前方案中该刀路的归属；给 C 加引线不会把 C 移回上游图层 |
| 打断、分段、微联产生独立结果 | 新结果默认按声明继承对应输入的图层；每条结果可独立换层 |
| 多输入合并、共边或桥接 | 各类图层分别检查；输入归属一致时可继承，不一致时显式指定该类结果图层，不默认取第一条 |
| 复制刀路 | 新身份默认取得源刀路当前有效归属，后续换层互不影响 |
| 上游重算 | 唯一匹配的结果保留显式归属；未覆盖的结果按继承规则解析，不能重置已换层刀路 |

继承是保存的规则，显式换层是对该结果的覆盖；用户可明确恢复继承。上游换层只传播到仍继承它的结果。输出角色发生歧义时保留原归属和诊断，不将覆盖移给最近一条结果或按下标套用；角色退役后其覆盖休眠，同一角色恢复后继续生效。

创建、重命名、修改层属性、单条/批量换层和恢复继承均支持原生撤销。删除有引用的图层必须同时指定同类目标层，原子迁移全部方案中的成员、默认层及继承策略等引用；不能删除刀路、丢失休眠覆盖或留下悬空引用。默认层只能在同一事务中替换后删除。损坏导入中的缺层引用报告错误，不静默换成默认层。

### 3.7 图层与加工、显示的边界

隐藏显示层只改变可见性及画布拾取；层管理和刀路列表仍能定位其成员。锁定禁止成员编辑，但不等于禁止加工。按层选择和筛选不改变当前方案的有效加工输出；仅加工图层的明确参与设置或刀路参与命令可以排除加工。

加工图层的参与设置应用于已解析的终端结果，不能剪断来源依赖或复活被替代的输入。层内顺序和层间排序要求交由作业规划与加工块约束共同检查，不能用图层列表顺序覆盖必要先后关系。空层或明确停用的层不等于计算失败；尚未确定的输出不能因隐藏或停层而被当成完整结果。

层名、颜色、显隐和锁定变化只更新展示与交互，不重算几何或使加工验证失效。换加工图层或修改层内工艺绑定时，按实际依赖更新参数、相关几何工艺、执行编译和验证；原始曲线保持不变。层工艺绑定使用工程内快照，操作显式参数优先于层默认值，缺少工艺不能用虚构默认参数冒充可加工。

### 3.8 场景右侧图层栏与默认 8 层

场景右边缘显示独立的竖排图层栏，每层用色块和简短名称表示，颜色就是成员刀路的显示颜色。右侧色块对应显示图层，不增加两套重复色块栏，不在点击换色时暗中切换加工工艺。

初始图层名为“图层 1”至“图层 8”，默认新建刀路使用图层 1；以下仅为可修改的初始配色：

| 初始层 | 颜色 |
| --- | --- |
| 图层 1 | 红 `#EF4444` |
| 图层 2 | 橙 `#F59E0B` |
| 图层 3 | 黄 `#EAB308` |
| 图层 4 | 绿 `#22C55E` |
| 图层 5 | 青 `#06B6D4` |
| 图层 6 | 蓝 `#3B82F6` |
| 图层 7 | 紫 `#8B5CF6` |
| 图层 8 | 粉 `#EC4899` |

- 选中一条或多条刀路后，点击某个图层色块，所选刀路一次性归入该层并立即使用该层颜色；选择保持，主体线条不被统一的选中颜色覆盖。选中效果通过外描边、线宽或控制点表达。
- 没有选择刀路时点击色块，将该层设为后续新建刀路的当前层；已有刀路不随之换层。有选择时换层不擅自改变新建默认值。
- 提供新增、删除、重命名和自定义配色入口，8 仅是初始数量，可以继续增加或删除；同色层仍以 ID/名称区分。颜色更改同步更新该层全部刀路，图层数量多时竖栏内部滚动。
- 删除不删除刀路。有引用时选择同类接收层并原子迁移；仅剩一层时须先创建接收层再删除。普通换层和配色直接提交，只有真实迁移选择才需要交互决定。
- 图层名称、数量、颜色、当前层和刀路归属随工程保存，重开不恢复默认 8 层或重置自定义配色。新增、删除、换层和配色均支持撤销/重做。

色块栏及其成员颜色使用公共图层查询与命令，不保存前端私有图层表。布局不能挤掉或重建属性侧栏；改色、换层和异步响应都遵守焦点、选区及各层滚动保护规则。

## 4. 用户要求的完整链路

以开曲线 A 的内部留出一个不切割区间为例：

```text
绘制/导入 A
  -> 微联操作 M
       -> B
       -> C 的基础输出
            -> 给 C 加引线 L
                 -> C 的当前输出

当前加工：B + C 的当前输出
```

B、C 都具有独立刀路身份，可以直接选择，也可以继续打断、合并、施加工艺、删除或复制。A 继续作为来源存在，已消费的 A 和 C 的旧输出不重复加工。

修改 A 后，M 根据精确来源映射更新 B、C；L 继续作用于能够唯一对应的 C。编辑 B 只影响 B 及其依赖后继，不回写 A，也不修改 C。

### 微联输出数量

输出数量由实际连通关系决定，不写死为两个：

- 开曲线内部去除一个加工区间，通常得到两条加工刀路。
- 闭环去除一个连续区间，通常得到一条开刀路。
- 闭环去除两个分离区间，通常得到两条开刀路。

保留的材料区间另有明确记录。它可以生成不加工跨越的连接意图，但不强制生成一条参与切割的“微联刀路”。具体执行路径由工艺和后续规划共同确定。

## 5. 基础操作语义

| 操作 | 输入/输出 | 身份及语义 |
| --- | --- | --- |
| 绘制 | 0 → 1 或明确的多条 | 创建独立刀路；无须先有工艺或 CAD 特征 |
| 直接几何编辑 | 1 → 1 | 保持刀路身份，在当前来源之后记录局部编辑 |
| 反向、改起点 | 1 → 1 | 保持身份；物理锚点、保留材料侧和附着数据正确映射 |
| 内部分段 | 1 → N | 形成可编辑结果；保留约定的内部加工组织 |
| 打断为独立刀路 | 1 → N | 创建独立输出与加工组织，输入被替代 |
| 几何合并 | N → 1 | 创建结果；保持输入来源和各区间语义，输入不重复输出 |
| 分组/解组 | N → N | 只改变组织关系，不隐式改几何或建立替代 |
| 显式桥接 | N → 结果集合 | 新连接有独立构造来源、加工含义和参数 |
| 删除刀路 | 1/N → 0 | 删除当前输出；保留必要的删除规则和撤销依据 |
| 复制 | 1/N → 独立副本 | 新身份；明确为独立快照或显式关联副本 |
| 解除关联/固化 | 1 → 1 | 用户明确将当前精确结果作为独立定义，保留历史来源说明 |

几何合并要求连接关系成立。未连接的输入不能悄悄补直线或放宽容差；应采用分组或显式桥接。跨坐标系、材料侧、参数场或工艺冲突必须由明确策略处理，不能默认保留第一条并丢弃其他信息。

局部操作必须覆盖其替代范围：未被修改的部分继续输出，去除部分必须有明确的删除/排除声明。不能只返回选中的变化段而使其他段无声消失。

## 6. 工艺作用与可编辑性

工艺类型、工艺预设、工艺实例和计算结果分开。工艺实例记录输入、选择范围、实际参数和顺序；预设选入工程后成为工程内的参数快照。

工艺可能修改几何、拓扑、方向、姿态、参数场或事件，支持多输入、多输出。算法通过注册接入，不能要求每新增一种工艺都改核心参数大表或中心分支。

每个工艺结果继续使用通用刀路的身份、段、锚点和编辑接口。拓扑改变时，几何、姿态控制、事件、保留侧和后续工艺的范围映射需共同更新。

微联的材料保留、引线的材料侧和补偿的方向等专用正确性由工艺模块校验。仅有来源区间守恒或输出数量正确，不代表制造语义正确。

## 7. 六种关系分别管理

| 关系 | 决定内容 |
| --- | --- |
| 组织关系 | UI 分组、浏览和局部所有权；允许多个过滤视图，不复制业务对象 |
| 图层归属 | 当前方案中加工图层、显示图层及继承/覆盖；跨组织组和工件筛选，不改变操作依赖 |
| 操作依赖 | 哪个结果由哪个输入产生，改变后重算哪些后继；多输入且无环 |
| 替代关系 | 哪些输入不再独立输出；从启用操作的替代输入及作用域推导 |
| 加工组织约束 | 独立排序单元、内部执行块及必要前后约束；交给作业规划使用 |
| 工件归属 | 结果服务哪些工件、是否属于完成判定；不限制为单一工件父树 |

工艺内部的 B、C 可以保留同一加工块，同时始终可以被选择和编辑。是否允许它们独立参加全局排序由明确的加工组织约束决定，不能由“树上是子节点”推断编辑权限。提升为独立加工单元是明确操作。

## 8. 稳定输出与重新关联

输出角色来自操作实例、稳定锚点/特征及语义角色，不使用数组下标或显示顺序作为身份。例如微联实例 M 的前段、后段依靠 M 和边界锚点匹配。

重算依次执行：

1. 验证来源与输入版本，计算新结果及精确映射。
2. 唯一对应的输出保留端口、刀路及段身份。
3. 明确新增的输出创建身份；消失的输出进入已退役/不可关联状态。
4. 映射后续编辑、姿态、事件和工艺作用范围。
5. 对无法唯一对应的关联保留参数并标记需要重新关联，不自动吸附到最近一段。

锚点越过另一锚点、闭环拆开、合并使区间角色改变等，均需要检查真实拓扑含义。同一个角色字符串不能掩盖语义已改变的事实。

## 9. 删除、取消、禁用与来源缺失

### 9.1 删除结果

删除 B 表示从当前加工结果中删除 B。微联 M 继续存在，A 继续被 M 消费；A 更新时 B 的删除决定继续生效。删除最后一个结果也不能自动恢复 A。

删除需要持久关联到稳定输出位置/角色。只删除一次计算得到的实体、不保留规则，会在下次重算时复活，属于错误实现。

删除组织组时，命令明确展开当前成员；引用这些成员的外部后继保留其参数和最近结果并进入来源失效，不随组织树被物理删除。

### 9.2 取消操作

取消微联 M 是撤销该衍生关系，与删除 B 不同。原输入可恢复时，预检给出恢复输出及对后继的影响。存在依赖 B/C 的后续操作时，必须明确保留失效关联、重新绑定或将当前结果固化的策略。

输入已缺失时不擅自抹掉现有结果，也不暗中固化。组件返回明确的影响结果，宿主选择“保留结果并解除关联”等明确命令。

### 9.3 禁用、删除来源与故障

临时不参与加工、删除结果、取消操作分别表达。禁用一个拓扑操作也不能无条件将 B 的后继迁到 C 或 A。

来源、算法或插件缺失时，保存用户参数与最近有效精确结果用于查看、恢复、固化或重新关联；它们不自动成为可生产结果。

## 10. 当前有效加工输出

有效输出由加工方案、操作端口、替代、删除、启用、加工图层参与、有效性和加工组织约束共同解析。组织树叶子列表或当前可见刀路不能作为实际加工清单。

解析器必须：

- 沿启用操作的替代关系展开输入，追踪到当前终端输出。
- 区分同一刀路的基础输出与后续编辑输出，只发出当前结果。
- 对合并等多输入路径去重，避免从两个来源根重复输出同一结果。
- 保留删除决定；结果缺失或失败时不回退加工原始整条输入。
- 返回完整性状态和未就绪项，而不是过滤掉失效刀路后声称成功。

结果为 `Complete / Incomplete / Invalid`，附带当前路径、加工块、显式排除项和诊断。用户明确删除全部路径可以是“完整且有意为空”；缺少算法造成空结果属于不完整。

## 11. 增量更新与并行

依赖至少区分几何、拓扑、方向、姿态、工艺参数、事件、来源、坐标变换、工件归属和展示信息。工艺声明实际读写的数据及上下文。

纯名称变化不重算几何。纯功率字段改变且未影响几何相关派生参数时，不重算补偿与空移。修改一条刀路只传播到实际读取其变化的后继；相同端点、姿态和环境的连接空移可以复用。

一个依赖链按拓扑顺序计算，独立刀路/分支可以并行。补偿可能读取姿态，不能通过并行或固定流水顺序忽略这种依赖。

异步结果按所读输入及版本验收；无关刀路的修改不应单凭全局版本号使任务全部失效。过时结果不得覆盖较新的编辑。

## 12. 保存、撤销与交互

刀路定义、图层目录、默认层、方案内归属/继承/覆盖、层工艺快照与参与设置、操作实例、参数、端口、映射、删除规则和需要保存的结果均是工程数据库数据。CAD/BRep、显示网格、材质等资产继续使用资源系统；显示采样和大批量传输副本可以是运行期资源。

不为每次编辑永久复制整套工程或所有上游快照。当前操作图与撤销日志分别保存；计算缓存按保留策略管理。

一次用户编辑包含关联、身份、替代、分组和删除等全部变化，形成一个原生撤销单元。后台派生结果发布不清空撤销/重做历史。撤销后只有输入指纹匹配的结果才能恢复为 Current；缓存不足时标记待更新并重算。

输出数量由后台计算确定时，核心在原子派生发布中登记身份并提交完整结果。撤销使相关输出退出活动集合，重做复用同一操作与可唯一匹配的结果身份；休眠身份记录不自行参与加工。框架的派生事务、身份归属和晚到任务防护必须与基础结构一并到位，不采用同步降级或事后补撤销的中间实现。

普通可逆编辑不额外增加确认框。真实多解的目标/冲突需要明确选择，但不能用默认参数或静默丢弃关联解决。

刀路列表和属性区可查询所属加工图层、显示图层；多选不同归属时显示混合值，支持一次批量换层。场景右侧图层栏按第 3.8 节呈现显示层；图层管理可另提供显隐、锁定、按层选择与加工参与入口。图层变化走同一局部刷新与交互状态保护机制。

前端刷新优先更新必要 DOM 和场景对象。保持输入节点、画布、监听器、焦点、光标选区和左右及内部滚动位置；在实际更新前捕获最新状态，避免旧回调抢回其他项目或后续选择的焦点。

## 13. 跨产品验收

通用组件必须有不加载 FiveAxisCAM、TubeDesigner 或 Machine 的独立测试宿主。至少通过二维切割适配器与空间切割适配器验证相同命令和存储契约；这不等于已经交付一个新的平面切割产品。
