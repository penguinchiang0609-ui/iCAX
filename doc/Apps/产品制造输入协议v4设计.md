# 产品模板制造声明协议 v4

产品模板的基础零件与几何资源由 `display(parameter_values)` 唯一提供。`manufacturing(parameter_values)` 返回引用这些零件的连接与装配工艺声明。宿主组合两份输出，交给下游执行；产品模板不根据焊接、U 形折弯或空间连续折弯预先划分制造件。

本文描述当前公开格式：[显示协议 v2](产品显示脚本协议.md)与制造协议 v4。旧 [v3](产品制造输入协议v3设计.md)、[v2](产品制造输入协议v2设计.md)和 [v1](产品制造脚本协议.md)文档保留历史及兼容记录，其独立制造资源表、设计输入表或加工结果图不作为新版返回结构。

## 两个入口的职责

| 所有者 | 保存或生成的内容 |
|---|---|
| 宿主产品实例 | 使用哪个产品模板、产品参数值、生成状态与保存快照 |
| `display` | 唯一的基础 `resources` 与 `items`、成品几何、实例树、固有管型／板型等组件和标注 |
| `manufacturing` | 引用基础零件的全部连接、所选装配工艺、该工艺的局部输入和资源草稿 |
| 下游装配工艺 | 实际制造件的拆分与合并、连续路径、加工毛坯、余量、槽位、加工与成形、实际来源映射 |

基础零件有独立身份；相同几何可以引用同一个资源。管型截面也是零件自身组件引用的共享资源，产品不创建独立“母材”实体。下游在执行工艺时准备的加工毛坯属于制造结果。

修改工艺选择时，共享的设计构件及设计位置保持稳定，下游制造件的数量、身份与路径可以改变。例如同一组三面窗设计构件可以由 U 形路线产生更多分段制造件，也可以由空间路线产生更少的连续制造件。隔离点是工艺输入与输出，产品不用随路线重新提供另一份零件表。

## 公开顶层结构

`display` 使用 `icax.display-model` 第 2 版，顶层精确为八个字段：`schema`、`schemaVersion`、`coordinateSystem`、`lengthUnit`、`resources`、`items`、`roots`、`annotations`。显示结果不含 `connections`。

`manufacturing` 使用 `icax.manufacturing-model` 第 4 版，顶层精确为四个字段：

| 字段 | 内容 |
|---|---|
| `schema` | `icax.manufacturing-model` |
| `schemaVersion` | `4` |
| `connections` | 连接声明数组，参与者引用共享 `display.items` 的键 |
| `processes` | 待执行工艺数组，输入引用共享设计对象或显式依赖的前序输出 |

两份结果都不回传产品模板引用或产品全量参数。制造结果不另带 `resources`、`items`、`roots`、`designInput`、坐标单位、来源表或执行后的几何；这些不能伪装成第五个公开字段。

坐标与长度单位统一取共享显示模型的声明。工艺调用中的 `definition.parameters` 仅表示该次工艺实际需要的局部输入，与宿主持有的产品参数字典分别保存。

## 共用零件上的设计事实

共用 `items` 可带材质、分类、采购方式、数量及管型／板型等固有组件。它们使用 `material`、`materialCategory`、`categoryKey`、`categoryName`、`partKind`、`sourcing` 等中性属性，不借制造属性携带路线选择、加工状态或槽位。

`assemblyFrame.member` 表达真实设计起终点、轴长和截面坐标系。构件轴向沿起终点，截面轴为单位、正交轴，截面偏置和 `centerlineUV` 保留原设计基准。截面法向取 `cross(xAxis, yAxis)`；若显式提供 `zAxis`，必须与该法向一致。既有固定构件允许沿法向反向挤出，不能因此镜像原截面。窗口整组工艺生成的设计输入另外要求截面法向与构件轴向一致。这个组件描述构件自身的位置，不能用显示几何的包围盒反推，也不声明这根构件最终是一根料还是连续料的一段。

`tubeDesigner.profile.sectionResource` 指向唯一公共资源表中的真实截面节点，保留管型组件原轮廓的局部坐标基准。渲染使用的规范化轮廓可能调整局部方向，不能代替管型组件基准。若轮廓及基准与已有资源完全相同则复用；否则在同一 `display.resources` 中增加共享截面节点。现有组件的内联轮廓暂用于旧读取兼容，下游以显式 `sectionResource` 为准。

实际 `profile2d` 资源使用 `kind: "path"` 的通用闭合曲线。窗口组件的原截面若以多边形点列保存，显示资源按原顺序逐点连接，并以最后一点连接首点；原始坐标、绕向、孔洞及组件事实保留。渲染截面和被引用的原始截面资源都遵守此格式，不能只转换其中一份，也不以近似曲线替代原几何。

`tubeDesigner.profile.sectionCoordinateMap` 表达原始截面二维坐标到该构件右手截面坐标的方向关系；它保留非方、非对称及偏置截面的安装方向，不修改共享截面轮廓或显示几何。

共用零件的成品显示几何不等于加工初始毛坯。成品可以已裁切、包含装饰组合或具有最终长度。下游应根据固有截面／板型、设计位置与所选工艺准备毛坯，再完成加工，不能直接把渲染实体当作全部工艺的原料。

## 连接与整组工艺声明

`connections` 使用 `{key, kind, items, properties?}`，`items` 中的键必须存在于共享设计模型。连接可表达参与者、端部／侧面、设计接触点与方向，不能携带已经计算的刀具或加工结果。窗口的这些关系仅在制造顶层声明，不在显示结果或工艺局部 `geometry` 中再复制一份。

窗口只有一条 `assembly-process` 整组调用，键为 `window.assembly`，提供者为 `security-window-assembly`。其 `definition` 包含 `templateId`、`processInput`、`parameters`、`processDrafts`、`outputs`、`dependencies`。

`processInput` 使用 `icax.assembly-process-input` 第 3 版；这是独立的工艺输入版本，与制造顶层的第 4 版不同：

- `parts.members` 为 `{scope: "design", itemKeys: [...]}`，引用整组共享设计构件。
- `geometry.layout` 只给稳定布局事实，如 `faceType` 与 `accessDoorEnabled`。管段尺寸来自共享构件；连接来自制造顶层。
- `resources` 按工艺角色给出选用资源 `{ref: {scope, id, templateId?}}`。

`definition.parameters` 给路线、连接方式、间隙和嵌入要求等局部值；`definition.processDrafts` 按角色和所选资源保存原始草稿。产品不求值草稿，不提前调用模具或装配工艺，也不把完整产品参数传给下游。工艺提供者拒绝未知选择、缺失输入、不支持的资源范围及未声明的角色或草稿键，不能静默替换为默认方案。关闭上级选项时，宿主保留草稿值；下游先判断适用分支，不让不适用的子选项影响执行或阻断生成。

窗口当前明确输出 12 个局部参数，其中 `assemblyPlanningMode` 区分现有加工路线与独立节点装配声明。单面窗选择 `external_templates` 时，下游保留足尺未切构件和待选装配节点，制造结果标记尚未就绪；产品不提前开孔或折弯。这个选择只适用于单面窗，多面窗按实际适用分支使用 `legacy_processed`，宿主仍保存未启用的原草稿。读取历史声明时，仅恰好缺少 `assemblyPlanningMode` 的已知 11 项集合兼容为原路线，其他缺项或未知字段仍拒绝。

资源引用协议可表达 `system`、`user` 和 `template` 三种范围；当前窗口提供者支持前两种，尚不处理 `template` 范围，使用不支持范围时明确拒绝。

窗口通过 `outputs: {manufacturing: {kind: "manufacturing-set", key: "window.manufacturing"}}` 声明动态结果集合。产品不预建这些制造件，也不填写件数；集合命名空间必须唯一，不能占用设计对象键。

协议也允许后序工艺通过 `{scope: "process-output", processKey, outputKey}` 引用具名集合，`outputKey` 是生产者的输出角色，且必须显式声明对生产者的依赖。缺失引用与循环依赖必须拒绝。当前生产注册的窗口整组工艺接收设计构件集合；接续提供者仍需实现相应制造集合输入，不能把已有局部 `targets` 调用直接视为整组集合消费者。

数量与身份已确定的零件局部加工调用可以继续使用严格的 `targets` 输出绑定；窗口整组调用使用动态 `outputs`。同一调用的两种提交方式互斥。

局部调用中的 `scope: "manufacturing"` 绑定引用共用设计对象的键，`state` 指定初始毛坯或明确依赖的加工状态，不创建第二份产品零件表。显示还包括采购件时，`product-manufacturing-members` 调用显式列出参加制造的已有对象；例如铝窗的型材参加加工，显示中的玻璃与纱网保持采购件。成员选择不生成几何，也不根据材质名称推断成员。

固定管件需要额外初料时，制造声明使用下游内置 `profile-stock-preparation`，仍绑定同一个共享零件键。下游从该零件的原始 `sectionResource`、截面坐标映射与构件轴线生成真实实体；产品不传一份毛坯 CAD 图，也不创建母材实体。准备范围必须有明确来源：连接参与端的真实点和余量、沿设计轴的起止站位，或同一零件已经声明的后续工艺所需初料。连接模式只允许 `connectionKeys`、`status`、`ready` 及可选 `freeEnds`；不能混用方向或另一种范围。引用后续工艺时，该加工调用必须显式依赖备料，并从其输出状态开始。

备料记录属于执行结果中的 `tubeDesigner.workpiecePreparations`，不能冒充一次切削结果。实际物理长度与按模板精度报告的长度分别保存。初始料已准备但加工由外部节点完成时，结果保持 `await-external`、`ready: false`；选择外部加工不能暗中完成端切、孔槽或折弯。显示组件递归禁止 `cutPlanes`、`machiningFeatures`、`slotFeatures` 等加工字段。

完整板型及其平面坐标足以让下游准备真实板坯。即使没有进一步加工调用，板坯也必须是对应轮廓的实体，不能直接把显示中的装饰表面组合当作制造实体。窗口的名义全高初料采用单独的初始材料边界声明；它保留整段来源覆盖，不能伪造一个没有实际切除的端部加工来凑长度。

共用 `plate` 组件提供有限正数的板宽、板高和板厚；尺寸的工程限制由各模板保留原规则，通用协议不另加厚宽比限制。可选 `outline` 为板自身二维平面中的顶点数组，末点与首点隐式闭合；斜坡栏板保留真实多边形轮廓。有轮廓时 `areaMm2` 按轮廓面积校验，没有轮廓时按矩形面积校验，包围尺寸不能替代实际面积。

需要独立准备板坯时再提供成组的 `center`、`xAxis`、`yAxis`。装饰门的显示表面已经含凹槽或镂空，下游据该板型组件准备真实板坯，再执行表面加工；有轮廓的板坯按真实轮廓挤出。钢梯的端部加工可在局部工艺输入中声明加长截面要求，下游准备相应毛坯再裁切。公开声明不保存旧加工初态的完整几何图。

## 宿主组合、执行与保存

宿主从产品实例组件取模板引用与规范化参数，分别调用两个公开入口，独立校验后组合共享模型与制造声明。制造引用解析以这份共享模型为准；不存在的零件、资源、输出集合或依赖必须拒绝。下游执行请求提供制造声明、共享设计模型及可信执行上下文，不携带产品脚本路径或产品全量参数，也不回调产品脚本。

参数规范化须先得到全量类型正确的值，再按模板声明的显示／启用条件检查适用字段的边界，不能依赖字段排列顺序。已隐藏或禁用的草稿保留原值；数值必须仍有限，类型和枚举值必须合法，但不适用的数值范围、字符串长度或缺失子字段不能阻断当前分支。再次启用时恢复正常边界校验。只读字段仍按模板的规范值处理；前端资源库、内嵌编辑器和示意图继续共用 `parameterConditions.mjs`。

下游读取连接和所选工艺，生成实际制造对象、毛坯、连续路径与加工结果。来源可以是多个设计构件对应一件连续制造件，也可以是一件设计对象对应多个制造件。执行结果通过 `tubeDesigner.assemblyOutputSets` 记录生产工艺、输出角色、集合命名空间、实际件键与输入设计来源，宿主按实际结果统计制造件数。

固定零件以共用对象键保持身份关联，不附加连续料分配标记或展开区间。只有工艺生成、拆分或合并的制造件使用相应分配来源；不能把板件的同身份关联误当作管料展开映射。

已知固有零件、外购件和分组可以与工艺生成件共存。当前执行器允许同一直接父分组内的设计成员生成制造件；跨不同直接父分组的合并会明确拒绝。

宿主分别保存模板参数、共享基础模型、原始制造声明、执行结果和精确 BRep。保存重开使用冻结执行结果，保留资源和来源身份。后续修改工艺时由下游重建加工结果，不修改成品设计的身份和位置。

V 槽圆角与释放孔继续表示槽根避空，保留原认可的局部切除几何。K 补偿独立由工艺计算，不能以展开公式重新定义圆角。
