# 百叶窗产品参数化模板设计说明

> 目标：将市面常见百叶产品抽象成可参数驱动生成的产品模板。  
> 模板只负责 **几何、结构、拆单与零件生成**；材料选型、强度、风压、防雨、性能等级等由用户自行决定。

---

# 1. 总体设计原则

百叶产品不建议按“市场名称”各写一套完全独立脚本，而应采用统一的参数化内核：

```text
总体边界
  ↓
外框 / 支撑
  ↓
分格
  ↓
百叶区域
  ↓
叶片截面
  ↓
叶片阵列
  ↓
可选活动机构
  ↓
零件拆分
  ↓
BOM / CAM
```

公共对象建议：

```cpp
struct LouverProduct
{
    EnvelopeSpec envelope;
    FrameSpec frame;
    GridSpec grid;

    std::vector<LouverZone> zones;
    std::vector<PanelSpec> panels;
    std::vector<SupportSpec> supports;
};
```

叶片区域：

```cpp
struct LouverZone
{
    ProfileId bladeProfile;

    double bladeAngle;      // α
    double pitch;           // P
    int count;              // N

    double startOffset;     // S1
    double endOffset;       // S2

    SolveMode solveMode;
};
```

推荐三种叶片阵列求解模式：

1. **给定中心距 P，自动计算数量 N**
2. **给定数量 N，自动计算中心距 P**
3. **同时给 N、P，自动计算剩余边距**

# 2. 固定金属百叶面板

![固定金属百叶面板](./百叶窗参数化模板_assets/01_固定金属百叶面板.png)

这是最基础、也是最值得优先落地的百叶模板。

适合：

- 固定百叶窗；
- 百叶门填充面；
- 空调外机罩；
- 隐私屏；
- 设备遮挡面板；
- 百叶围栏面板；
- 简单建筑遮阳面板。

## 2.1 结构

```text
外框
├─ 上框
├─ 下框
├─ 左框
└─ 右框

内部
└─ 重复叶片 × N
```

可扩展：

```text
中横梁
中竖梁
多分格
```

## 2.2 核心参数

| 参数 | 含义 |
|---|---|
| `W` | 总宽 |
| `H` | 总高 |
| `FrameProfile` | 外框型材 |
| `BladeProfile` | 叶片型材 |
| `α` | 叶片安装角 |
| `P` | 叶片中心距 |
| `N` | 叶片数量 |
| `S1` | 顶部起始偏移 |
| `S2` | 底部起始偏移 |
| `IL` | 叶片插入左框深度 |
| `IR` | 叶片插入右框深度 |
| `CL` | 左侧装配间隙 |
| `CR` | 右侧装配间隙 |

## 2.3 叶片数量

若给定中心距：

\[
N=
\left\lfloor
\frac{H_e-S_1-S_2}{P}
\right\rfloor+1
\]

其中 \(H_e\) 为百叶有效排列高度。

若给定数量：

\[
P=
\frac{H_e-S_1-S_2}{N-1}
\]

## 2.4 叶片下料长度

若叶片从左右两边插入框体：

\[
\boxed{
L_{blade}
=
W_{bay}+I_L+I_R-C_L-C_R
}
\]

其中：

- \(W_{bay}\)：叶片所在分格净宽；
- \(I_L,I_R\)：左右插入量；
- \(C_L,C_R\)：装配间隙。

## 2.5 脚本逻辑

```text
1. 输入 W、H

2. 生成外框
   TopFrame
   BottomFrame
   LeftFrame
   RightFrame

3. 求内部净区域

4. 根据 SolveMode：
   - P → N
   - N → P
   - N + P → S1/S2

5. 逐片生成叶片：
   Yi = Y0 + i × P

6. 每片叶片旋转 α

7. 计算叶片实际下料长度

8. 输出：
   外框料
   叶片料
   可选连接孔/插槽
   BOM
```

# 3. 刚性活动百叶扇

![刚性活动百叶扇](./百叶窗参数化模板_assets/02_刚性活动百叶扇.png)

用于：

- 室内 Plantation Shutter；
- 铝合金百叶窗扇；
- 室外百叶门；
- 平开百叶；
- 推拉百叶；
- 折叠百叶；
- 上下分体百叶。

## 3.1 结构层次

```text
Opening
└─ Panel × PanelCount
   ├─ LeftStile
   ├─ RightStile
   ├─ TopRail
   ├─ BottomRail
   ├─ DividerRail[]
   └─ BladeZone[]
```

## 3.2 参数

| 参数 | 含义 |
|---|---|
| `W / H` | 总宽 / 总高 |
| `PanelCount` | 面板扇数 |
| `g` | 相邻面板间隙 |
| `Sw` | 竖框宽度 |
| `Th` | 上横框高度 |
| `Bh` | 下横框高度 |
| `Dy[]` | 中横档位置 |
| `BladeProfile` | 叶片型材 |
| `α` | 叶片角度 |
| `P` | 叶片中心距 |
| `TiltMode` | 叶片联动方式 |
| `PanelMotion` | 面板运动方式 |

## 3.3 分扇

若所有面板等宽：

\[
\boxed{
W_p=
\frac{W-(PanelCount-1)g}{PanelCount}
}
\]

其中：

- \(W_p\)：每扇面板宽度；
- \(g\)：扇间缝。

也应支持用户直接给每扇独立宽度。

## 3.4 Full Height

整个高度就是一套面板：

```text
Opening
└─ Panel
   └─ BladeZone
```

## 3.5 Café

增加：

```text
CoverHeight
或
CoverRatio
```

计算：

\[
PanelHeight=H\times CoverRatio
\]

只在指定高度范围生成面板。

## 3.6 Tier-on-Tier

增加：

```text
TierSplitY
```

结构变为：

```text
Opening
├─ UpperPanelSet
└─ LowerPanelSet
```

上下是两套独立面板，而不是一扇面板中间加横梁。

## 3.7 PanelMotion

```cpp
enum class PanelMotion
{
    Fixed,
    Hinged,
    Sliding,
    BiFold,
    TopHung
};
```

运动方式只改变外层装配关系，不改变内部叶片阵列内核。

## 3.8 脚本逻辑

```text
1. 输入开口 W/H

2. 根据 PanelCount / g 分扇

3. 每扇生成：
   左右竖框
   上下横框
   中横档

4. 中横档将内部拆成多个 BladeZone

5. 每个 BladeZone 独立生成叶片阵列

6. 根据 PanelMotion：
   Fixed      → 固定安装
   Hinged     → 生成铰链基准
   Sliding    → 生成滑轨/滑轮基准
   BiFold     → 建立面板间铰接关系

7. 输出面板零件和 BOM
```

# 4. Jalousie 可开启百叶窗

![Jalousie可开启百叶窗](./百叶窗参数化模板_assets/03_Jalousie可开启百叶窗.png)

这一类模板的核心是：

> **所有叶片分别有转轴，并通过侧边机构同步运动。**

## 4.1 结构

```text
OuterFrame
├─ Mullion[]
└─ Bay[]
   ├─ LeftGallery
   ├─ RightGallery
   ├─ Blade[]
   ├─ Pivot[]
   ├─ Linkage
   └─ Operator
```

## 4.2 参数

| 参数 | 含义 |
|---|---|
| `W / H` | 总宽 / 总高 |
| `BayCount` | 分格数量 |
| `Hb` | 单片叶片高度 |
| `t` | 叶片厚度 |
| `P` | 叶片节距 |
| `N` | 每格叶片数量 |
| `α` | 当前叶片开启角 |
| `e` | 转轴偏置 |
| `OperatorSide` | 操作侧 |
| `FillerTop` | 顶部填充片 |
| `FillerBottom` | 底部填充片 |
| `MullionProfile` | 中挺型材 |

## 4.3 分格

若分格等宽：

\[
W_{bay}
=
\frac{
W-W_{frame}-W_{mullion}
}{
BayCount
}
\]

实际程序不应写死此式，应依据所选框型材的真实占宽计算净开口。

## 4.4 叶片转轴

在叶片局部截面坐标中定义：

\[
Pivot=(x_p,y_p)
\]

也可简化为：

\[
e=\text{转轴相对叶片参考线的偏置}
\]

当前叶片姿态：

\[
T_i
=
Translate(P_i)\,
Rotate(\alpha)\,
Translate(-Pivot)
\]

## 4.5 脚本逻辑

```text
1. 根据 W/H 生成外框

2. 按 BayCount 分格

3. 插入 Mullion

4. 每格生成左右机构基准

5. 按 N/P 生成叶片

6. 每片建立 Pivot

7. 根据 α 旋转叶片

8. 生成联动点

9. 所有联动点连接成 Linkage

10. OperatorSide 决定操作机构位于左侧或右侧

11. FillerTop / FillerBottom 生成固定补片

12. 输出叶片、边框、中挺、机构和 BOM
```

# 5. 建筑遮阳百叶

![建筑遮阳百叶](./百叶窗参数化模板_assets/04_建筑遮阳百叶.png)

这一类不一定存在完整矩形外框。

典型结构：

```text
Support
├─ Blade
├─ Blade
├─ Blade
└─ Blade
```

既可以水平排列，也可以垂直排列。

## 5.1 参数

| 参数 | 含义 |
|---|---|
| `W / H` | 布置区域宽高 |
| `BladeProfile` | 叶片型材 |
| `α` | 叶片角度 |
| `P` | 叶片中心距 |
| `N` | 叶片数量 |
| `Orientation` | Horizontal / Vertical |
| `SupportCount` | 支撑数量 |
| `Xi[]` | 每个支撑位置 |
| `E` | 叶片相对端部支撑的退让 |
| `Motion` | Fixed / Rotating |
| `Pivot` | 活动时转轴位置 |

## 5.2 水平排列

叶片位置：

\[
Y_i=Y_0+iP
\]

叶片长度：

\[
\boxed{
L_{blade}=W-2E
}
\]

若左右退让不同：

\[
L_{blade}=W-E_L-E_R
\]

## 5.3 垂直排列

算法不需要重写，只需交换排列轴：

\[
X_i=X_0+iP
\]

叶片长度沿高度方向：

\[
L_{blade}=H-E_T-E_B
\]

## 5.4 支撑

用户可直接输入：

```text
SupportCount
Xi[]
```

也可提供：

```text
SupportPitch
```

自动阵列支撑。

## 5.5 脚本逻辑

```text
1. 定义 W/H 边界

2. 根据 Orientation 决定：
   Horizontal → 沿Y阵列
   Vertical   → 沿X阵列

3. 按 P/N 排列叶片

4. 每片旋转 α

5. 按 SupportCount / Xi 放置支撑

6. 叶片按 E 退让

7. 若 Motion=Rotating：
   在 BladeProfile 中读取 Pivot
   建立旋转关系

8. 输出叶片、支撑和端部零件
```

# 6. 通风百叶

![通风百叶](./百叶窗参数化模板_assets/05_通风百叶.png)

用于：

- 普通固定通风百叶；
- 折弯叶片百叶；
- 排水型几何百叶；
- 活动通风百叶；
- 带网片百叶。

此处只处理几何，不负责判断通风、防雨等性能。

## 6.1 参数

| 参数 | 含义 |
|---|---|
| `W / H` | 外形尺寸 |
| `Df` | 框深 |
| `FrameProfile` | 框型材 |
| `BladeProfile` | 叶片截面 |
| `α` | 叶片角度 |
| `P` | 叶片中心距 |
| `N` | 叶片数量 |
| `MullionCount` | 中挺数量 |
| `Xi[]` | 中挺位置 |
| `Screen` | 是否生成网片 |
| `Pivot` | 活动叶片时的转轴 |
| `ScreenOffset` | 网片所在深度位置 |

## 6.2 中挺

中挺可采用两种参数模式：

### 数量等分

```text
MullionCount = M
```

自动均布。

### 指定位置

```text
Xi = [x1, x2, ...]
```

直接在指定位置生成。

## 6.3 Screen

`Screen=true` 时生成一块内部网片几何区域。

参数可以为：

```text
ScreenProfile
ScreenOffset
ScreenInsetLeft
ScreenInsetRight
ScreenInsetTop
ScreenInsetBottom
```

## 6.4 活动叶片

若：

```text
Pivot != None
```

则叶片按转轴生成。

固定叶片则直接：

```text
Transform = Translate × Rotate(α)
```

## 6.5 脚本逻辑

```text
1. 生成外框

2. 求内部净区域

3. 按 P/N 生成叶片阵列

4. 按 Xi 或 MullionCount 生成中挺

5. 若 Screen=true：
   生成内部网片

6. 若 Pivot 有效：
   将叶片定义成可旋转构件

7. 输出：
   外框
   中挺
   叶片
   网片
   转轴相关零件
```

# 7. 连续设备遮挡屏

![连续设备遮挡屏](./百叶窗参数化模板_assets/06_连续设备遮挡屏.png)

这一类不是一个矩形窗口，而是一条沿路径连续生成的百叶围挡。

适合：

- 空调外机设备屏；
- 屋顶设备遮挡；
- 百叶围墙；
- 隐私围栏；
- 连续百叶立面；
- 带检修门的设备围挡。

## 7.1 参数

| 参数 | 含义 |
|---|---|
| `Path(P0...Pn)` | 围挡中心路径 |
| `H` | 总高度 |
| `S` | 立柱间距 |
| `PostProfile` | 立柱型材 |
| `PanelFrame` | 单块百叶面板框型材 |
| `BladeProfile` | 叶片型材 |
| `α` | 叶片角度 |
| `P` | 叶片中心距 |
| `GroundClearance` | 面板底部离地距离 |
| `Gate[]` | 检修门定义 |
| `CornerPostMode` | 拐角立柱生成方式 |

## 7.2 路径

输入：

```text
P0
P1
P2
...
Pn
```

形成二维折线路径：

\[
Path=P_0P_1P_2...P_n
\]

每一段：

\[
L_i=|P_{i+1}-P_i|
\]

## 7.3 立柱

若采用最大间距模式：

\[
n_i=
\left\lceil
\frac{L_i}{S}
\right\rceil
\]

实际单格宽度：

\[
S_i=\frac{L_i}{n_i}
\]

然后在路径段上等分生成立柱。

也可以让用户直接指定各立柱位置。

## 7.4 角柱

所有路径转折点：

```text
P1 ... Pn-1
```

默认生成角柱。

角柱方向由前后路径方向共同确定。

## 7.5 面板生成

相邻两根立柱之间：

```text
Post_i
Post_{i+1}
```

生成一个：

```text
LouverPanel
```

面板高度：

\[
H_p=H-GroundClearance
\]

内部再调用固定金属百叶面板模板。

## 7.6 Gate

检修门参数：

```cpp
struct GateSpec
{
    double pathPosition;
    double width;
    double height;
    OpenDirection direction;
};
```

门所在区间替换普通百叶面板。

## 7.7 脚本逻辑

```text
1. 输入 Path[]

2. 遍历每条路径段

3. 根据 S 布置中间立柱

4. 所有路径拐点生成 CornerPost

5. 每两根立柱之间：
   调用 LouverPanel

6. 设置 GroundClearance

7. Gate 区域替换成 GatePanel

8. 输出：
   立柱
   百叶面板
   检修门
   叶片
   外框
   BOM
```

# 8. 多分格百叶不是新模板

以下产品不应再新增脚本：

- 带中横梁；
- 带中竖梁；
- 十字分格；
- 上下不同叶片；
- 左右不同叶片；
- 多区域不同角度。

统一抽象成：

```text
Grid
└─ Zone[]
```

例如：

```cpp
struct GridSpec
{
    std::vector<double> verticalSplits;
    std::vector<double> horizontalSplits;
};

struct LouverZone
{
    Rect2D region;

    ProfileId bladeProfile;
    double angle;
    double pitch;
    int count;
};
```

这样每个区域都可以独立设置：

```text
BladeProfile
α
P
N
```

# 9. 水平、垂直、斜向叶片统一

不建议只写：

```cpp
Horizontal
Vertical
```

更通用的是：

```cpp
Vector2D arrayDirection;
Vector2D bladeDirection;
```

其中：

- `arrayDirection`：叶片重复排列方向；
- `bladeDirection`：叶片长度方向。

因此可以自然支持：

```text
水平百叶
垂直百叶
斜向装饰百叶
```

无需增加新模板。

# 10. 推荐最终模板体系

建议真正保留的核心模板：

```text
1. FixedLouverPanel
   固定百叶面板

2. RigidLouverPanel
   刚性百叶扇

3. JalousieWindow
   可开启百叶窗

4. SunLouverSystem
   建筑遮阳百叶

5. VentilationLouver
   通风百叶

6. EquipmentScreen
   连续设备遮挡屏
```

而这些：

```text
Full Height
Café
Tier-on-Tier
平开
推拉
折叠
水平百叶
垂直百叶
带中横梁
带中挺
上下不同叶片
左右不同叶片
```

都应作为：

\[
\boxed{
\text{参数组合 / 模板预设}
}
\]

而不是增加新的几何内核。

# 11. 从产品参数到 CAM 的完整流程

最终推荐工作流：

```text
产品模板
   ↓
用户参数
   ↓
结构脚本
   ↓
装配模型
   ↓
零件拆分
   ↓
型材归类
   ↓
连接关系
   ↓
孔 / 槽 / 端切
   ↓
CAM
```

每个生成零件至少保存：

```cpp
struct GeneratedPart
{
    ProfileId profile;

    double length;

    Transform3D transform;

    EndTreatment startEnd;
    EndTreatment endEnd;

    std::vector<Feature> features;

    PartRole role;
};
```

`PartRole` 可以包括：

```text
FrameTop
FrameBottom
FrameLeft
FrameRight

Mullion
Rail
Post

Blade

PanelStile
PanelRail

GateStile
GateRail

Linkage
Support
```

这样产品模板生成的不是一个“外观模型”，而是真正可继续进入拆单和 CAM 的制造数据。

# 12. 产品模板的边界

模板负责：

\[
\boxed{
\text{几何正确}
+
\text{结构关系正确}
+
\text{参数驱动}
+
\text{拆单正确}
}
\]

模板不负责判断：

- 材料是否够强；
- 叶片是否能承受指定风压；
- 百叶是否达到某个防雨等级；
- 某个叶片间距是否满足法规；
- 某个结构是否具备认证性能。

用户可以自由选择：

```text
型材
尺寸
角度
数量
间距
分格
支撑
转轴
连接方式
```

系统按照参数生成即可。

# 13. 最终建议

百叶产品模板真正应该形成的是一个“参数脚本体系”：

```text
边界
+
框架
+
分格
+
叶片截面
+
叶片阵列
+
面板
+
支撑
+
运动关系
```

六个核心模板共用同一套底层对象。

这样后续即使市场上出现新的百叶款式，通常也只需要：

- 增加预设；
- 增加新的 BladeProfile；
- 调整参数组合；

而不需要再新增一个完整产品生成器。
