# 产品制造脚本协议

> 本文保留旧 v1 格式的兼容说明。当前公开协议为[制造声明 v4](产品制造输入协议v4设计.md)与[显示 v2](产品显示脚本协议.md)：显示入口唯一提供基础零件和资源，制造入口只返回连接与待执行工艺声明。下文 v1 的加工结果图、独立零件表与执行记录不得作为新版产品脚本返回值。

## 调用与参数所有权

公开制造入口为 `manufacturing(parameter_values)`，返回 `icax.manufacturing-model` 第 1 版。宿主从产品实例组件读取模板引用和参数，定位对应 Python 文件并调用入口。生产 worker 明确调用这个入口；`generate(parameters, context)` 保留为离线旧调用兼容。

脚本返回制造定义，不返回产品模板身份、产品输入 `parameters` 或产品执行记录。宿主保存模板引用、规范化输入快照与生成状态。局部工艺定义中的 `definition.parameters` 是该工艺的参数，可以合法存在；它不等于产品参数字典，也不能移到结果顶层。

## 返回的 11 个字段

| 字段 | 含义 |
|---|---|
| `schema` | 固定为 `icax.manufacturing-model` |
| `schemaVersion` | 固定为 `1` |
| `coordinateSystem` | 坐标约定；省略时使用宿主既定右手坐标 |
| `lengthUnit` | 长度单位；省略时使用 `mm` |
| `resources` | 加工件及刀具的几何声明，节点为 `key/operator/inputs/arguments`，依赖必须存在且无环 |
| `items` | 加工件实例与分组，字段为 `key/displayName/geometry?/children?/properties?` |
| `roots` | 实例树的全部真实根；宿主将其带几何的后代收集为制造结果 |
| `sourceMappings` | 加工件到显示构件的显式来源映射；没有映射的项保留宿主既有兼容处理 |
| `processes` | 制造定义列表，条目为 `{key, kind, definition}` |
| `partLists` | 制造清单，保留原表格的列、行、数值及加工件引用 |
| `checks` | 生成校核提示，保留原检查的严重程度、代码、说明和关联键 |

顶层不得出现 `template/parameters/outputs/tables/diagnostics/extensions` 等内部字段。`resources/items/roots` 必须存在，其余列表可为空。加工属性可以表达实际管型、尺寸和制造信息；`manufacturing.sourceMembers` 只能由宿主从 `sourceMappings` 恢复，脚本不能同时把它塞进 `items[].properties`。

`items[].geometry` 使用 `{resource, placement?, instanceKey?}`。`placement` 是完整、正交、单位、右手的世界坐标 `origin/xAxis/yAxis/zAxis`；分组不叠加父变换。省略放置时直接使用资源坐标，并省略 `instanceKey`。资源复用只共享几何定义，不合并加工件身份；`instanceKey` 也不是数据库实体身份。

## 加工件与显示构件独立

制造输出拥有自己的资源、实例清单和数量，不共享显示实例身份，也不按显示数量分配加工件。四个成品显示构件可以由一个连续加工件实现，也可以使用四个加工件。制造方法改变时，成品显示的构件数量和设计位置保持独立。

例如，一个连续加工件的来源可以写为：

```json
{
  "itemKey": "frame.continuous",
  "sources": [
    { "itemKey": "frame.left" },
    { "itemKey": "frame.top" },
    { "itemKey": "frame.right" },
    { "itemKey": "frame.bottom" }
  ]
}
```

这是一条 `sourceMappings` 记录，上例仅示意来源引用；实际连续管件还需要附带 `spans`，说明每段显示构件对应加工件的区段及坐标映射，供宿主拆单和回显使用。目标必须是本次制造 `items` 中存在的键；`sources[].itemKey` 属于外部显示模型，宿主结合成品实例核对，不能用制造清单判断其是否存在。单条记录中来源键不得重复；协议不施加所有来源全局一对一的限制，也不要求每个制造项都有映射。

## 两类制造定义

`geometry-function` 表示脚本已经调用局部 Python 工艺函数。函数已产出资源和 Boolean 声明，并留下输入、局部工艺参数及结果记录。`definition.instanceId` 必须等于过程 `key`，`targetGeometry/resultGeometry` 必须引用现有资源或展开后的实例几何键。局部 `result.geometry` 使用函数自己的命名空间。宿主执行已有几何声明，不重新调用同一个函数。

`assembly-plan` 表示明确待执行的装配工艺源。`definition` 沿用 `icax.assembly-process-source` 第 1 版的 `stocks/instances` 数据，由宿主统一制造 pipeline 求值、执行并冻结。一个制造结果最多声明一个汇总工艺源。

两类条目都是制造定义或待 CAD 求值的声明，均不表示脚本已经生成可直接保存的 CAD 实体。前者的局部函数已经求值，后者的工艺源等待宿主执行；宿主按 `kind` 区分，避免再次调用已经编译为几何声明的函数。

## 保存、重开与兼容

宿主分别保存三份数据：`ManufacturingDefinition` 是脚本的公开原始制造定义；`ManufacturingParameters` 是宿主本次使用的产品输入快照；内部执行 recipe 保存适配后的制造结构、求值计划、工艺追溯及原始／加工后的冻结精确几何。内部模板头、参数和兼容扩展不写回公开制造定义。

资源声明经校验和外部资源解析后进入几何求值；需要执行的工艺源由同一制造 pipeline 处理。提交成功后冻结执行结果。保存重开直接读取冻结执行与精确几何，不重新运行产品制造脚本或局部工艺函数。用户明确重新生成或修改制造方案时，再生成新定义与执行结果。

旧保存中的 `icax.neutral-model` 第 1 版几何图、第 2 版资源表，以及既有冻结工艺数据继续可读。新协议通过临时内部适配衔接现有求值器，不要求把旧文件改写成新的公开制造协议。
