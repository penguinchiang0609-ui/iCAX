# Han's TubeNest-Pro 防护网/极简防盗网模块分析与我方支持方案

> 版本：V1.0  
> 日期：2026-09-13  
> 目标：分析大族 Han's TubeNest-Pro 截图中“防护网/纱窗类”免画图模块的产品逻辑，并给出我方可直接落地的参数模型、几何规则、拆单方式和迭代计划。

---

## 1. 结论先行

从现有截图看，这个功能**更准确地说是“极简防护网 / 极简防盗网”成品拆单**，而不是传统意义上的“纱窗”。

截图中的成品由两侧连续竖管和多根横向内管组成，并带有把手位置、安装孔、公母管半孔等加工参数。软件的目标不是帮助用户画一根管，而是：

> **输入成品尺寸与装配规则 → 自动生成完整成品结构 → 自动拆成可切割管件 → 自动生成孔、插接头等加工特征 → 得到零件加工清单。**

大族当前的产品思路是正确的，而且这是切管 CAM 很值得做的一类“行业免画图”。

我方不建议把它做成一个写死的“防护网模板”，而应拆成三层能力：

1. **成品拓扑层**：两竖管、四边框、横杆阵列、把手区、安装孔等；
2. **装配接头层**：公母管半孔、平口焊接、45°拼角、直切拼角等；
3. **零件生成层**：按规则生成实体、孔、切断面、接头、零件清单，并进入正常排样加工流程。

这样以后护栏、防盗窗、百叶、门花、货架等产品都可以复用同一套接头和阵列能力，而不是每个行业重新写几何代码。

## 3. 对大族截图的结构分析

## 3.1 成品拓扑

截图当前成品可抽象为：

```text
左竖边框 ┃──────── 横杆 1 ────────┃ 右竖边框
         ┃──────── 横杆 2 ────────┃
         ┃──────── 横杆 3 ────────┃
         ┃   把手/特殊区域          ┃
         ┃──────── 横杆 n ────────┃
```

关键特征：

- 左、右两根边框竖管是主承载管；
- 多根内横管在高度方向自动排列；
- 内横管与边框不是单纯“碰焊”，而是支持公母插接；
- 边框上另有安装孔；
- 把手会影响内部杆件排布或孔位；
- 成品不是一个零件，而是一套管件。

因此，程序内部应先建立**装配关系图**，再生成各根管，而不是先生成若干独立管再拼成成品。

### 一个重要推断

母孔为 `15.30 × 10.30`，装配间隙为 `0.30`，高度疑似对应一根 `15 × 10` 的矩形内管。

因此，大族这里很可能采用：

```text
母孔宽 = 插入管外形宽 + 装配总间隙
母孔高 = 插入管外形高 + 装配总间隙
```

即：

```math
W_h = W_t + C
```

```math
H_h = H_t + C
```

若截图中的管材确实为 15 × 10，则：

```text
15 + 0.30 = 15.30
10 + 0.30 = 10.30
```

这里的 `0.30` 更像是**总间隙**，即单侧理论间隙约 `0.15 mm`，而不是每侧各 0.30 mm。

> 此项属于高可信推断，但仍应通过“基本参数”页中的管材截面尺寸再次确认。

## 3.3 “公母管半孔”应如何理解

结合截图、传统防盗网冲孔行业以及切管加工方式，“公母管半孔”应拆成两个概念：

### 母管

作为接收件，例如左右边框，在一个管面上开插接孔。

“半孔”建议在我方定义为：

> **只切穿接收管的进入侧管壁，不切穿对侧管壁。**

它与传统冲孔行业所谓的“半孔/单面孔”是一致的加工概念。

### 公管

作为插入件，例如横杆，在端部形成可插入母孔的公头/榫头。

截图可见公头至少包含：

- 公头长度；
- 公头宽度；
- 倒角类型；
- 倒角尺寸。

因此，这不是简单的“横管加长几毫米”，而是一个**端部特征生成器**。

# 4. 我方产品范围定义

建议产品名称：

> **极简防护网 / 防盗网拆单**

不要直接命名为“纱窗”。

真正的纱窗/金刚网纱窗通常包含纱网、压条、专用铝型材、合页、锁具等，管材只是框架；它和截图中的“多根横杆式防护网”虽然属于同一门窗应用，但几何拓扑不同，应拆成两个产品模板。

## 4.1 第一阶段必须支持

### 类型 A：两竖管式

```text
┃────────┃
┃────────┃
┃────────┃
┃────────┃
```

特点：

- 左右两根连续竖管；
- 中间若干横管；
- 横管插接或焊接到竖管；
- 竖管带安装孔；
- 可带把手区域。

这是截图当前样式，应作为 MVP 第一优先级。

### 类型 B：四边框封边式

增加上、下横边框。

- 长边补齐；

这与市场上“极简防盗网”的完整需求一致。

# 6. 内杆自动排布算法

这是该功能最重要的“免画图”能力之一。

不应让用户手工输入每根横杆坐标。

建议同时支持三种模式。

## 6.1 固定根数

用户输入：

```text
N = 内杆根数
```

程序自动均分。

若可用高度为 `L`，内杆在高度方向占用尺寸为 `h`，两端都保留见光，则实际见光：

```math
g = \frac{L-Nh}{N+1}
```

---

## 6.2 最大见光

用户输入最大允许间隙：

```text
Gmax
```

最小内杆数量：

```math
N = \max\left(0,\left\lceil\frac{L-G_{max}}{h+G_{max}}\right\rceil\right)
```

再重新均分：

```math
g = \frac{L-Nh}{N+1}
```

这样可以保证：

```math
g \le G_{max}
```

此模式最符合防护网行业习惯，柏楚公开资料也采用“最大见光”作为核心输入。

---

## 6.3 固定节距

用户输入杆中心间距 `P`，程序计算可容纳根数并处理上下余量。

余量分配方式支持：

```text
居中
从底部开始
从顶部开始
```

---

# 7. 把手区域与“三段均分”

把手或开锁区域通常会形成一个不能随意布置横杆/孔的特殊区。

建议将整个高度拆为：

```text
上段
把手影响段
下段
```

两种排布方式：

### 中间统一均分

所有允许放置的杆件按照一个统一节距计算，只在把手禁区内删除冲突杆件。

优点：整体视觉节距一致。

### 三段各自均分

上、中、下可用区域分别计算根数和实际见光。

优点：每一区域都能充分利用空间。

柏楚的极简防盗网公开资料同样提供“中间均分”和“三段各自均分”，说明这个需求具有行业代表性。

---

# 8. 管件长度计算

## 8.1 两竖管式边框

设：

- 成品宽：`W`
- 成品高：`H`
- 左边框在成品平面 X 方向占用宽度：`B_L`
- 右边框占用宽度：`B_R`
- 横杆插入左边框深度：`D_L`
- 横杆插入右边框深度：`D_R`

### 左右边框

```math
L_{frame}=H
```

### 内横杆

如果只是顶到边框内侧：

```math
L_{inner}=W-B_L-B_R
```

如果采用插接：

```math
L_{inner}=W-B_L-B_R+D_L+D_R
```

> 注意：公头本身若属于“在原管实体上切出来的榫头”，长度计算要以最终实体包围盒为准，不能再重复增加一次公头长度。

---

## 8.2 四边框直切

### 横边框补齐

如果上下横边框为长边、覆盖左右竖边框端部：

```math
L_{horizontal}=W
```

```math
L_{vertical}=H-T_{top}-T_{bottom}
```

### 竖边框补齐

如果左右竖边框为长边：

```math
L_{vertical}=H
```

```math
L_{horizontal}=W-T_{left}-T_{right}
```

其中 `T` 是对应边框在成品平面内的占用尺寸。

---

## 8.3 45°拼角

不建议只通过长度公式拼凑。

正确做法是：

1. 先按成品外轮廓生成边框实体；
2. 建立 45°切割平面；
3. 进行实体裁剪；
4. 从最终实体计算实际零件长度和切断面。

这样矩形管旋转、非正方截面、R角、后续焊缝补偿都不会出错。

# 9. 公母管半孔几何算法

这是第一阶段技术重点。

建议做成独立的 `JointRecipe`，不要写死在防护网模块里。

## 9.1 接头数据结构

```text
JointType = MaleFemaleHalfHole

InsertDepth
AssemblyClearanceMode
AssemblyClearanceX
AssemblyClearanceY
MaleHeadLength
MaleHeadWidth
MaleCornerType
MaleCornerSize
FemaleHoleCornerType
FemaleHoleCornerSize
```

---

## 9.2 母孔

对于矩形插入管外轮廓：

```text
Wt × Ht
```

如果使用“总间隙”定义：

```math
W_h = W_t + C_x
```

```math
H_h = H_t + C_y
```

如果使用“单边间隙”定义：

```math
W_h = W_t + 2C_x
```

```math
H_h = H_t + 2C_y
```

我方界面必须明确写：

```text
总间隙
```

或：

```text
单边间隙
```

不能只写“装配间隙”，否则 0.3 mm 到底代表总增量还是每侧 0.3 mm 会产生歧义。

### 推荐默认

为了和截图表现保持一致，行业模板默认采用：

```text
装配总间隙
```

即 15×10 管、0.30 总间隙生成 15.30×10.30 母孔。

---

## 9.3 半孔

母孔仅投影到接收管进入侧管壁：

```text
NearFace：切孔
FarFace：保留
```

不能直接用一个穿透整个管材的拉伸切除完成，否则会变成“对穿孔”。

在展开/刀路层面，应产生一组只属于单个管面的闭合轮廓。

---

## 9.4 公头

公头需要按照端面和接头方向生成。

建议流程：

1. 取得插入管端面；
2. 根据 `MaleHeadLength` 建立端部加工区；
3. 根据 `MaleHeadWidth` 生成保留区域；
4. 将非公头区域切除；
5. 对公头角部添加圆角/斜角；
6. 生成最终端面刀路。

截图中的示例：

```text
公头长 = 3.00 mm
公头宽 = 10.00 mm
倒角类型 = 圆角
倒角尺寸 = 1.00 mm
```

说明大族已经把“接头可装配性”做成了显式参数，我方必须同等级支持。

---

# 10. 安装孔

## 10.1 “圆大小孔”

截图显示一种非常典型的安装结构：

```text
近侧面：大孔 D2
远侧面：小孔 D3
```

通常用于：

- 螺钉头/套筒从大孔进入；
- 小孔用于螺杆通过或定位。

因此在几何上它不是一个简单的通孔，而是同轴的两个不同直径孔。

数据模型：

```text
InstallHoleType = RoundLargeSmall
LargeDiameter D2
SmallDiameter D3
```

---

## 10.2 安装方向

安装孔方向不应该用全局 XYZ 写死，而应相对于边框管截面定义：

```text
FrontFace
BackFace
LeftSideFace
RightSideFace
```

界面再映射为行业语言，例如：

```text
正装
侧装
```

这样用户旋转矩形管截面后，孔仍能正确跟随。

---

## 10.3 孔数量与位置

建议支持：

```text
单侧孔数 N
顶部首孔距离 At
底部尾孔距离 Ab
均分
```

若孔中心范围为：

```math
y_0=A_b
```

```math
y_1=H-A_t
```

当 `N > 1`：

```math
y_i=y_0+i\frac{y_1-y_0}{N-1}
```

```text
i = 0 ... N-1
```

---

## 10.4 安装孔和插接孔冲突

必须做几何冲突检测。

典型冲突：

- 安装孔与内横杆母孔重叠；
- 安装孔离端面太近；
- 大孔切到边角 R；
- 安装孔与把手孔重合。

我方建议：

### 默认策略

**报错并高亮冲突位置，不自动偷偷移动。**

### 可选策略

打开“自动避让”后，在用户给定最大偏移量 `Δmax` 内寻找最近合法位置，并明确显示移动后的实际尺寸。

这比直接自动改坐标更可控。

```text
公母插接角
V槽折弯角
定位舌片角
```

边框拼角也是独立 `CornerJointRecipe`，未来门框、窗框、画框、设备框架均可复用。

# 12. 零件拆单

点击“生成零件”后，不应该只生成一个装配体模型。

应输出：

```text
左边框 × 1
右边框 × 1
上边框 × 0/1
下边框 × 0/1
内横杆 A × n
特殊横杆/把手杆 × n
……
```

每个零件包含：

```text
Section
RawLength
FinalBoundingLength
CutFaces
Holes
MaleFeatures
Marks
PartName
Quantity
AssemblyRole
```

## 12.1 相同零件自动合并

几何完全相同的零件应自动聚类：

```text
内横杆_15x10_L170 × 6
```

而不是生成六条独立清单。

判断“相同零件”不能只看长度，还要看：

- 截面；
- 端部工艺；
- 孔位；
- 打标；
- 正反方向；
- 焊缝方向；
- 管材旋转方向。

# 13. 生成后的零件是否允许编辑

这里建议我方比竞品更进一步。

柏楚公开文档说明，其楼梯护栏拆单得到的成套零件不能直接在普通绘制零件界面二次修改。

我方建议提供两种模式：

### 参数关联模式

零件继续受成品参数驱动。

修改成品尺寸后整套重新计算。

### 脱离模板模式

执行：

```text
转为普通零件
```

之后用户可以自由修改任意单根管，但该零件不再跟随成品参数更新。

这能解决实际现场大量“标准模板 + 一点非标修改”的需求。

# 15. 软件架构建议

不要写成：

```text
AntiTheftWindowGenerator.cpp
    if 两竖管...
    if 公母孔...
    if 三孔...
```

这样下一个护栏、门花又会重新写一遍。

建议拆成：

```text
ProductTemplate
├─ TopologyGenerator
├─ LayoutSolver
├─ SectionDefinition
├─ JointRecipe
├─ HolePattern
├─ CornerRecipe
├─ FeatureGenerator
├─ CollisionValidator
└─ BOMGenerator
```

## 15.1 TopologyGenerator

负责：

```text
需要几根管
每根管是什么角色
谁和谁连接
```

不负责具体公母孔长什么样。

## 15.2 LayoutSolver

负责：

```text
横杆数量
横杆坐标
见光
把手禁区
```

## 15.3 JointRecipe

负责：

```text
公母管半孔
插接
焊接
马鞍口
```

## 15.4 HolePattern

负责：

```text
大小孔
圆孔
长圆孔
孔阵列
```

## 15.5 FeatureGenerator

把上述规则真正转成 BRep/实体特征和 CAM 轮廓。

## 15.6 BOMGenerator

完成：

- 拆件；
- 合并相同件；
- 数量统计；
- 管材需求量统计。

# 17. 参数合法性与约束

必须在生成前做以下检查。

## 17.1 尺寸约束

```text
W > 左右边框占用宽度
H > 0
内杆长度 > 最小可加工长度
```

## 17.2 公母接头约束

```text
母孔尺寸必须小于接收管可用管面
插入深度不能超过接收管有效深度
公头剩余壁不能过窄
倒角不能吃掉整个公头
```

## 17.3 安装孔约束

```text
孔不能越过管面
孔不能与母孔相交
孔不能离切断面过近
大小孔必须在正确的相对管面
```

## 17.4 排布约束

```text
实际见光 <= 最大见光
把手净空不能被普通横杆侵入
首尾杆件不能和边框拼角冲突
```

# 18. 与大族相比，我方应做得更好的地方

大族截图已经证明“成品级免画图”是正确方向。我方若只做到同样的输入框，没有竞争优势。

建议重点做下面几件事。

## 18.1 接头做成公共能力

公母管半孔不要只服务防护网。

以后：

- 护栏；
- 门花；
- 货架；
- 框架；
- 防盗窗；
- 家具；

都可以直接调用。

## 18.2 自动见光算法

用户只给：

```text
最大允许间距
```

系统自动算杆数和实际间距。

这比让用户输入每根杆的坐标更符合行业使用习惯。

## 18.3 明确装配公差语义

不要只写：

```text
装配间隙 0.3
```

要明确：

```text
总间隙 0.30
单侧约 0.15
```

减少现场“孔大了一圈”的歧义。

## 18.4 生成后允许脱离模板编辑

模板解决 90% 标准情况；剩下 10% 非标不能逼用户回去重新画全部零件。

## 18.5 批量订单

除了单套向导，还应支持 Excel/表格批量：

```text
编号 | 宽 | 高 | 把手侧 | 把手高度 | 数量
A01 | 800 | 1200 | 左 | 900 | 5
A02 | 900 | 1500 | 右 | 1000 | 8
```

批量生成所有零件后统一合并、排样。

这一点与大族最新公开的“Excel → 3D模型 → 排样加工”路线一致，也是实际门窗订单最有价值的工作流。

H = 300
W = 200
边框 = 两竖管

装配总间隙 = 0.30

- 横杆自动排布；

- 大小孔出现在正确管面；

# 21. 还需要向大族现场继续确认的点

仅凭当前截图，以下信息不能可靠确定，应继续收集截图或操作视频：

有这三类信息，基本可以把大族这一模块的规则还原到 80%～90%。

# 22. 最终建议

这个功能值得做，而且优先级不低。

原因不是“防护网市场有多大”，而是它非常适合作为我方**成品级行业免画图框架的第一批落地模板**：

- 结构规则稳定；
- 管件数量多且重复度高；
- 客户订单尺寸变化频繁；
- 传统做法依赖量尺、冲孔、人工算间距；
- 激光切管天然可以一次完成切断、插接头、安装孔、定位孔；
- 同一套底层能力可继续扩展到护栏、防盗窗、门花、货架、窗框等行业。

产品实现上，应以：

> **“拓扑生成 + 布局求解 + 接头模板 + 特征生成 + 拆单/BOM”**

作为底层，而不是简单做一张“大族同款参数窗口”。

这样第一版是在支持防护网，第二版开始就是在扩展一套通用的“管材成品自动拆单系统”。
