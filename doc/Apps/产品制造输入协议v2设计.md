# 产品模板制造输入协议 v2 设计

> 本文保留第 2 版的实施及验收记录。当前公开协议为[制造声明 v4](产品制造输入协议v4设计.md)与[显示 v2](产品显示脚本协议.md)：基础零件和资源唯一由显示入口提供，制造入口只返回连接与工艺声明，实际分件与路径由下游生成。下文第 2 版的制造对象与验收数字仅属于历史版本。

## 状态与职责

运行接口已迁移到 v2，全部 13 个产品模板的公开 `manufacturing()` 只生成制造输入。宿主使用独立的 `execute-manufacturing` 请求执行下游流程。原有 v1 仅供旧文件读取和离线兼容，生产入口要求 v2。实施与本轮验收已完成，并部署到本地 `src/x64/Debug` 调试目录；历史 v1 记录不代替本轮验收。

公开入口保持 `manufacturing(parameter_values)`。宿主保存产品实例的模板引用与参数值，找到产品模板 Python 并传入规范化参数。返回值是**后续装配工艺的完整输入声明**，不是加工或装配执行结果。

产品模板负责决定加工对象、设计几何约束、显示来源、各节点选用的装配工艺，以及工艺实际需要的输入数据和参数。它不得调用装配工艺、加工函数或模具求值，不读取工艺模板内部实现来推导刀具、补偿和加工结果。

产品模板可以构造真实截面、固有零件几何，计算设计位置、目标路径和设计转角，并检查产品输入与设计拓扑。所选装配工艺的适用性、展开料长、槽位、槽根避空、K 补偿、刀具、Boolean、成形和装配结果，由后续装配工艺负责。

## 返回结构

返回 `icax.manufacturing-model` 第 2 版，顶层只有下列九个字段：

| 字段 | 内容 |
|---|---|
| `schema` | `icax.manufacturing-model` |
| `schemaVersion` | `2` |
| `coordinateSystem` | 坐标约定 |
| `lengthUnit` | 本次输入的统一长度单位 |
| `resources` | 可复用的真实截面及固有几何声明 |
| `items` | 制造对象和分组；每个制造对象有独立身份 |
| `roots` | 制造对象树的全部根节点 |
| `sourceMappings` | 制造对象与显示构件的设计来源对应关系 |
| `processes` | 要交给后续装配工艺执行的调用声明 |

不返回产品 `template/parameters`、`outputs`、`partLists/tables`、`checks/diagnostics` 或兼容 `extensions`。制造清单、工序清单、工艺适用性与执行校核是后续结果。零件数量、材质、牌号、采购类型、外购规格、组件引用等已知输入事实仍放在制造对象中，不能指望后续从几何反推这些事实。

## 制造对象与资源

`items` 使用稳定的 `key`，包含 `displayName`、`children` 和 `properties`。分组只有 `children`；实际制造对象必须提供下列三种输入之一，三者互斥：

- `geometry`：确实已知的加工初态固有几何，格式为 `{resource, placement?}`。不能把成品折后 compound 或已经加工的几何作为未经加工的初态。
- `manufacturingInput`：需要装配工艺完成材料分配的设计约束，例如连续管件的目标路径及真实截面。
- `componentReference`：外购件或固有组件的引用与规格，供后续解析；不能以一个没有输入内容的空对象冒充零件。

一条连续窗框路径是一个制造对象，即使它对应四个显示构件、并且此时还没有展开直料几何。制造对象数量按对象及数量统计，不能只统计有 `geometry` 的项。显示模型与制造模型的实例身份分别管理；字符串恰好相同不表示共享数据库实体。

资源节点继续使用 `{key, operator, inputs, arguments}`。同一截面可以供多个制造对象复用，复用只共享几何定义。产品可以用 Boolean 描述固有零件几何，但不能在这里生成装配加工的槽口、孔刀具或加工后的结果图。

管型信息由加工件自身的 `tubeDesigner.profile` 属性表达，截面几何通过 `sectionResource` 引用 `resources`。不增加独立的母材实体。已有几何资源的放置是完整、正交、单位、右手的世界坐标；分组不叠加变换。

### 连续管件输入

`manufacturingInput.kind` 为 `tube-path` 时，包含：

- `profileResource`：真实截面资源，与该对象管型组件的 `sectionResource` 一致。
- `path.vertices`：有稳定键的目标成品中心线点，点使用本次声明的世界坐标和长度单位。
- `path.segments`：按路径方向排列的区段，使用稳定键和 `from/to` 顶点引用；每段给出真实 `sectionFrame`，以表达空间折弯后的截面朝向。
- `path.closed`：路径是否闭合。闭合路径不重复首点，由最后一段连接到第一顶点。
- `path.startVertex`：路径起点；闭合路径的展开起点和接缝位于这里。
- `path.closure`：闭合接缝的设计要求。本例为直边中间接缝。
- `formingOrder`：有明确顺序要求时传入目标转角键；这是要求，不能宣称设备已验证可执行。

`sectionFrame.origin` 是本段的起点，`zAxis` 沿本段方向；截面坐标使用 `xAxis/yAxis`。不只提供首段朝向后让下游猜测空间管件的 roll。

这里的路径是目标成品路径，不是展开直料，也不是槽根实际铰链轨迹。不得预填 `length/station/stockStart/startReserve/endReserve/bendAllowance` 等尚待工艺求解的制造值。已知设计尺寸可表达在顶点和截面中，不能标成最终下料尺寸。

## 工艺调用声明

所有 `processes` 条目统一使用 `kind: assembly-process`；不再混用已执行的 `geometry-function` 和待执行的 `assembly-plan`。

每条记录为 `{key, kind, definition}`。`definition` 包含：

| 字段 | 含义 |
|---|---|
| `templateId` | 选用的装配工艺标识；不是产品模板身份 |
| `processInput` | 工艺输入，第 2 版角色引用、设计几何约束与选用资源 |
| `parameters` | 该次装配工艺的局部参数，不是产品参数字典 |
| `processDrafts` | 选用资源的原始草稿参数，由后续按资源条件规范化 |
| `targets` | 工艺输出角色对应的制造对象 |
| `dependencies` | 必须先完成的工艺调用键，必须存在且无环 |

`processInput.parts` 按装配工艺的输入角色绑定数据：

- 制造对象：`{scope: manufacturing, itemKey, state, data?}`。`data` 是已经明确的局部输入事实，不是执行结果。
- 显示构件观察者：`{scope: display, itemKey, segment?}`，只能读取，不能作为 `targets`。
- 固有几何观察者：`{scope: resource, resourceKey, placement, data?}`，必须显式提供资源和放置，不能失去角色与几何身份。
- 内联观察数据：`{scope: input, data}`，用于完整的已知截面、设计区域或观察几何配方；不能放入产品全量参数，也不能放入刀具或已求得的裁切平面。

`state: initial` 指后续完成材料分配后的初始材料状态，不代表产品模板已经生成该初态。`state: {after: processKey}` 指指定依赖工艺提交后的结果快照；该工艺必须在依赖关系中，而且必须确实产出所引用制造对象的状态。不以数组顺序或“最新结果”猜测输入版本。已知初态几何的局部加工还可在 `data.initialGeometry` 声明 `{resource, itemPlacement}`；它明确该初态几何与制造件世界位置的关系。下游保持这个坐标关系执行及提交。复用同一资源的不同制造件仍分别绑定和提交自己的状态。

`targets` 只引用本次制造对象，角色与工艺输出契约一致。后续按明确依赖提交加工，作用于同一件的可交换切除由执行方稳定地合并；会影响对方输入且无明确顺序的冲突应拒绝，不能并发覆盖或任意挑一个结果。

输出角色必须在 `processInput.parts` 中绑定同一个制造对象，不能把 `display`、`resource` 或 `input` 观察者直接列为输出。多面连续框的三向立柱节点用 `data.sourceMember` 指定所属连续制造件的显示来源区段；宿主结合该制造件的 `sourceMappings` 取得局部角色几何，输出仍归属独立的制造件。

V 槽输入锚定目标路径的转角：`geometry.anchor` 指出转角顶点及入、出区段，`angle` 和 `axisDirection` 按右手规则表达目标转角。这个顶点不是已求得的槽位或实际槽根铰链。装配工艺结合截面、所选模具和四个转角共同求解材料分配、展开槽位与成形结果。

针对同一连续件，后续收集全部转角调用共同完成材料分配；切槽在同一展开件上累计。`formingOrder` 约束随后成形阶段的顺序，不能把示例中的四个 `initial` 调用解释为四份可并发覆盖同一加工件的成形结果。路径闭合与接缝位置是设计要求，不能替代接缝焊接或其他连接工艺的声明；本例的工艺范围是四处 V 槽折弯。

产品直接声明所选工艺和资源，例如 `node-v-notch-integrated` 与 `v-notch-sharp`，不加载工艺内部描述符去挖出 `partProcesses` 或刀具构造。

草稿原样保留，不在产品脚本里模拟工艺条件解释器。关闭上级选项后的不适用子选项由后续统一规范化，不能继续影响加工或阻断生成。

当前路径折弯执行路线支持所选模具引用及草稿。通用局部几何加工函数使用自身已声明的输入和参数；若向这种函数附加尚未接通的资源槽或资源草稿，执行方明确返回不支持，不静默忽略后生成默认加工结果。

工艺记录和 `items.properties` 均不得夹带 `result/applicable/functionDigest/executionSignature/resolvedPlan`、加工刀具、成形结果、冻结 BRep 或旧 `assemblyProcessPlan/assemblyGeometryProcesses`。生成声明不等于工艺已经执行或已经通过适用性检查。

## 显示来源

`sourceMappings` 保留 `{itemKey, sources}`。目标 `itemKey` 属于制造对象；每条来源 `sources[].itemKey` 属于外部显示模型。

连续路径用稳定的区段键声明对应关系：`segments` 中每条记录为 `{segmentKey, sourceRange}`。`sourceRange: [0, 1]` 表示该显示构件的完整设计中心线区间，范围按显示构件自身方向参数化；可以用反向区间表达反向对应。只表达设计对应关系，不表达展开坐标。

本例底边被中间接缝分成两段，同一个显示底边来源包含 `bottom.right` 的 `[0.5, 1]` 与 `bottom.left` 的 `[0, 0.5]`。实际方向必须按显示构件定义核对，不能假定所有来源一对一。

本例使用现有显示模型的以下中心线方向，坐标单位为 mm。底边与右边正向对应，顶边与左边反向对应；这些是示例伴随的显示来源，仍由显示模型保存，不嵌入制造对象身份。

| 显示构件键 | 起点 | 终点 |
|---|---|---|
| `outer_frame.bottom.0001` | `[19, 0, 19]` | `[1181, 0, 19]` |
| `outer_frame.right.0001` | `[1181, 0, 19]` | `[1181, 0, 1781]` |
| `outer_frame.top.0001` | `[19, 0, 1781]` | `[1181, 0, 1781]` |
| `outer_frame.left.0001` | `[19, 0, 19]` | `[19, 0, 1781]` |

来源是否存在，由宿主结合显示模型核对；产品声明中的区段键必须存在，映射不能引用缺失区段或越界区间。展开后 `stockStart/reserve` 与精确坐标映射属于后续装配工艺结果。

端接分配使原始材料只覆盖某个显示来源的部分设计区间时，下游对来源区段求真实材料交集，并同时更新来源分数范围。包覆连接增加的端部原料保留为材料余量，不能拉伸原显示区段来覆盖它。执行结果中的展开区间必须落在真实原料长度内。

## 后续结果与参数所有权

后续装配工艺接收本声明、解析所需资源、完成制造分配和加工，并返回实际加工件几何、展开尺寸、槽位、工序、材料需求、成形与装配数据、清单及校核。它不应再索取全量产品参数或依赖产品 Python 的隐藏运行状态；所需业务输入必须已经在声明中。

宿主分别保存产品模板引用与参数、原始制造输入声明、以及后续工艺执行结果和精确几何。后两者分开，不能把执行结果回写成产品脚本的输入声明。

改变制造路线或模具草稿可以改变工艺声明。仅改变 K 补偿、槽根圆角或释放孔参数时，不改变产品目标路径和显示来源。槽根避空沿用原几何语义，K 补偿由工艺独立求解，不用展开模型重定义圆角。

## 完整设计示例与验收条件

[V 槽连续窗框设计示例](../examples/product-manufacturing/v2-v-notch-frame.json) 是本设计的完整 JSON：一个连续制造对象、一个复用截面、五个目标路径区段、四个 V 槽调用和四个显示来源。它保留为单个连续框件的设计示例。当前脚本的完整实际返回值另见 [V 槽窗实际返回值](../examples/product-manufacturing/v2-v-notch-window.actual.json)，宿主传入的参数单独保存在 [宿主输入示例](../examples/product-manufacturing/v2-v-notch-window.host-input.json)。实际返回值包含该窗全部制造件及其工艺调用，不含产品参数或模板身份。

实际返回值含 3 个截面资源、8 个独立制造对象和 44 条待执行工艺声明。一处穿管节点位于连续框的接缝，后续按路径来源分配到展开料的两个端区，因此内部执行源共有 45 条工艺实例。这个拆分由下游完成，产品声明不预填展开槽位或加工结果。

实施后必须满足：

1. 全部 13 个产品模板的公开入口和 worker 在禁用加工函数、装配求值和刀具物化后，仍能产生声明；动态模块别名不能绕过禁用验证。声明中没有加工结果、刀具或工艺派生的最终尺寸。
2. 显示几何保持不变；不同管型、模具和制造路线的输入引用完整。四个显示框件与一个连续制造对象分别有自己的身份，不增加母材层。
3. 后续仅凭声明可以求解，执行后的实际几何、尺寸、来源映射与原已认可结果回归一致，覆盖产品、制造参数变化和不适用草稿分支。不能只换返回标签而保留产品内执行。
4. 原生预览、拆单、制造修改、拒绝后的无副作用、保存重开验证通过；原始声明与执行结果分别保存。旧文件和 v1 兼容读取与新产品输出分开处理，不把旧结果伪装成 v2 输入。

本轮 [验收记录](../../output/tests/assembly-process/manufacturing-v2-acceptance.json) 包含 48 项 Python 测试、12 项原生单元测试、全部 13 个产品模板的原生预览与制造接口，以及 7 个原生保存重开案例。窗产品覆盖 24 组面型、制造路线和门扇组合的材料、来源区间及有效加工声明对比；另有 6 组原生几何对比，共 144 件零件，检查体积、边界、实际位置与 49,003 个实体分类采样点。部署目录中的 217 个 Python 文件与源码逐一校验一致。

验收不表示任意模具或任意参数组合均已支持。铝窗制造测试使用明确标记的测试夹具，未核验的生产铝型材仍被拒绝；既有用户分段／柔性模具的 `bendRadius` 限制未在此次扩展；通用局部加工函数尚未接通的资源槽和草稿明确返回不支持。这些限制在验收记录中单独保留。
