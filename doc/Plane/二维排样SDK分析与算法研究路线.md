# 二维排样 SDK 分析与算法研究路线

日期：2026-10-26。研究对象是本目录提供的三个压缩包；解压、元数据、导入表及分析记录保存在 `output/research/plane-nesting/20261026/`。

## 1. 当前结论

这批资料足以提炼工业二维异形排样的问题模型、约束语义、结果契约和有依据的算法架构假设。ALMA 的头文件与接口文档最完整；二进制保留的类名、诊断和参数名还能补充几何运算、构造策略、压紧及多板优化线索。NestFab 则提供另一套订单、几何、姿态与结果组织方式。

目前没有还原任何一家的完整排样算法，没有获得可复用的核心源码，也没有完成真实算例的性能或利用率对比。不能用接口声明、DLL 大小、存在某个内部名称或一次版本查询代替这些验证。

根据用户明确提供的产品关系，FastNest 是 ALMA PowerNest 的精简版，二者应作为同一家算法体系的两个产品变体分析。两个包版本也不同，静态差异可能同时来自产品精简、版本演进和发布配置，不能把所有差异都归因于精简。

本项目第一站确定为**独立二维排样算法**。当前实施顺序为规则图形、类规则组合、余隙补小件，以独立策略 job 比较选优；扫描线、NFP 左底及放置顺序/实数角联合优化随后接入。当前实现与范围见 [SheetNesting](../../src/iCAX-Engine/foundation/SheetNesting/README.md)。

## 3. ALMA：可直接提炼的工业问题模型

以下来自随包头文件和文档，表示接口契约，不能自动推定当前包、许可与调用路径全部支持。

| 层次 | 可提炼的信息 | 对 iCAX 的价值 |
| --- | --- | --- |
| 几何与数量 | Shape 复用几何，Part 表示实例；轮廓包含圆弧、孔洞及多个外环 | 几何、订单数量与放置结果分开，按几何缓存 |
| 板材与库存 | 矩形/异形板、板边留量、缺陷区、有限库存 | 输入应是整个订单和可用库存，而非只向单板塞图形 |
| 姿态 | 固定角、角度区间、自由角及独立镜像配置 | 角度应进入问题模型，镜像要由工艺明确允许 |
| 间距 | 材料轮廓与保护轮廓分别表达；保护区之间允许重叠 | 间距语义必须统一，不能误把 5 mm 加成 10 mm |
| 目标 | 用料、切割及换版成本；最后一张板的直线/L 形余料 | 不能只优化单板填充率，应明确订单完成与余料价值 |
| 搜索过程 | 时间预算、线程数、停止回调和发现更好解回调 | 持续保留最好可行解，记录随时间改善的曲线 |
| 后优化 | Shake、Compact、Spread 等不同操作 | 初次放置与后续移动、压紧、展开应分层 |
| 手排与续排 | 预排、固定策略、追加排样、填充零件 | 固定件和剩余需求需要明确状态，不能每次全部重排 |
| 共边 | 刀缝、普通间距、最短公共边、簇尺寸等独立规则 | 共边是有条件的几何与加工关系，不能等同于零间距 |

主要证据位于 PowerNest 包的 `include/powernest2.h`、`powernest2_metal.h`、`powernest2_objective.h` 与 `powernest2_common_cut.h`。详细行号见专项报告。

几个重要语义：

- `PN2_CreateFreeOrientation` 明确表达自由角；内部怎样采样或细化角度尚未确认。旧的区间创建辅助函数还有跨 0/360 度的弃用提示，应直接规范化合法区间，不能照搬有缺陷的辅助接口。
- Part 的 priority 是倾向性约束，不等于绝对固定的放置顺序。输入数组次序、订单优先级、布局位置和加工切割顺序是不同概念。
- `PreNest` 明确不保证几何合法，调试 SVG 也不足以检查细小重叠。结果必须独立复核。
- 最好解回调中的结果具有调用期生命周期，不能把临时句柄直接交给异步界面长期读取。

## 4. ALMA：二进制还能提供哪些算法线索

两个原生库均保留了比导出接口更丰富的内部名称。下面列的是架构研究线索，**不是已复原的调用链**。

| 线索 | 能支持的判断 | 仍然未知的内容 |
| --- | --- | --- |
| `BoolMinkowskiSumWithParts`、`MultiExternalMinkowskiSum` | 包内存在 Minkowski 类几何运算 | 是否、何时用于某种 NFP/IFP；孔洞、退化和精度处理细节 |
| `IntervalMap`、`MapTables`、`GreedyNester`、`AngularScanner` | 存在区间表示、贪心放置与角度相关模块 | 区间图不能仅凭名字直接认定为用户所述扫描线实现 |
| Rectangle、Column、Offset、Escher 等策略名与 `StrategyManager` | 存在多种构造策略及调度结构 | 策略选择、评分公式和每个变体实际启用范围 |
| `Shaker`、`RotativeShake`、`NestingLocalOptimizer` | 存在移动、旋转、压紧或局部改进的模块线索 | 邻域、接受准则、迭代预算、是否改善任意角度 |
| `CanReorderParts` 诊断 | 存在与重新排序有关的代码概念 | 是否搜索放置顺序、搜索范围以及实际获益 |
| pattern/LNS、COLGEN、LP rounding、MIP 相关名称 | 多板阶段值得研究布局模式组合、大邻域和数学优化 | 具体数学模型、列生成子问题、启用条件及最优性证明 |
| `NesterThreadsSupervisor`、动态权重和策略时间比例 | 存在并行候选与预算调度线索 | 确定性、随机种子、线程共享以及调度公式 |

例证：PowerNest 文件偏移 `0xFC99B0` 为 `BoolMinkowskiSumWithParts`；`0xFBE8F8` 为 `P_MULTI_PATTERN_LNS_WEIGHT`；`0xFBEC20` 为 `P_MULTI_COLGEN_WEIGHT`。对应原始文件的偏移与专项报告一起留存，不能套用于其他版本 DLL。

其中出现 HiGHS 等第三方求解器，仅能作为模块依赖或代码存在的证据，不能推出整个二维几何排样由 MILP 完成，更不能推出全局最优。

据此值得验证的整体架构是：

```mermaid
flowchart LR
  A[轮廓、孔洞、间距与角度约束] --> B[可行位置与接触候选]
  B --> C[多个放置顺序和构造策略]
  C --> D[移动、换序、旋转与压紧]
  D --> E[多板分配与布局组合]
  E --> F[独立几何校验与最好解]
  F --> C
```

这是结合资料提出的自研研究结构，不是声称已还原 ALMA 的实现。

## 5. FastNest 精简边界：已知与未知

两个包共享 PN2 接口体系。配套导入库各能恢复 177 条名称到序号的绑定，但不能将导出表的 1004 个序号槽位当作 1004 个有效 API。

当前 FastNest 导入库未提供 `PN2_Nest`、`PN2_PreNest`、`PN2_NestMore`、`PN2_PricedNest` 的同名绑定；PowerNest 导入库提供这些入口。FastNest 二进制还保留了单板入口应转向 `PN2_MultiNest` 的诊断。这是可复核的调用路线差异。

两份导入库也存在共同缺失的头文件声明，例如 `PN2_SetExclusiveGroups` 和 `PN2_ShapeSetPrice`。这说明文档、头文件与二进制需要逐项对照，不能只按头文件设计直接调用。

这些差异尚不能给出 FastNest 的完整阉割清单，也无法证明几何精度、角度、放置顺序或后优化的具体限制。FastNest 文件版本为 `3,10,7,205738`，PowerNest 为 `3,10,7,204562`，比较时必须同时考虑版本差异。

## 6. NestFab：另一套可参考的表达与边界

NestFab 主程序集可见订单、几何、板材、排样任务和结构化放置结果。存在本地文件、参数化几何及编码 CAD 输入等形式，CAD 依赖包含 CadLib，绘图依赖包含 SkiaSharp。

角度相关可见项包括 `AvailableAngles`、`TiltAngle`、`FixedAngle`、`GlobalRotationDegrees`，以及 `RanFabAngle` 中的 `Free`。这足以确认其具备自由角配置语义，但不能证明连续角求解，也不能把枚举 `Any=15` 直接解释成 15 度步长。

可见 `Priority`、`SequenceNumber`、`PlacementIndex`，但这些可能分别是输入属性与输出编号，不能直接作为其优化放置顺序的证据。

主程序集存在混淆，`Engine2D` 又调用 `liblcns.dll` 的序号导出，当前已定位到这一原生算法边界。`liblcns.dll` 具有 UPX 样式分节特征，仅凭文件名不能将其归类为纯授权库。`libta64.dll` 和 `libtf64.dll` 则分别由版本资源明确标识为 TurboActivate、TurboFloat。

因此 NestFab 当前更适合用于学习输入输出组织与后续行为对照，不能声称已从托管程序集拿到排样内核。

## 7. 按用户提供的信息确定自研比较基线

以下为用户在本次讨论中提供的现有产品实现信息，并非本轮对维宏、柏楚软件做运行分析后独立得到的结论：

- 维宏平面排样主要采用扫描线和贪心 NFP，策略基本为左底。
- 维宏、柏楚的现用排样没有考虑零件放置顺序优化，也没有任意角度的概念。

这里的排序特指**排样时决定先放哪个零件**，与 CAM 切割顺序分开。供应商 SDK 可以表达自由角，不代表维宏、柏楚产品已采用该功能或采用相同搜索策略。

我们据此建立的研究问题是：固定左底构造规则时，联合改变零件顺序、旋转角度和板材分配，能否在相同时间预算下稳定改善完整订单的用板结果？

## 8. 后续一般异形搜索的算法实验闭环

### 8.1 模型与几何合法性

每个实例的解至少包含 `(sheetId, x, y, angle)`，镜像仅在输入明确允许时参与。约束包括需求数量、板材库存、孔洞、缺陷区、板边距离、零件间距及纹理/轧制方向。

精确原始轮廓与搜索用近似轮廓分开，记录弦误差和保守余量。独立验证器重新检查数量、包含、最小距离、重叠及角度合法性，不能复用搜索缓存的“已合法”标记。

已有 `GeometryData::Region2` 与 Clipper2 可复用；现有 `TubeNesting` 解决轴向管材问题，不能直接替代二维异形排样内核。

### 8.2 顺序与角度联合搜索

- 先保留扫描线/贪心 NFP＋左底作为可复现基线。
- 顺序候选覆盖固定输入顺序、面积/长边排序、多起点及换序/移位邻域。
- 角度实验分别覆盖固定允许角、等步长离散角、几何特征角＋自适应细化，再研究连续参数的局部搜索。
- 顺序改变后重新求可行位置与角度，避免“先固定全局顺序，再给每件选角度”成为唯一模式。
- 任意角度不能预先缓存所有角度对的 NFP；应按需构造、限制缓存，并把几何版本、姿态、间距与误差纳入缓存身份。

允许任意角度是可行域定义，连续局部搜索是求解方法，连续域全局最优是证明结论。这三件事必须分别报告。增加 1 度采样不能称为已经解决连续角全局优化。

### 8.3 指标、算例与拆分对照

先比较是否完成需求，再比较板材成本/用板数、可用余料和其他生产目标。单板利用率不能覆盖漏排件、库存超用或不合法间距。

准备互补凹件、孔中套料、斜边互补、多数量混排、库存紧张和微小间距算例；其中专设“只能换序才改善”“非直角才能改善”的实例，区分两项优化的贡献。

在相同硬件、线程数、时间预算及多次运行条件下，记录首个可行解时间、最好解改善曲线、完成数量、板数、材料成本、余料、峰值内存和几何合法率。输入洗牌用于检查顺序敏感性，但输出相同或不同都不能单独证明内部是否进行顺序搜索。

首轮应产出可独立运行的算法、独立验证结果和排版图。接入 SDK 做质量基准时，要使用同一份规范化输入，并复核坐标、圆弧、旋转、间距与输出精度。
