# 07 多排序独立构造竞赛

将构造算法与输入排序作为两个独立维度，在固定总预算下比较多个初始布局。该策略搜索构造选择，不等同于对已有坐标连续压紧。

2026-11-08用户最新明确以利用率为唯一目标：本入口及其子构造默认使用统一 `Utilization`，取消内部切换到其他质量目标。原件全需求和几何合法性为硬条件；完整候选先比净料／实际使用板材面积，同用料再比净料／整板宽占用段面积，段内侧向和下方空白计入分母，包络紧密度只作同段利用率平手。自配对和异规格的准备额度属于搜索投入分配，不给任一种组合额外质量分。本轮11项原生及2项生产命令测试通过；v13原32件使用段利用率74.49%、占长27245.11mm，约10.05秒进入共同优胜，整轮52.22秒。下述v9／v10／v11为旧版本历史观测，详见逐路核对。

类型：搜索组合策略。当前实现状态：**已实现受限适配；v13单案约10.05秒进入共同优胜，使用段利用率74.49%，尚未达到整体初解质量验收**。核对日期：2026-11-08。

## 代码实现与调用

入口：`plane.order-ultra / MakePlaneOrderPortfolioFactory`。实现位置：[NestingPlaneStrategies.cpp](<D:/penguinchinage0609/iCAX/src/iCAX-Engine/foundation/SheetNesting/NestingPlaneStrategies.cpp:2385>)，按 `OrderPortfolio / InitialOrderFactory` 符号定位；行号可能随后续修改移动。

`MakePlaneOrderPortfolioFactory` 是通用纯构造器包装，接收调用方的 `StrategyFactory`。本轮 `OrderPortfolio` 先生成长边、净材料面积、短边、宽、高五种降序排列，稳定平局保留原输入顺序；按全部原件下标组成的完整排列去重，再从长边基序的前十项中，按私有种子生成同材料、同几何类别的非累积单对交换。零需求原件也在完整排列内，不删除原行或改需求。

公开注册的 `plane.order-ultra` 与 `plane.initial` 通过同一个 `InitialOrderFactory` 配置：每个排序先独立运行数量优先延后补隙阵列，再独立运行 `NfpArray`。两次都从该排序对应的完整原需求开始，新建构造器，不读取前一份布局坐标；只共享本任务不可变 NFP 几何缓存。通用工厂仍只运行调用方给定的一个构造器，不暗中追加 NFP。不新增注册 ID，原27／22候选数未因此改变；内部两个构造不能冒充又两条外层候选。

每次调用拿本路线**实际剩余时间与尝试数**，不再机械除以剩余排列数。完成或返回后，才在共同剩余预算内尝试下一构造／排序；最多16个排序是上限，不要求16次都启动，也不表示最多16次构造。默认双构造配置最多32次，正式运行可能因时间、尝试数或取消提前结束。若数量阵列用尽全部本路预算，NFP-array不会凭空获得另一份预算。

范围与差异：默认最多16个唯一完整排列，通用工厂可配置1～46；五种确定性规则先占名额，随后才用兼容交换补足，最多46是接口限额，不承诺覆盖五规则与45交换对的全部不同排列。交换仍从长边基序独立发生，不是全排列。相同输入与种子重放候选排列顺序，墙钟截止可能影响实际完成的构造数。

本轮已增加首份构造连续预算、长边／面积确定性前缀不依赖随机种子的测试断言。源码断言存在不等于本轮实际运行通过；零需求完整排列、全向量去重与封顶仍应有直接证据。独立排序诊断约29k用长没有直接当作主流程成绩。后续 [v9完整正式竞赛](<D:/penguinchinage0609/iCAX/output/research/plane-nesting/20261108/materials-audit/textile-self-pair/textile-0-full-initial-v9.json>) 确实选中本路线，32/32、一板、含末边距用长29013.2199mm，按裁切用长归一约69.954%；独立GEOS审查通过。但内层好结果到55.29秒才出现，外层约60.03秒才收回，**不能称快速强初解已经达标**。

v9之后的 `PlaneInitial` 将准入队列稳定调整为首四项 `envelope-initial`、`order-ultra`、`nfp-array`、`nfp-initial`；其余候选保持原相对顺序，27／22候选及 `FairScheduling` 配额协议不变。首波分别覆盖保守快基准、排序×构造、同规格周期阵列、逐件NFP，按机制安排而非按素材名称特判。`PlaneStrategyTests` 用真实 `scheduler.queue` 事件断言27项唯一且首四项一致。v10实测order在0.0069秒启动、10.048秒由外层收回，两个基序构造都排齐；但NFP反向配对已认证后被准备时限触发的发布门丢弃，最终仍输包络。首波提前本身没有证明强初解改善，见 [逐路核对中的v10证据](<D:/penguinchinage0609/iCAX/doc/Plane/策略/初解机制逐路核对.md>)。

## 原资料的方法与实际分支

旧 SortUltra 每次先恢复长度排序，仅在前 min(规格数,10) 项中交换一对；要求优先级与组合件类别兼容，并用历史交换对去重。前十项最多 45 个无序对，不是 K! 排列，也不是累积交换。余量随后按零件 ID 重新绑定。

排序层级及时间配置影响候选数量，不等于精确墙钟控制。部分 NFP 候选在排序循环外只加入一次；不能把策略数直接当作并发线程数。

## 面向 iCAX 的独立策略步骤

1. 选取明确的构造工厂与排序配置，不自动展开无上限笛卡尔积。
2. 排序必须返回所有原 Parts 下标的完整排列，包括零需求行；不改材料、数量和角域。
3. 面积、长边、短边、宽高等确定性顺序各自构造；随机变体从 job 私有种子生成。
4. 对有效实际排列去重，并保存排列本身，不能只依赖截断前缀编码。
5. 为每候选新建策略对象和输入副本；在共同时间／尝试预算内给每份构造连续完成的机会，不将可用窗口按预定重启次数碎切。前轮输出只用于统一比较，不成为下一轮坐标输入。
6. 验评每个结果后用统一质量选择，构造器内动态选件仍属于其自己的逻辑。
7. 输出可重现的种子、排列、工厂、配置与停止原因。

## 当前适用边界

默认注册每排序运行数量阵列与 NFP-array 两个独立构造，最多16个唯一完整排列；通用工厂仍接受调用方选择的一个纯构造器，最多46个排列。确定性五规则在前，兼容单对交换在后；共享预算截止时允许只完成前几次构造，不虚报全部排序已经试完。

`order.permutation` 记录规则、构造编号、实际剩余预算和完整 `sourcePartIndex[j]`；子过程 `PartIndex`／成员下标映射回外层原输入，结果布局以原 `PartID/Instance` 绑定，按原问题验评。`order.result` 保留每次构造终局。诊断中的 `completed-constructions` 当前统计返回次数，包含部分解，**不是完整解数量**；是否完整须看逐次结果。记录中的算法局部索引型评分项仍是该次排序的局部排名语义，不能当外层原件编号。
