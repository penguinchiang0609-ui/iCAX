# 06 双层仿真、验证与加工交付

版本 1.0 · 2026-10-13。覆盖 F32—F38，领域 M08/M09，并连接 F09 的制造文件发布。原则是一个固定 Plan、多种检查和展示视角，最终以实际输出文件语义核验交付。

## 1 两类仿真的职责与资格

| 维度 | CAM 轨迹仿真 | 独立实机仿真 |
| --- | --- | --- |
| 数据 | ProcessPath 曲线、方向、事件 | 最终轴轨迹、真实机型运动链和环境 |
| 显示 | 工件、切割头、切割/空移线 | 完整固定/运动部件、头部、工件、夹具 |
| 用途 | 观察顺序、起点、方向和工艺连续性 | 检查实际各轴、部件碰撞、行程与运动约束 |
| 缺数据 | 无有效路径则不可播放 | 无实机配置或完整轴轨迹则待配置/待生成 |
| 资格 | 不形成整机通过报告 | 只有规定检查全部有证据才形成有效报告 |

头部预览可以发生在实机规划前，但必须显示预览来源和阶段；进入独立页不能沿用它的“播放成功”。历史 Plan 可以查看，历史模式不授予当前交付资格。

## 2 播放状态与计算验证分离

播放是交互会话：`sessionId, sceneEpoch, mode, planRef, clock, speed, state, controlSequence`。验证是可取消后台任务，输入固定快照，输出不可变报告。播放到结尾不自动生成通过结论，播放速度也不影响验证结论。

实机每帧根据 `q(t)` 和机型零位直接计算所有绝对/局部位姿，禁止不断把上帧增量叠到 Transform 导致 Seek、倒播和重复播放累积漂移。当前 Machine 的关节增量更新接口适合状态修改，正式播放器应有基于基准姿态求值的适配层。

播放状态不写入可撤销工程输入。可通过 Scene 运行切面/PDO/View 显示，但不驱动“几何已修改”的失效链。验证快照独立于显示细节，关闭网格、隐藏夹具、降低渲染帧率都不减少检查对象。

Seek 增加 controlSequence；旧异步资源/轴状态晚到按 sessionId+sequence 丢弃。Pause 只停播放，不隐式取消独立验证；Close 释放会话。机器重新配置后旧会话仍只能以历史状态查看或关闭，不能悄悄切到新配置继续播放旧轨迹。

## 3 检查集与报告结构

检查分为：输入/资源完整性、工艺尺寸/方向、运动可达与轴限位、速度加速度 jerk、连续碰撞、事件状态机、输出语义重放。各检查返回 `Pass/Fail/Unresolved/NotApplicable`；NotApplicable 必须有依据，Unresolved 不能被总报告当 Pass。

```text
VerificationReport {
  reportId, planRef, machineRef, calibrationRef,
  placementRefs[], fixtureAssemblyRef, checkProfileRef,
  inputDigest, verifierVersion, coverage[],
  checks[]: {kind, status, domainCoverage, tolerances, evidenceRef},
  issues[]: {id, severity, code, operationId?, trajectorySpan?,
             timeInterval?, entityPair?, sourceAnchor?,
             measuredValue?, bound?, limit?, evidenceRef, repairTarget},
  qualification: Passed | Failed | Incomplete,
  createdAt, elapsed, terminationReason
}
```

IssueLocation 同时携带 Plan/资源版本，用户点击问题先解析相应历史或当前对象；不能把旧采样 index 指向新轨迹另一个位置。问题合并按相同原因的连续区间聚合，仍保留首个违规和最严重值。

## 4 碰撞场景与精度

### 4.1 对象和碰撞对

场景构成：固定机床、运动部件、切割头各碰撞形状、工作台、加工件、夹具及用户障碍物。碰撞角色与显示层独立。allowlist 只排除有明确结构理由的接触对和接触模式，例如正常关节邻接面；不能全局排除所有相邻部件或“刀头对工件”。

机械臂加地轨单元必须包含地轨固定体、小车、机器人全部 link 及可选变位机。轨道和臂关节共用 q(t) 与时间基准，不能在播放开始前挪一次机器人基座后忽略轨道；Indexed 模式的关光移站也属于完整运动检查。

激光切割的束线与加工面相交是预期过程，但喷嘴/头体与工件接触一般不是同一类允许关系。光路检查和实体碰撞分开：束路是否被夹具遮挡、穿透后是否击中不应加工表面，需要按照工艺和材料表示计算，不由碰撞网格忽略名单处理。

### 4.2 连续检测和误差预算

对于近似碰撞网格，保存其与精确表面的有效偏差界。设求得距离下界为 `d_lb`，两对象几何/标定/轨迹误差上界总和为 e；只有 `d_lb - e >= requiredClearance` 才能证明间隙合格。没有误差界的显示网格不能作为生产避碰的充分证据。

旋转部件采用覆盖扫掠区间的保守界，不能只用 TCP 的位移估计整个头部移动。临近间隙区间细分并用更精确距离；达到深度/数值极限仍无法判断则 Unresolved。记录最小距离是上界、下界还是估计值，禁止混用。

连续碰撞所用插值必须与 05 的正式轴轨迹一致。若第三方检测器仅支持直线刚体插值，不能直接把非线性关节运动端点交给它就宣称整段连续保证；需要有界细分或适配运动函数。

### 4.3 材料去除和落料

首个版本可采用静态工件的保守检查，但报告必须明确覆盖范围。静态模型可能把已切除材料算作障碍，也无法证明落料后夹具/工件仍稳定；不能自动忽略这类碰撞。

若启用阶段材料状态，必须根据已执行事件与切割完成状态更新独立验证材料模型，保留中间形状与假设；其算法是新增能力，不能依据播放器把某片面隐藏就称为材料去除仿真。未建模的落料/热变形在报告 coverage 中明确，需工艺/装夹规则处理。

## 5 动态和工艺复核

轴位置、速度、加速度和 jerk 按连续段求值/求界，段间也检查连续性。检查限制来自实际机型和工具固定配置，不把UI播放倍率乘进真实加工速度。

切割段通过 FK 回算 TCP、光束方向和设计测量截面边界，对照 Intent/CompiledOperation 的尺寸合同。空移段检查光关闭、起止边界和所有部件运动；停顿段检查轴保持与工艺事件。气体/光/随动的最终状态必须确定，异常退出策略由输出配置明确。

验证器可以复用中性 FK/几何求值服务，但不复用规划器的“这条边已经安全”缓存作为唯一结论；缓存必须能独立验证输入摘要与证据边界。

## 6 三点定位与输出坐标

现场计划保存模型点、顺序、测量坐标定义及 applicationMode。两种合法输出模式：

1. CAM 已应用定位：输出使用已定位轨迹，文件/manifest 标明 transformApplied=true 和摘要，执行端不得再次乘该变换。
2. 执行端测量：输出包含经过设备契约支持的待定位计划，执行端负责取得测量、残差检查和变换应用。设备不具备此能力则不能按该模式交付生产程序。

“三个模型点已选”只表明计划就绪；缺少实测或执行端能力时不能变成已定位。执行端控制器协议由设备适配合同定义，本设计不推断 FACut-C 或某私有扩展名的含义。

执行端定位还会改变轴解、可达性和与固定机床/夹具的关系。定位前的 nominal Plan 报告不能直接覆盖任意实测变换。ApplyAtExecution 的生产资格要求二选一：其一，执行端取得实测变换后，按相同机床/环境合同重算或解释轨迹并完成必需验证，返回绑定变换、轴轨迹和程序 hash 的执行资格；其二，离线已对明确允许变换域给出完整保守验证且现场变换落在该域内。仅有 RTCP 或坐标偏置功能不满足这项条件。首批设备若无此能力，先回传实测数据到 CAM 应用定位、重新规划和验证，再交付最终程序；待测计划可导出准备资料，但不标记可直接生产。

## 7 加工程序不是新的路径权威

后处理直接消费固定版本 ProcessPath/AxisTrajectory/事件和执行配置。内部 `ProgramIR` 是编译期数据，带来源映射，既不成为第二套可编辑 Path Entity，也不让用户编辑文本后仍沿用旧 Plan 报告。

`ExecutionProfile` 明确：轴顺序/正负/单位、TCP/RTCP 责任、绝对/增量坐标、工件坐标与定位责任、支持插补类型、数值精度、速度模式、光/气/随动指令、程序入口/结束、未知指令处理和控制器约束。

后处理输出前检查每个功能是否可表达。若控制器仅支持线段，则将连续轨迹离散为满足姿态/成品/轴动态误差的段，不是按固定采样间隔粗略写 G1。不能用舍入后“差不多”的轴值当等价。

## 8 实际文件重放

输出链为：资格预检 → 编译 → 临时文件 → 独立语法解析器读取实际字节 → 解释控制器语义 → 回算运动/工艺 → 核对 → 发布。

解析器不直接复用后处理生成时的内存列表，否则无法发现序列化丢字段、轴序/单位错、舍入、缺尾段、模态指令和文本被改的问题。读取磁盘中的最终编码、换行、精度和文件集合；记录每个文件 SHA256。

重放比较两类条件：相对计划的路径/姿态/事件误差，以及重放本身是否符合机床和工艺限制。即使“相对差很小”，也可能原计划已经贴着限位，舍入后越界。无法解释的自定义指令或控制器插补行为导致 ReplayIncomplete，而不是跳过后继续通过。

### 8.1 关键发布竞态

Preflight 通过只返回当时的 qualificationDigest，不授予永久许可。生成或重放期间 Setup/机型/Plan 改变时，旧文件只能作为历史候选，不能作为当前生产交付。发布前再次核对 digest、报告覆盖、支持组合和文件字节 hash。

最后核验和外部文件显现之间要有明确临界区。Scene owner 先核验并授予短时 publication lease，覆盖此次交付所依赖的输入；首版依照全 Scene mutationSequence 保守阻止输入编辑/Undo/Redo，并返回可重试的 PUBLICATION_IN_PROGRESS，查询和播放仍可用。文件已经生成并关闭写句柄、通过重放且隔离其他写入后，发布 worker 只执行最终 rename/commit marker，再回 owner 记录结果和释放 lease；不能把整个后处理时间都放入这个临界区。

取消先于 lease 获准则不发布；文件已显现后取消不能谎报“已取消输出”。超时或断线导致结果未知时进入 Recovering，按 outputId 和文件 hash 查明后释放发布锁，不能盲目再次覆盖。Scene 关闭使发布进入恢复流程；重开先核对未终结记录。发布成功后的新编辑将包标为历史版本，不修改已交付文件。目标存储不支持原子 rename 时使用唯一版本目录和最后写入的提交标记；缺标记的包不得作为完整交付，传递端必须遵守此合同。

### 8.2 文件与数据库不是单一事务

文件系统发布采用本地临时包 + 已核验 manifest + 原子目录/文件替换（目标文件系统支持时）。Repository 记录 Prepared/Published 状态和可恢复 outputId；使用同 outputId 重试时查现有完整包/hash，避免重复输出或混包。

文件已经原子落盘但记录写入失败时，重连可从输出包 manifest 识别该 outputId，核对来源和完整性后补记；记录成功但目录发布失败时保持 PendingPublication，不显示“已交付”。不删除用户原有目录作为补偿，不让多个并发任务写同一临时目录。

## 9 消息合同

复用 `CamSimulation.Open/Play/Pause/Seek/Close`，Open 新增明确 `scope=HeadTrajectory/MachineTwin` 和固定资源引用；旧的 `mode=Current/InspectHistorical` 是时间资格维度，两者不混为一枚枚举。MachineTwin 检查完整配置，HeadTrajectory 不暗中启动整机验证。

`CamVerification.Run` 使用基线 checkProfile 固定引用和可选 requiredChecks，返回 taskId；后端补全生产用途必需检查，前端不能通过省略 collision 字段跳过检查。`CamSimulation.ReadIssues` 按固定 reportRef 分页，不分页读取“当前正在变化的列表”。

`CamOutput.Preflight/Generate` 沿用基线；Generate 的正式完成响应给 `outputId, manifestRef, replayReportRef, publicationState, pathSummary`，不把“写了一个文件”当成功。生产与设备验收用途都执行同样完整性/重放门槛，其支持组合和发布标签可不同。

## 10 必测故障

同一时间反复 Seek 后姿态无漂移；隐藏夹具仍碰撞；两个端点安全而旋转头中途撞板；网格误差大于剩余间隙；未知碰撞对/缺模型；动态段间超限；静态材料模型遇已切除区域；定位双应用；角度单位错误；输出轴序交换；末尾 CutOff 丢失；坐标舍入越界；输出中编辑机型；文件落盘后记录失败；未知指令导致重放不完整。报告必须逐项区分 Fail 与 Unresolved。
