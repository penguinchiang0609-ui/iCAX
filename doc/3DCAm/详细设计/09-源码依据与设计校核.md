## 3 公共协议的收敛

技术基线的 `CommandContext{contractVersion,commandId,expected}` 保持唯一，expected 必含 sceneEpoch、mutationSequence 及 Job/Setup 对应修订。所有 U64 在 JSON 中使用十进制文本。分册为表达步骤省略公共头时，不表示后端可以免验。Job 与 Setup 变体互斥，业务载荷中的 setupId 若重复出现必须一致。

| 对象 | 统一决定 |
| --- | --- |
| 工件导入 | 使用 `CamWorkpiece.Import`。复用基线 sourcePath 与宿主读取授权校验 |
| 特征识别 | ExtractCandidates 使用 extractionRuleRef 指向固定 CamPlanningProfile 并读取 recognition；QueryCandidates 只读候选；Create 一次消费整个凭据，批量原子创建所选项 |
| 识别数据 | geometryKind 唯一取 GeneralContour/Circle/Rectangle/Slot；boundaryRole、passage 和 classificationStatus 分开。recognition 子配置取代笼统 featureRecognitionToleranceMm；不维护双份阈值 |
| 几何修复/CSG | `CamWorkpiece.PreviewPreparation` 为新增候选命令；`CamWorkpiece.Prepare` 扩展 candidateRef 后提交。新产品交互必须先预览，operations 和候选摘要不符即拒绝 |
| 投影编辑 | `CamProjection.Preview` 接受 recipeDraft；`Confirm` 一次写入 Recipe+Intent。预览不提前持久化配方 |
| 工艺修改 | `CamProcess.Update` 返回 CamReply，采用 setupInputRevision，不新增 appliedRevision 同义字段 |
| 姿态策略 | 持久权威为基线 CamPosePolicy.mode，扩充为 Continuous、FixedToolDirection、FixedRotary；概念/界面 rotaryStrategy 仅是该字段投影，不在 CutFeature 另存独立可写副本 |
| 模拟对象 | scope=HeadTrajectory/MachineTwin；mode=Current/InspectHistorical 仍表示当前/历史资格 |
| 模拟来源 | Open 统一用 source 标记联合体：Plan{plan:ResourceRef} 或 CompiledPreview{operationBundle:ResourceRef,displaySchedule:ResourceRef}。MachineTwin 只接受 Plan；原顶层 plan 收敛进 source，不同时接受两份来源 |
| 验证要求 | 使用基线 `checkProfile:ResourceRef`；可增加 requiredChecks 作额外请求，服务端合并必需检查，客户端无权减少 |
| 任务类别 | 基线 TaskStatus.kind 扩充 Model、FixtureGenerate、FixtureBreakdown、FixtureExport、Projection、Diagnostic；已有 Import/Prepare/Extract/Generate/Verify/Output 保留 |
| 任务终态 | 仍使用 Succeeded/Failed/Cancelled/Superseded。失败详细原因新增 terminationReason；BudgetExhausted 不另作与 Failed 并列状态 |
| 结果资格 | 任务 Succeeded 表示对应计算完成；候选完成不等于输入已提交，验证完成也可能报告 Failed/Incomplete |
| 结果读取 | 基线 TaskStatus.result 是统一资源引用；结果清单携带 typedResultKind 及具体引用，CamReply.data 不塞入大数组 |

增加 FixedToolDirection 后，SetType 负责策略切换，并保留基线中独立校验 feature 的责任；更改标准分类/测量合同或功能轴须有 11 定义的当前候选证据。UpdatePose 仍不能旁路改 mode/轴锁/关键点。固定方向字段为 `{frameRef,direction:Unit3,angularToleranceRad,hardness}`；设计轴是独立事实。切换策略保留不适用旧字段作历史或草稿，但有效输入只消费当前变体。实际机床轴锁绑定 machineRef、axisId、value 和 wrapPolicy，转换时必须重新求解验证。

CompiledPreview 的 displaySchedule 只表示示意播放进度，未有完整时间规划时界面不能把它标为加工秒数或节拍；不编造尚未规划的空移。HeadTrajectory 使用 Plan 时则读取同一真实时间线。Open 返回 source、sessionId 和 timeDomain=DisplayProgress/PlannedSeconds，进度、跳转和速度控件据此解释。

同一任务的进度投影、终态查询和结果资源保持同一个 taskId。存在局部成功而整体失败时，诊断可引用局部候选；LastSuccessfulPlan 不切换。Cancelled 仅在取消获准早于提交临界点时成立；完成之后取消返回 AlreadyTerminal。

## 4 候选预览与确认合同

几何修复、投影、夹具和切割特征提取共用候选凭据结构，避免各模块自行解释“这份预览还能不能确认”。字段含义如下，所有引用均锁定版本。

```text
CandidateTicket {
  candidateId: UUID, kind: Preparation | Projection | FixtureAssembly | CutExtraction,
  sceneEpoch: UUID, ownerScope: JobOrSetup,
  baseMutationSequence: U64Text, dependencyRefs: ResourceRef[],
  sourceEntityRevisions: {entityId: UUID, revision: U64Text}[],
  draftId: UUID, draftRevision: U64Text, normalizedDraftDigest: Digest256,
  algorithmIdentity: {providerId: string, buildDigest: Digest256},
  resultManifest: ResourceRef, issueSet: ResourceRef,
  confirmationEligibility: Ready | NeedsChoice | Blocked,
  expiresAt: UTC, consumedByCommandId: UUID?
}
```

任务 owner 保存凭据和消费记录，预览资源为 RuntimeOnly。过期时间由候选保留策略决定，接口返回确切 expiresAt；页面只能提示有效期，不能自己延长。用户继续改草稿即增加 draftRevision，旧候选仍可浏览但不对应当前草稿。候选过期、Scene 变化或任一依赖不符时返回 CANDIDATE_EXPIRED/REVISION_CONFLICT；不能偷偷重新算出另一份几何并作为用户已确认的内容。

确认命令包含 CommandContext、candidateRef、draftDigest 和该类型允许的选择，例如投影 chosenBranches。服务端核对选择确实属于候选；Blocked 不得以 acceptedChecks=true 绕过。确认发布 Embedded 资源完整闭包，在同一事务更新正式输入和实体；成功后记录 consumedByCommandId。同 ID 重试返回原回执，另一 ID 重复消费返回 CANDIDATE_ALREADY_CONSUMED，并给出已创建对象引用。

CutExtraction 沿用既有 Create 载荷名 `candidateSet`，它是 ticket.resultManifest 的固定引用；后端据此找到唯一凭据，不再要求重复传 candidateRef。集合内 candidateId 与凭据 candidateId 是不同作用域；前者指单项，后者指一次预览。选中项全部提交后整个凭据消费，未选项不自动创建，具体规则见 11 §13。

配方、工艺、来源和实体更新失败时候选仍可用于查诊断，工程不改变。候选只有在事务成功后才标为已消费；“资源发布成功但事务失败”不能永久吞掉用户这次确认。取消预览只取消该任务和浏览状态，不撤销已提交的其他操作。

## 6 连续轴段的最小可执行格式

首批自有轨迹使用分段多项式，每轴至少能表示五次多项式以连接位置/速度/加速度边界；五次形式本身不保证满足约束，也不自动保证 jerk 连续。不同插值类型为明确联合体，未知类型拒绝。第三方控制器原语只有在存在同语义求值器时才进入有效结果。

```text
PolynomialSegment {
  segmentId: UUID, startSeconds: f64, durationSeconds: f64 > 0,
  degree: u8, coefficients: f64[axisCount][degree+1],
  parameterDomain: NormalizedTime,
  // tau=(t-startSeconds)/durationSeconds, tau in [0,1]
  // q_i(t)=sum(coefficients[i][k]*tau^k)
  sourceOperation: UUID?, sourceSpan: UUID?, phase: Cut | Rapid | Dwell,
  bounds: {position[], velocity[], acceleration[], jerk[], method, tolerance}
}
```

内部直线轴用 mm，旋转轴用 rad，时间用 s；导数包含 duration 的倒数幂。axisOrder 与系数行一一对应；有限轴不展开到限位外，连续轴保留真实绕转值。段区间按左闭右开求值，最后一段右端闭合；端点事件单独按 eventSequence 执行一次。Dwell 用常值轴段表达持续时间，零时长事件不伪装成运动段。

输入阶段验证有限数、轴数、次数、正时长及时间无缝覆盖。求动态界时对各阶导数的极值求根并校核区间，或使用带舍入裕量的区间包络；数值根不能界定时继续细分或 Unresolved，不能只取若干采样点最大值。段间位置、速度、加速度按允许连续等级验收；启停/工艺断点必须显式表达，不用时间重复隐藏跳变。

位置和方向的加工误差仍要经过 FK 对整段核验；轴多项式满足轴限位，并不证明 TCP 落在切割曲线上。历史报告保存插值 schema 和求值器 buildDigest，后处理量化后的轨迹按实际控制器语义重新验证。

## 7 几何算法参考的使用范围

- [OCCT Section](https://dev.opencascade.org/doc/refman/html/class_b_rep_algo_a_p_i___section.html)说明求交产生边和顶点；夹具材料区域、板厚包络与装配检查是产品算法。
- [OCCT Projection](https://dev.opencascade.org/doc/refman/html/class_b_rep_proj___projection.html)提供方向/中心投影和多 wire 结果；投影分支、设计尺寸和稳定身份由 03 负责。
- [OMPL 状态与运动检查](https://ompl.kavrakilab.org/core/stateValidation.html)明确离散检查的采样间漏检风险；05 要求有界运动检查适配器。
- [Ruckig](https://docs.ruckig.com/index.html)提供受速度、加速度和 jerk 限制的运动生成；其状态间轨迹不能替代本产品的成品轮廓保持证明。

## 8 设计交付的校核范围

文档校核检查 F01—F49 名称和数量、每项设计/验收映射、D01—D40、IK01—IK12、FR01—FR36 编号、分册和源码链接、JSON 示例、代码块闭合及已废弃同义契约。结果记录于[设计校核记录](设计校核记录.json)，passed 仅指这些静态规则。它不能证明算法正确、设计已达到全部可实施深度，也不能替代逐项人工设计审阅和原生验收。

实施验收必须使用 08 规定的独立判据、真实 Scene、真实浏览器和设备组合证据。尚未提供的实机/试切配置是实施输入，不妨碍当前明确算法接口与错误分支；任何具体配置未验证时保持未开放资格。
