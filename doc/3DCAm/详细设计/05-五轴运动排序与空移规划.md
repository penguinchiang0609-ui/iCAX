# 05 龙门五轴与机器人运动排序和空移规划

版本 1.0 · 2026-10-13。覆盖 F26—F31、F35 的运动部分，领域 M06/M07。输入是 04 的过程路径与允许姿态，输出是可唯一重放的完整轴轨迹，不是显示用折线。

## 1 规划问题如何分解

不能把五轴规划写成“逐点 IK → 最近邻排序 → 连接直线”。同一刀存在多个姿态/轴解，顺序改变连接，连接又决定端点分支与速度；端点改变还可能影响前后切割的动态可行性。

采用有限层级求解：

1. 工艺编译确定必须保持的几何、允许方向、事件与顺序依赖。
2. 每道工序产生有限个经验证的入口/出口分支候选及内部连续轴路径。
3. 在工艺偏序与人工锁定内选择工序顺序和相邻候选连接。
4. 为切割、连接和入口/退出整体做时间规划，必要时回退到候选分支。
5. 若调姿影响尺寸补偿，按 04 的有界机制回编译；最后独立验证所有约束。

这是预算约束下求可行优选解，不宣称全局最优。结果记录尝试次数、成本和终止原因，区分 `InfeasibleProven`、`NoCandidateInSupportedFamily`、`BudgetExhausted`、`Unsupported`、`NumericallyUnresolved`。一般数值搜索失败不能说“物理上绝对不可加工”。

## 2 机床模型是运动树，不是两个角公式

支持头头、台台、头台等龙门配置，以及六轴机械臂加地轨，必须由运动链声明和单独验收，不写死 AC/BC 或轴数 5。机床描述中明确 base、workpiece attachment、tool attachment、每个活动/固定关节的 parent/child、轴、零位、正向、单位、限位及工具标定。机械臂以地轨联动单元为主配置；轨道、臂关节及可选工件变位轴共同进入 q，轴角色和控制器同步模式见 [10](10-逆运动学开源库选型与接入.md)。

```text
KinematicSnapshot {
  machineRef, calibrationRef, executionProfileRef,
  joints[]: {id, parentLink, childLink, kind,
             T_Parent_Joint0, axisLocal, qZero,
             hardLimits, softLimits, wrapPolicy, dynamicLimits},
  toolLink, T_Tool_TCP, beamDirectionLocal,
  workpieceLink, T_Link_Setup,
  collisionAssemblyRef, enabledAxes[],
  supportedTask: PositionAndDirection | FullPose
}
```

工作台运动会改变工件世界位置，求解目标是相对工件的 TCP/光束关系。统一由 FK 得到 `T_Base_TCP(q)` 与 `T_Base_Workpiece(q)`，计算相对变换；不能先把工件变换成世界坐标后在所有时刻当作静止。

常见五轴激光任务约束位置 3 维和单位光束方向 2 维，不额外要求任意第六维 roll。即便工艺不约束 roll，完整切割头的世界姿态仍由真实运动链确定，碰撞使用 FK 的完整姿态，不能把头部当无限轴对称物体。

## 3 标定与能力开放

几何模型加载不等于标定。标定快照需包含旋转中心、轴向、工具伸出和 TCP，记录来源、单位和版本。最少通过若干已知轴位的 TCP/方向实测或权威基准，计算残差并检查整个使用区间；单一姿态拟合正确不能授予全工作空间资格。

支持目录按 `(machineFamily, kinematicProfile, toolProfile, processFamily, postProfile)` 建立能力组合。没有通过该组合测试时允许配置浏览和离线检查，但不能自动开放 Production。换工具长度、旋转中心或轴限位都使相关结果失效。

## 4 连续逆解与分支选择

### 4.1 单位置逆解

单点求解复用成熟开源库：统一 Pinocchio 模型，已验证机型优先使用 IKFast 生成的解析后端，一般受限任务使用 Pinocchio+Ceres 数值后端；结构适配的机械臂可选 OPW。选择理由、五维/六维任务、地轨自由变量与 IService 接入见 [10](10-逆运动学开源库选型与接入.md)。固定最大迭代、残差门限和多初值策略，所有候选经独立 FK 回代核对位置和方向、硬限位及 branch identity。库返回成功仅授予候选资格，不授予整条轨迹资格。

方向残差用球面夹角或两个切向分量，不用易受 ±π 跳变影响的欧拉角差。Jacobian 的平移/旋转量纲先按工具长度/任务尺度归一化，再判断奇异程度；单一未经标度的条件数不是可靠机型无关阈值。

连续轴保存 winding/turn count。允许跨 ±π 的连续转轴与有电缆/机械限位的转轴分别定义；不能一律将角度归一到 [-π,π]，否则 359°→1° 的实际转动语义丢失。

### 4.2 沿路径建立候选图

按几何曲率、允许方向变化、限位裕量、奇异指标及障碍物距离自适应采样。每层节点为 `(s, q, branch, directionChoice)`，q 包含地轨等已启用外部轴；同一机械臂分支下可有多个轨位和自由变量候选。节点只代表该位置可行；边还要检查连续运动、方向域、几何误差和转轴周期，不能先独立选轨位再只连接机械臂。

成本按归一化项组合：关节移动量、限位裕量、法向偏好、奇异风险、分支变化与人工软目标。硬锁定和设计尺寸不能当有限权重罚项，否则成本优化可能“花一点罚分”越过硬约束。

首轮可用动态规划选择最优连续候选序列；涉及二阶平滑时状态需要相邻两层或明确速度候选，不能在只记当前节点的 DP 中声称已经优化加速度。随后用受限平滑/重新采样检查完整路径和工艺约束。

### 4.3 奇异区域

在奇异附近方向微变可能需要很大轴运动。允许措施按工艺资格选择：在允许角域内调姿、换连续分支、降速、增加工艺分段、改装夹。不能只对角度做平滑而越过轮廓/方向约束。固定功能轴没有可调角域时明确返回限制，不能暗改孔轴。

分支切换必须有连续连接或在工艺允许的断光分段处重定位；不允许切割过程中瞬间翻轴。每个不可行区间记录 source anchor、候选状态和拒绝原因。

## 5 加工顺序作为约束图

工序节点以 operationId 表达，不是 UI 显示索引。建立偏序边：内孔先于使其支撑失效的外轮廓、必须保留的支撑/微联、用户明确依赖、固定前缀/相邻锁。不能仅凭包围盒包含关系推断三维支撑关系；未知支撑依赖需要人工配置或保守顺序。

提交手动排序前检查偏序环和冲突锁，返回最小可说明冲突子集，例如“用户锁 A→B，而支撑依赖要求 B→A”。取消排序只丢草稿；应用一次 Undo；后移/前移操作在草稿内撤回/重做。

自动排序采用拓扑可选集合上的增量选择，粗成本先估计空移距离/时间，再对若干候选做真实连接求解。保持有限 beam width、确定的 tie-break 和随机种子；不能把几何最近但无可行连接的节点当作最优下一刀。

完整连接代价包含端点姿态/轴分支、速度状态、抬升和避障，不仅是 TCP 欧氏距离。支撑条件变化引起顺序变化时，要同时重算受影响连接和剩余工序可达性。

## 6 空移规划

### 6.1 连接契约

输入为 `fromBoundary`、`toBoundary`、机床/碰撞快照、人工覆盖、可用策略和计算预算。边界包括实际 q、速度/加速度约束和光/气/随动状态。起始/结束连接同样存在，首刀前与最后一刀后不能缺失。

策略按以下顺序尝试，且每步记录证据：

- Direct：在指定机床插补语义下构造轴/任务空间连接，完整验证途中运动。直线 TCP 不意味着机床部件也走直线。
- ClearancePlane：先确认有向安全平面、可达抬升方向以及旋转过程包络；不是默认“Z 抬高就安全”。转台/头台需考虑工件同步运动。
- Search：在关节配置空间使用有界搜索，结合任务空间引导。碰撞几何、状态和运动有效性检查由产品提供，不能由规划库默认全有效。
- Waypoints：按用户显式路点求解并验证，不允许路点之间未检查。

目标状态可行但无连接时回溯端点分支，再考虑未锁定顺序。任何回退不得删除人工硬锁。总预算耗尽返回可查看的诊断而不是半条可执行连接。

### 6.2 连续碰撞与保守界

仅检查采样 q₀/q₁ 无碰撞不证明中间安全。优先使用支持本机床运动插值的连续检测；否则做带位移上界的自适应区间细分。对每个刚体，线位移与角位移半径界可构成保守 swept bound，间距大于双方最大可能位移与误差和时才可跳过该区间；无法界定则继续细分或报告 Unresolved。

OMPL 的默认离散 MotionValidator 可能漏掉采样间违规，其官方建议在具备连续检测时实现相应 MotionValidator。本方案只把 OMPL 作为可选搜索适配器，不把它作为碰撞正确性的来源：[OMPL 状态和运动校验](https://ompl.kavrakilab.org/core/stateValidation.html)。

## 7 时间规划必须保持加工路径

对已确定的连续轴路径 `q(s)` 选择单调时间标度 s(t)，满足：

```text
q_dot   = q_s * s_dot
q_ddot  = q_ss * s_dot² + q_s * s_ddot
q_jerk  = q_sss * s_dot³ + 3*q_ss*s_dot*s_ddot + q_s*s_jerk
```

同时满足轴速度/加速度/jerk、TCP 工艺进给和工艺事件速度要求。真实尖角在无允许轮廓误差带的情况下必须降至可行速度或停点，不能为了连续快速运行自动磨圆。

规划时先求速度包络与前后向可达性，再在可行域内生成平滑时间段并做导数上界检查。切割和空移在统一时间线上连接；边界速度/加速度不兼容时重新定时，不能把每段“各自通过”直接串起来。

Ruckig 这类状态到状态的限 jerk 生成器可作为合适连接段的候选工具；用一串离散轴位置调用它，不能据此证明中间 TCP 仍满足切割曲线。路径保持和最终 FK 验证是本产品责任。是否引入由任务适配、性能与部署验证决定，本设计不直接新增依赖：[Ruckig 文档](https://docs.ruckig.com/index.html)。

## 8 连续轨迹资源的必要扩充

现有 `CAxisTrajectoryResource` 只有 samples；详细设计要求增加可唯一求值的 segment schema：

```text
AxisTrajectory {
  schemaVersion, machineRef, calibrationRef,
  axisOrder: {axisId, kind, unit, wrapPolicy}[],
  segments[]: {segmentId, timeStart, duration,
    interpolation: Polynomial | ControllerDeclared,
    coefficientsPerAxis | controllerPrimitive,
    boundaryState, provenDerivativeBounds,
    sourceOperation, sourceProcessSpan, phase: Cut|Rapid|Dwell},
  eventTimelineRef, sourceMapRef, samplingCacheRef?
}
```

正式求值使用 segment 插值定义；samples 仅作缓存/预览或明确的线性插补格式，不能在播放器、验证器和后处理各自猜一种样条。position/velocity/acceleration 由同一连续函数求值，时间严格单调，停顿和瞬时事件有明确规则。

轴数量/顺序由 axisOrder 确定，不能靠数组位置约定某个具体机型。资源保留 frame/单位定义，后处理的度/弧度、毫米/英寸转换只做一次并可回放核对。

## 9 可复现、缓存和复杂度预算

缓存按阶段建立：几何编译依赖 Intent/工艺/几何；局部 IK 依赖机型/工具/目标；连接依赖两端完整状态与环境；定时依赖连续轴路径和动态配置。移动夹具不必重复草图投影，但所有相关连接/碰撞资格要重验。

候选层有 N 个采样、每层 K 个候选时，最简单相邻层图约 O(NK²) 边验证；连续碰撞通常主导成本，必须利用保守 broad phase、缓存和候选剪枝。不能只给“支持十万点”的口号，应记录 N/K、碰撞对数、细分深度、内存上限和时间预算。

所有预算在 PlanningProfile 中显式声明。达到上限返回 BudgetExhausted，保留可诊断候选；不能退回未经验证的最短直连。

## 10 提交和验收

完整 Plan 必须包含所有启用工序、顺序、起终状态、全部连接、事件和当前固定配置。worker 完成后按 01 的栅栏提交；部分预览永不覆盖 LastSuccessfulPlan。

样例至少包含：连续转轴跨 ±π、有限转轴绕回、两分支切换、奇异附近固定孔轴、头台相对运动、工艺顺序环、最近邻无法连接而次近可行、两端无碰撞而中间碰撞、抬升方向不可达、切割角点超加速度、时间拼接 jerk 跳变、预算耗尽和取消。每条成功轨迹由独立 FK/约束检查验证整个连续函数，不能只检查采样点。
