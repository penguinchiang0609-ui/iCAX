# 10 逆运动学开源库选型与接入

版本 1.0 · 2026-10-13。覆盖 F26—F29、F35—F38。机型范围包含龙门五轴，以及以六轴机械臂加地轨为主的机器人切割单元；六轴固定基座、七关节机械臂和带变位机的单元使用同一契约扩展。本次选型按成熟度、任务适配和 Windows/C++ 接入成本决定，不以许可证作为技术淘汰条件。

**采用统一机床模型、多个求解后端：Pinocchio 负责通用正运动学与 Jacobian，IKFast 为经过配置验证的机型生成解析逆解，Pinocchio+Ceres 负责通用受限数值逆解。** 六轴机械臂加地轨由整个单元共同规划；固定轨位上的机械臂解析解只是候选生成的一种加速方法，不能代替地轨联动规划。OPW 可作为匹配机械臂结构的专用后端，首版不同时引入所有候选库。

2026-10-24 接入进展：已提供中性的 `IMachineKinematicsService` 和 `IMachineMotionPlanningService`，分别由 Pinocchio 2.7.0 + Ceres 2.1.0，以及真实逆解候选 + Descartes 有限候选图实现。Windows Debug 原生测试已使用仓库 LC-3015 和 IR-1600 规范化运动树，验证 FK、Jacobian、五维位置/IJK 逆解和短段连续运动；这不代表对应实体机床的碰撞、控制器和动力学验收通过。IKFast、OPW 尚未接入。

产品层负责冻结 CAM 轨迹、工件摆放、轴限位、速度和实际碰撞对象，提供完整关节插补边的连续碰撞回调。`CamSimulation.PlanMachine` / `QueryTask` / `CancelTask` 组织异步任务；通过检查的计划以 `MachineMotionPlanRef` 嵌入工程。重新打开须重新核对源输入，导出使用同一份当前计划，不另求一套不同关节分支。工艺、资源、版本、撤销重做和文件保存仍归产品域与 framework/database。

当前五维数值逆解不施加刀轴自转角。交互式完整六维末端拖动保留独立的 KDL FullPose 约束与当前关节温启动；不得用五维求解替代旋转拖动。轨迹插补误差及进给速度采用有预算的自适应采样核对，轴速度受限；尚无连续 TCP 误差界、加速度/jerk、力矩或控制器标定资格，计划明确返回 `machineReady=false`。

交互拖动按一次手势冻结运动树、工件/夹具网格和碰撞结构，后续目标以已接受关节位置温启动，继续检查整段轴运动。领域或机床配置改变立即使缓存失效；缓存不跨手势。前端同一时刻只提交一个目标，将中间输入合并到最新目标，正常结束必须排空最后目标后才关闭 framework 撤销命令；Esc 使用同一命令的 Cancel 回滚。

参数编辑的自动保存通过通用 `Project.AutoSave` 完成。已存在的工程文件、文档设置和持久资源闭包描述完全匹配时，确认 database 恢复日志已刷新即可；持久资源或设置改变仍完整写入工程。正在进行的事务或手势返回 Deferred，不能在拖动中重打工程快照。显式 `Project.Save` 始终写入完整工程并重置恢复日志；保存义务不依赖后续界面或历史列表刷新成功。

## 1 成熟开源候选的判断

| 项目 | 核实的能力 | 龙门五轴 | 机械臂和地轨 | 选型结论 |
| --- | --- | --- | --- | --- |
| [IKFast / OpenRAVE](https://github.com/rdiankov/openrave/blob/master/python/ikfast.py) | 支持 TranslationDirection5D、Transform6D；为具体运动链生成 C++ 求解代码 | 对应位置加刀轴方向，生成成功和退化工况仍须逐机型验收 | 可为机械臂生成解析解；多余关节由外层给定自由变量后多次求候选 | 已配置机型的解析主选 |
| [Pinocchio](https://github.com/stack-of-tasks/pinocchio) | C++ 运动树、FK、Jacobian/导数；支持程序化模型，官方列出 Windows 测试 | 能表达直线轴和转轴及相对运动 | 可表达地轨、机械臂和工件侧运动分支 | 统一计算模型与正解主选；本身不是开箱即用的完备 IK 产品 |
| [Ceres Solver](https://github.com/ceres-solver/ceres-solver) | 成熟 C++ 非线性最小二乘，支持变量上下界 | 可求明确的五维位置/方向任务 | 可处理地轨和冗余轴变量；残差与候选策略需本产品定义 | 与 Pinocchio 组合成数值后端，不自写优化器 |
| [TRAC-IK](https://github.com/traclabs/trac_ik) | KDL 与优化算法结合，支持关节限位、超时和不同选解目标 | 官方接口是目标 Frame 加六维容差；不能直接当作原生五维方向任务 | 适合串联机械臂数值 IK，但单次种子求解仍不等于整条联动轨迹 | 保留对照候选，不作为统一架构的默认后端 |
| [Orocos KDL](https://github.com/orocos/orocos_kinematics_dynamics) | 成熟 C++ 链式 FK/Jacobian 与 NR/LM 类 IK | 可建运动链；默认完整姿态残差需适配 | 可用于机械臂和轨道链的基准对照 | 不单独作为本产品全机型逆解答案 |
| [OPW Kinematics](https://github.com/Jmeyer1292/opw_kinematics) | 面向具有特定平行基部及球腕结构的工业机械臂闭式解 | 不是三直线两转轴龙门通用求解器 | 符合结构的六轴机械臂可参数化接入；地轨由外层协调 | 特定机械臂的可选解析插件 |
| [IK-Geo](https://github.com/rpiRobotics/ik-geo/blob/main/README.md) | 以 6R 机械臂几何子问题分解为主要覆盖，包含 C++ 实现 | 不能将 6R 覆盖外推为全部混合直线/旋转五轴 | 可研究特殊六轴机械臂及奇异分支，地轨不自动包含 | 后续专项候选，不作为首批通用承诺 |

成熟度不由 star 数量决定。IKFast 有既有机械臂生态使用证据，但 [MoveIt 文档](https://moveit.picknik.ai/main/doc/examples/ikfast/ikfast_tutorial.html)也说明生成环境较繁复，并存在该插件自己的自由度范围限制。因此直接包装生成的 C++ 内核，不把 MoveIt/OpenRAVE 场景、运行时或 ROS 消息引入 iCAX。Pinocchio 的官方 [IK 示例](https://github.com/stack-of-tasks/pinocchio/blob/devel/examples/inverse-kinematics.cpp)是数值迭代示范，不能照搬后声称已处理全部限位、冗余和加工硬约束。

## 2 先统一设备任务而非轴数量

`machineFamily` 用于描述布局；`taskKind` 决定约束；轴表决定求解变量。不能由“名称含五轴”硬编码数组长度 5，也不能把第七轴一律当作机械臂内部关节。

| 单元 | 典型变量 | 切割任务 | 冗余及责任 |
| --- | --- | --- | --- |
| 龙门五轴 | 3 个直线轴 + 2 个转轴；分布由头头/头台/台台模型决定 | PositionAndDirection，3 维位置+2 维方向 | 通常非冗余，但仍有多解/周期/奇异 |
| 六轴机械臂固定基座 | 6 个转动关节 | PositionAndDirection 或 FullPose | 方向任务存在一个局部冗余自由度；FullPose 仍可能有离散多分支 |
| 六轴机械臂加地轨 | 1 个地轨直线轴 + 6 个机械臂关节 | 两种任务均支持 | 地轨参与整体变量；五维任务一般具有两个局部冗余自由度，六维任务一般具有一个，实际以 Jacobian 秩为准 |
| 七关节机械臂加地轨 | 1 个地轨轴 + 7 个关节 | 两种任务均支持 | 增加自由变量预算，不沿用六轴分支数量 |
| 机械臂加地轨及变位机 | 地轨、机械臂、工件侧转轴 | 相对工件的任务 | 工具和工件两分支同时运动；外部轴支持范围按控制器和配置资格开放 |

PositionAndDirection 不约束绕刀轴的 roll；FullPose 只有工具/工艺要求完整朝向时使用。即使不约束 roll，头部、机器人腕部和附属结构的完整姿态仍由 FK 确定并参加碰撞。不能为了给 6D 求解器凑参数随意指定一个 roll，删掉本来合法的解。

## 3 地轨进入运动链和作业合同

典型地轨单元采用以下权威关系：

```text
CellBase
  ├─ RailJoint(P) → Carriage → RobotMount → J1 ... J6 → Tool → TCP
  └─ FixtureMount → 可选 PositionerJoint(s) → Setup → Workpiece

T_Workpiece_TCP(q) = inverse(T_Base_Workpiece(q)) * T_Base_TCP(q)
q = [rail, robot_j1, ..., robot_j6, optional_positioner_axes...]
```

地轨字段包括 axisId、role=ExternalLinear、轴向/零位、有效行程、正负向、安装变换、速度/加速度/jerk、同步模式和 controllerChannel；机械臂关节为 RobotJoint，变位机轴为 Positioner。轴身份与数组位置分开，额外的电缆/拖链运行限制以有效轴域或经建模的障碍表达，不能从外观网格猜测。

两种执行模式必须显式区分：

- `Coordinated`：轨道与机械臂同步联动，切割过程中 q(t) 同时含全部轴；IK、连续碰撞、定时和后处理统一求解。优先按此模式设计主能力。
- `Indexed`：仅设备能力或工艺明确限制时使用。切割期间锁定轨位，在关光连接中允许移动，再确认稳定与定位状态；不得自动将同步联动任务降成分站加工。

若轨道与机械臂由独立控制器驱动，ExecutionProfile 必须说明同步时基、轴命令语义及跟随误差合同。缺少同步能力时不能导出名为 Coordinated 的程序。轨道改变基座位置后，地轨小车、机器人所有 link、工具和相对工件运动均重算；只移动 TCP 的画面不是联动仿真。

## 4 IKFast 的接入办法

IKFast 官方源码说明生成代码可以编成独立库，复杂机型可能需要 LAPACK；源码同时列出十进制几何带来的生成复杂度和退化情形。因此采用离线生成、冻结构建的方式，不让用户每次点击生成刀路时运行符号求解器。[IKFast 生成器说明](https://github.com/rdiankov/openrave/blob/master/python/ikfast.py)

本产品的适配流程如下：

1. 从经过校验的 KinematicSnapshot 构造求解链。头台/台台可对工具与工件之间的树路径建立等价串联关系，反向边必须使用完整逆变换，不能只给关节角乘负号。先与原运动树 FK 对照证明等价。
2. 龙门机选择 TranslationDirection5D；六轴机械臂可生成 Transform6D 后端。方向任务若使用 6D 后端，外层按配置在允许 roll 上求多个目标候选；采样覆盖明确记为有限，不能声称穷尽所有姿态。
3. 六轴机械臂加地轨可复用机械臂解析内核：为多个候选轨位构造机器人基座坐标中的目标，枚举各机械臂解；这只是单路径位置的候选集。相邻位置的轨位与关节必须由 05 的候选图联合选择和连接。
4. 生成工件侧多活动轴的等价链失败时，返回该后端 Unsupported，并转入明确启用的数值后端；不得改成工件静止来强行求解。
5. 生成代码的几何摘要、关节顺序、零位、常量和工具变换与 MachineProfile 严格绑定。若仅外部基座/TCP 固定变换可在适配层精确换算，则不必重新生成；内部轴向、旋转中心或几何常量发生变化时必须重新生成或切换经验证数值模型。
6. 返回全部已发现的合法候选，按限位展开允许周数、去重并独立 FK 回代。奇异处的解族需要参数范围/覆盖信息；不能以一个任意角度代表所有可用分支。

不为加速生成而无记录地将实测标定参数四舍五入。确需对名义模型作有界近似时，记录误差预算，最终仍用实际标定模型回代和验证。生成器、模型和输出 C++ 的 hash 一并保存；生成器构建环境与 Windows 运行库分开冻结。

## 5 Pinocchio 与 Ceres 数值后端

Pinocchio 通过程序化模型使用 iCAX 规范化的同一运动树，避免重新读一份 URDF 后形成第二套轴序、单位和标定事实。每个 worker 独立拥有可变 Data/求解上下文；不可变模型可按摘要缓存，缓存没有工程业务状态。[Pinocchio 能力与平台说明](https://github.com/stack-of-tasks/pinocchio)

本产品构造位置与方向残差，Ceres 执行数值优化。对于相对任务，FK 得到 `p(q), d(q)`，目标为 `p*, d*`，使用：

```text
r_position = (p(q) - p*) / positionScale
r_direction = (d(q) - d*) / directionScale
```

方向残差有三个分量但局部独立维数为二，不约束 roll，也不把 d 与 -d 当作同一方向。相反方向可能形成不良驻点，须多初值并做实际夹角验收；不能仅看优化器的“已收敛”。FullPose 单独使用有明确参考系的旋转残差，不混用两种任务。

求解变量先按各轴量纲/行程尺度规范化，避免毫米地轨和弧度关节数值条件悬殊。关节/轨道硬上下界使用 Ceres 参数界；固定轴从变量中消去或固定对应参数。Ceres 的 [Problem 接口](https://github.com/ceres-solver/ceres-solver/blob/master/include/ceres/problem.h)提供上下界机制，但不是通用非线性约束求解器，因此碰撞、工艺角域等仍作为候选接受的硬检查，不能写成一个可被优化器牺牲的有限权重惩罚。

冗余候选通过确定的轨位/自由变量种子、前一位置解、限位中点及分支种子生成；记录种子与预算。优先得到满足位置/方向容差的候选，再在可行候选之间按偏好选解。数值迭代未找到解返回 NoCandidateInSupportedFamily 或 BudgetExhausted，不能证明物理上不可达。跨路径位置的连续分支仍由规划器负责。

这个后端需要实现任务残差、相对 Jacobian、模型适配和结果判定；成熟库承担 FK/Jacobian 与优化迭代本体。它不是把第三方示例改个名称就完成的通用 IK，实施时按第 9 节验收。

## 6 地轨与机械臂的连续联合规划

单点最近关节解常导致地轨来回移动、腕翻转或下一刀不可达。候选节点必须保存整个 q、机械臂分支、轨位、工具 roll/自由变量及可达裕量。边检查轨道和各关节连续性、全单元碰撞、限位、方向/成品误差及执行模式。

软目标可包含轨道移动时间、轨道方向反转、腕部/肘部限位裕量、奇异风险、能耗代理和接续成本。以物理意义归一化后配置权重；不把“尽量不移动轨道”设成不受用户控制的硬锁。长工件可用可达区域的保守界筛选轨位范围，再在区间内生成候选；不能从工件包围盒中心直接确定唯一轨位。

自动排序比较的是包含外部轴运动的实际可行连接代价。选择同一工件附近的刀不一定更快：机器人构型不连续时可能需退刀、移动轨道和重新进入。最终整体时间规划统一约束全部轴；控制器不能同步实现的组合不能借播放速度掩盖。

遇到死端时按顺序扩大已允许自由变量候选、回退邻接分支、调整未锁定顺序。允许角域、实际轴锁和轨道模式不被静默放宽。所有回退受总预算约束，返回可解释的失败区间。

## 7 按 iCAX IService 接入

技术基线的 MachineKinematics 能力落实为拟新增 `IMachineKinematicsService : IService`。其接口不暴露 Pinocchio/KDL/Ceres/IKFast 类型，不调用 Repository，不查前端选择，也不保存 Plan。

```text
BuildModel(KinematicSnapshot) -> ImmutableModelHandle + ModelDiagnostics
Forward(model, axisValues, requestedFrames) -> FrameTransforms + TaskPose
Jacobian(model, axisValues, taskDefinition) -> ScaledTaskJacobian
InverseCandidates(model, IKRequest, cancellation) -> IKResult

IKRequest {
  taskKind: PositionAndDirection | FullPose,
  targetFrame: FrameId, tcpFrame: FrameId,
  positionMm: Vec3, direction: Unit3?, orientation: Quaternion?,
  jointConstraints: {axisId, lower?, upper?, fixedValue?, wrapPolicy}[],
  seeds: AxisVector[], freeVariableDomains: AxisDomain[],
  toleranceProfile: NeutralToleranceData,
  maxCandidates: u32, maxIterations: u32, deadline: MonotonicTime,
  deterministicSeed: u64, solverPolicy: QualifiedProviderPolicy
}
IKResult {
  status: Solved | NoCandidate | Unsupported | Cancelled | BudgetExhausted | Unresolved,
  candidates: {axisValues, branchKey?, freeValues, fkResidual, limitsMargin}[],
  coverage: DiscreteEnumeration | FiniteFreeVariableSearch | LocalNumericalSearch,
  providerId, providerBuildDigest, modelDigest, diagnostics
}
```

machineRef 与 calibrationRef 在 Scene 中先解析成不可变快照。产品域记录资源依赖和任务资格，再调用中性服务；服务返回的候选由 05 的规划器选取，最后按 01 发布资源和提交引用。服务结果的 BudgetExhausted 映射为任务 Failed+terminationReason，不改变公共 TaskStatus 枚举。

后端选择按 `(modelDigest,taskKind,solverQualification)` 固定，不能根据显示名称包含“机器人”自动启用。解析和数值后端同时使用时，输出记录每组候选的来源；数值修正解析解之后重新 FK 核验和分支跟踪，不能沿用原解析解的完备性声明。

## 8 Windows 构建和部署

拟新增中性 Kinematics 插件和产品域适配，目录遵守现有插件依赖方向。首先引入 Pinocchio 与 Ceres 的最小 C++ 配置，并编译一个目标龙门求解器及一个机械臂求解器。Eigen、Boost/Abseil 等传递依赖按所选提交实际构建清单统一，Debug/Release、运行库和导出 ABI 与 iCAX 对齐。[Ceres 官方 Windows 构建说明](https://github.com/ceres-solver/ceres-solver/blob/master/docs/source/installation.rst)

IKFast 只将所需生成代码、适配层及必要运行依赖放入产品；符号生成器环境作为开发工具保存。生产默认关闭 Python 绑定、可视化示例和无关求解器。精确版本在原型通过后固定到 tag/commit 与校验和，不追随 master/devel；升级必须重跑同一机型矩阵。

线程数由 Scene 任务预算统一分配，Ceres 内部线程数与并行候选任务协调，避免每个位置各开一组线程。超时和取消不终止进程；不能及时中断的第三方调用隔离其生命周期，返回后仍检查发布资格。

## 9 选型原型和验收

作为 W04 的前置原型，至少选一台明确 3P2R 龙门五轴、一台六轴机械臂加地轨；模型参数先可使用有明确解析答案的合成样本，实机资格另外取得。测试输入与“真值生成”必须独立，不能仅用同一个 FK 给同一个 IK 自证正确。

| 编号 | 验收内容 | 判据 |
| --- | --- | --- |
| IK01 | 龙门 PositionAndDirection | 与独立解析/基准结果一致；没有人为增加 roll 约束 |
| IK02 | 机械臂加地轨两种任务 | 轨位改变正确影响基座，FullPose 与方向任务分开验收 |
| IK03 | 工具/工件双运动分支 | 变位机和轨道运动时相对 FK 正确，原树与等价链一致 |
| IK04 | 限位与绕转 | 地轨软/硬限位、机器人有限轴和连续轴分别正确，不能归一化掩盖越限 |
| IK05 | 奇异、多解、腕翻转 | 返回覆盖与分支信息；连续路径不瞬间翻腕，不虚报穷尽解 |
| IK06 | 长工件连续联动 | 轨道和机器人轴函数一起连续，并满足各轴动态约束 |
| IK07 | Indexed 与 Coordinated | 固定轨位切割锁有效；联动模式实际包含轨道运动，后处理不能缺外部轴 |
| IK08 | 标定变化 | 内部轴几何改变后旧解析内核失效；可外置变换的情况经过等价证明 |
| IK09 | 冗余与死端回退 | 更换轨位/roll候选能恢复的路径得到可行结果，硬锁始终保留 |
| IK10 | 全单元碰撞 | 轨道小车、机械臂肘腕、工具与工件/夹具都检查，不能只查TCP |
| IK11 | 性能、取消和可复现 | 固定模型/种子/预算下记录成功率、误差、p50/p95/p99、内存及取消延迟；不引用第三方宣传耗时 |
| IK12 | 输出重放 | 地轨与机械臂轴序/单位/时基对应，故意交换外部轴或丢同步语义时拒绝交付 |

IK01—IK12 全部为待执行案例，关联 08 的 D18—D24、D26、D27、D32、D37。机型开放的必要条件是残差、动态和连续碰撞满足该配置容差；求解耗时是优化目标，不能以超预算后放宽加工精度换取“成功率”。

首轮原型结束必须产出两种机型的模型/求解器版本、可复现输入、各后端结果及边界失败报告，再决定是否启用 OPW 等专用机械臂加速插件。界面和领域协议不因后端切换而重写。
