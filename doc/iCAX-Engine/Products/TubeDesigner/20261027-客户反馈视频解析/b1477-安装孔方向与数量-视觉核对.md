## 可复用的工艺提供器与最小修改方向

1. `src/apps/tube-designer/templates/_shared/assembly_structural_machining.py` 的 `structural-apertures` 接受圆孔 `diameter + placement + vector`，可以表达 X 侧壁或 Y 前后壁单壁孔。方向变化不需要建立新的布尔加工器，更不应旋转整个装配来实现。
2. 当前 `_section_evidence()` 已计算侧向和正面截面度量，但返回的 `faces` 只含侧向支承范围。若加正装，需要返回并实际使用前后壁的平直范围和壁厚；不能用侧壁宽度替代正面可用区域。
3. 现有 `structural-male-head`、`profile-stock-preparation` 可继续处理公头与轴向料长；安装孔方向不要求重写它们，也不要求增加实物零件分段。
4. 数量可直接用数值枚举：`valueType: "enum"`，`defaultValue: 3`，`choices[].value` 为 JSON 数字 2、3、4、5。原生 `TemplateCodec.cpp` 的枚举比较及规范化保留数值类型；场景下拉和提交链路也保存并恢复 Number。无需改成字符串数量。
5. `integer + choices` 不适合作为替代：既有 integer 路径仍呈现数字输入，且原生整数校验不会用 choices 限制离散集合。
6. 数字枚举改动应同步模板规划函数的 2–50 校验及现有前端测试。`MinimalProtectiveGrilleProductTest.mjs` 当前断言 integer 范围；`MinimalGrilleMounting.browser.mjs` 编辑助手需按实际 select 控件选择，而非用 `typeof value === "string"` 判断下拉框。

## 后续确认及实现状态（2026-10-27 更新）

以上“核对时现状”保留为视频分析完成时的源码快照。后续客户已经明确确认：正装时正面大孔 6 mm，背面小孔 4 mm；数量限定 2、3、4、5 四档。实现采用产品正面为世界坐标 −Y，背面为 +Y。这里的客户确认来自后续直接沟通，不是视频自动语音识别结果。

源码现已实现：

- `installHoleCountPerSide` 为 JSON 数字枚举 2、3、4、5，默认值数字 3。模板规划与动态示意均拒绝 6 及更多组数。
- `installHoleOrientation` 为 `side/front` 枚举，默认侧装，仅在开启安装孔时显示于装配区；修改方向只使零件清单过期。开关、孔数、上下端距仍为创建后可改的布局值，改变后须重新生成显示基准。
- 侧装沿 X：朝网内大孔、朝左右墙体小孔。正装沿 Y：−Y 正面大孔、+Y 背面小孔。两孔各切自身一层管壁，不以大孔贯穿两壁。
- 正装使用真实前后壁的平直区域与壁厚，检查孔边余料及穿管螺丝路径是否被公头阻挡。方向不会改变构件端点、长度或数量。

最终只读审查确认，正常界面链路的孔位与加工参数更新一致：

1. 前端及原生都依据模板 `manufacturingOnly` 声明区分模型与零件过期。安装开关、组数、端距没有被排除出显示参数，未经重新生成不能拆单。
2. 单独把侧装改成正装时，杆件形状和孔中心位置不变，因此保留显示模型合理。拆单界面先等待参数提交，再通过 `productParametersByEntityId` 提交最新完整值。
3. `template.py:manufacturing()` 每次用当前参数调用 `layout()` 重建孔位规划，不读取显示模型中旧的安装孔 facts；旧显示模型用于冻结相同的实物管材基准。
4. 动态示意在全部杆件计算完成后单独绘制孔位点，安装孔开关、数量和方向不参与杆件分段。数量是数字枚举，显示条件仅比较 `installHoleEnabled == "yes"`，不存在数量数字与字符串混用。

审查另发现一项已有接口边界：直接调用原生 `DisassembleSelected` 时，如果前一步已经保存了新方向，却省略 `productParametersByEntityId`，当前无更新载荷分支会使用已提交的显示/制造快照参数。正常界面会携带最新完整参数，不走该路径；主任务验收脚本需要核对其调用方式。此轮审查没有修改该原生接口行为。
