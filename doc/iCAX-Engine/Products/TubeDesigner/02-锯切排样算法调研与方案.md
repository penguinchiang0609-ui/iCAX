# TubeDesigner 锯切排样算法调研与方案

## 1. 结论

TubeDesigner 首版排样不应从完整三维套料做起，而应把拆单生成的制造零件转成“带端面状态的一维锯切问题”。绝大部分零件由锯切得到毛坯，再由冲床加工孔槽；孔槽不改变母材占用长度，只作为后续工艺数据随零件传递。

推荐方案为 `SawNest v1`：按材料与截面分组，联合选择原材/余料、零件顺序、正反向和离散绕轴姿态；大规模使用多起点构造、局部搜索与大邻域重排，小规模继续做有界精确搜索。目标采用严格字典序，优先保证材料成本和标准料根数，再优化不可回收损耗、开料根数、余料段数、切割次数和订单切换。

当前实现位于 `iCAX-Engine/foundation/TubeNesting`，不依赖 CAD 内核和外部整数规划器。它是排样决策内核，不替代 TubeOne 对真实几何、夹具、刀具可达性、碰撞和 NC 顺序的复核。

### 2.2 常见算法路线

| 路线 | 优点 | 局限 | 本项目用法 |
| --- | --- | --- | --- |
| FFD/BFD 等贪心 | 极快、易解释 | 容易被零件顺序和局部选择卡住 | 用作构造初解，但不能单独作为最终算法 |
| 动态规划/背包 | 单根料或单个切割模式可做得很准 | 多原材、有限库存、相邻端面和姿态会扩大状态 | 后续可用于列生成的定价子问题 |
| 整数规划、列生成、Branch-and-Price | 一维切割库存的经典精确路线，可给下界和最优性证明 | 相邻端面、正反向、订单约束和余料价值会让定价问题复杂；引入求解器也增加部署成本 | 作为超大批次与离线最优模式的二阶段方向 |
| 遗传、退火、禁忌、蚁群 | 容易塞入复杂业务约束，随时间改善 | 参数敏感，难以证明最优，结果稳定性要专门控制 | 首版选择更可控的确定性局部搜索和 LNS |
| 2D/3D NFP、网格或碰撞搜索 | 可处理板材、支管相贯和完整激光切管 | 对“锯切毛坯 + 冲床”首版过重 | 留给 TubeOne 的真实几何与机床验证 |

经典切割库存研究证明了列生成与分支定界的价值；近期多规格管材研究也继续采用列生成。与此同时，带斜端面的 bar nesting 已出现针对端面方向、非对称截面的精确算法研究，说明端面状态不能简单折成一个固定件间距。

- [Brandão、Pedroso：等价于 Gilmore-Gomory 松弛的压缩 Arc-flow](https://arxiv.org/abs/1310.6887)
- [Wei 等：Cutting Stock 的 Branch-Cut-and-Price 与安全下界](https://arxiv.org/abs/2308.03595)
- [Vance 等：整数切割库存的 Branch-and-Price](https://onlinelibrary.wiley.com/doi/abs/10.1111/j.1475-3995.1998.tb00100.x)
- [Scientific Reports：多规格管材切割与列生成](https://www.nature.com/articles/s41598-026-43977-9)
- [Lewis、Bonnet：带斜端面的 bar nesting 精确算法（2025）](https://orca.cardiff.ac.uk/id/eprint/175006/)

Lewis、Bonnet 的结果与本项目尤其贴合。对同高梯形，零件 `i` 可写成中心长度 `ci` 和左右投影 `xi/yi`。当截面允许翻转、相邻斜面允许嵌套时，固定一组零件在单根母材中的最优排法可转成 Pair Sequencing Problem，相邻代价为 `|x-y|`；改进的 Euler-Splice 能在 `O(n²)` 时间精确求解。论文还覆盖不允许左右翻转、非对称截面和不同切割平面的扩展。它适合作为多根母材搜索中的“单根精确子程序”，而不是把斜切继续简化为固定包围长度。

## 3. TubeDesigner 场景建模

### 3.1 输入来源

`CManufacturingPartComponent` 已有 `ProductID`、`SourceMemberID`、`GenerationRunID`、`PartNumber`、`Quantity`、`Length`、制造几何资源和 `ItemProperties`。模板还会写入：

- `tubeDesigner.profile`：材料、截面和规格；
- `tubeDesigner.endProcess.startCut/endCut`：如 `square`、`miter-45`；
- `manufacturing.lengthAxis`：零件局部长度轴；
- 产品、角色、类别和孔槽等后续制造信息。

首版适配层应使用稳定实体 ID 作为 `PartDemand.ID`，使用产品或订单号作为 `OrderKey`，使用“材料牌号 + 截面定义 + 壁厚 + 表面状态 + 工艺公差等级”的稳定摘要作为 `CompatibilityKey`。不要只使用界面显示名称分组。

### 3.2 端面和姿态

每个制造零件枚举有限个允许姿态：原向/反向，以及截面允许时的 0°、90°、180°、270°绕轴旋转。每个姿态包含轴向包络长度和左右端描述。

端面规范签名建议包含：

```text
saw-plane/v1 | profile-hash | quantized-normal | axial-direction | rotation-class | tolerance-class
```

两个相邻端面只有在双方都允许共刀且规范签名完全相同的情况下，才能用同一刀分离。这里比较的是同一世界排样姿态下的切割平面，而不是模板中的字符串是否相同。

### 3.3 非严格斜截断的安全近似

对弧口、局部缺口或轻微非平面端部，首版允许近似成斜截断，但必须遵循“只多留料、不少料”：

1. 沿制造零件长度轴，对端部边界/保留实体采样；
2. 在截面局部坐标中拟合平面 `x = a*y + b*z + c`，可用稳健最小二乘或 RANSAC 排除孔边等离群点；
3. 根据起始端或结束端的保留方向，把拟合面向外平移，直至所有应保留点都位于毛坯侧；
4. 再叠加锯切、焊接或二次精加工余量；
5. 将外移后的轴向包络计入 `AxialLength`，将残差安全量计入 `SeparationAllowance`；
6. 将斜率、方位角和绕轴姿态按设备角度分辨率量化，生成端面签名。

若最大包络误差超过工艺阈值、等效角超出锯床能力、截面不允许该绕轴姿态，或近似后会破坏成品实体，则该端禁止共刀，使用独立两刀并标记人工/TubeOne 复核。该近似只定义下料毛坯，不表示一刀锯切已经完成最终端部几何。

### 3.4 单根原材占用

设某根原材中的有序零件姿态为 `v1...vn`，前端固定损耗为 `front`，尾部夹持死区为 `dead`，最终分离刀锯缝为 `kerf`：

```text
processed = front + Σ axialLength(vi) + finalKerf + Σ transition(vi, vi+1)
processed <= stockLength - dead
```

相邻过渡为：

```text
同一切割平面：kerf
不同切割平面：2 * kerf + partGap + rightAllowance(vi) + leftAllowance(vi+1)
```

最后一件仍需一次分离锯切。前端若不需要修齐可把 `front` 设为 0；若设备要求首刀修齐，则把该损耗和刀数显式传入适配层。

## 4. SawNest v1 求解流程

1. 校验并量化输入，推荐长度单位 `0.01 mm`；展开需求数量，生成稳定实例 ID。
2. 按 `CompatibilityKey` 拆成完全独立的组，拒绝跨材料或跨截面混排。
3. 为每组计算“最长件可放入何种原材”、总净长下界和成本下界，提前诊断超长件。
4. 用多种排序和固定随机种子执行多起点最佳插入；每次插入同时尝试原材、余料、位置和姿态。
5. 对候选方案做同根换向、重排、跨根移动、交换和小块拆解重插。
6. 对小组执行有节点上限的完整分支搜索；搜索闭合才返回 `Optimal`，否则只返回 `Feasible`。
7. 输出每根原材的零件顺序、坐标、姿态、共刀关系、切数、损耗和可回库余料。
8. 进入 TubeOne 前用实际 BRep 和机床配置复核，失败项禁止直接生成 NC，可退回禁用某姿态/共刀后重排。

### 4.1 目标函数

默认严格字典序如下：

1. 原材成本；
2. 新开标准料根数；
3. 不可回收损耗；
4. 总开料根数；
5. 可回收余料段数；
6. 锯切次数；
7. 订单切换次数。

余料的默认采购成本可为 0，但生产环境应给余料设置机会成本、库龄或清库权重，避免算法为了账面“零成本”制造不合理的碎片化作业。利用率只作结果指标，不应覆盖“少开新料、保住可复用余料”的业务优先级。

### 4.2 可重复性和可解释性

- 所有随机过程使用输入固定种子；同一输入、配置和算法版本必须得到同一结果。
- 每个未排入实例返回明确原因：无兼容原材、单件超长、库存不足、夹持死区冲突或约束上限。
- 每个共刀点保留端面签名和所选姿态；不能只返回坐标。
- 计划需保存输入摘要、算法版本、目标配置和求解状态，后续才能复现。

## 5. 当前代码落点

`TubeNesting` 静态库已经实现以下接口和行为：

- `PartDemand / PartVariant / EndDescriptor`：零件、姿态和端面状态；
- `StockType`：标准料、有限余料、成本、前余量、尾死区和回库阈值；
- `SolverSettings`：锯缝、件间距、搜索预算和目标顺序；
- `StockPlan / Placement / ResultMetrics`：可直接供后端保存及前端绘制的一维计划；
- 多起点最佳插入、姿态/顺序局部优化、大邻域重排和小组精确搜索；
- 对顺序无关的直切组增加整根切割模式构造：使用位集型 0/1 背包找高密度单根模式，并从填充率、余量、成本效率和件数四个方向构造完整候选，避免逐件贪心被短料局部成本卡住；
- 对一根母材中不超过 16 件的端面/姿态组合增加 Held-Karp 型精确排序，在全局启发式完成后同时纠正零件顺序和翻转姿态；
- 严格输入校验、未排入件和诊断信息。

TubeDesigner 适配层和 `TubeDesigner.Nest` 已接通，但目前生产调用只传最终 BRep 的轴向包络，并把所有端面标记为禁止共切。因此，上述直切模式优化已经能作用于产品；斜切精确排序虽然内核已经具备，尚未拿到真实端面投影，当前产品结果仍属于保守包络排样。下一步不能只解析 `miter-45` 字符串就宣布套切：必须从 BRep、长度轴和截面坐标中提取左右投影、切割平面、允许翻转/绕轴姿态及安全余量，再进入梯形算法。

### 5.1 本轮回归样例

- 多规格直切陷阱：`12 × 5000`，候选母材为 `6000` 和 `15000`，关闭全局精确搜索后，整根模式优化得到 `4 × 15000`；旧逐件策略会得到 `12 × 6000`。总投料从 `72000` 降到 `60000`。
- 斜端姿态陷阱：构造阶段故意选择字典序更靠前但不能共切的姿态，关闭局部搜索和全局精确搜索后，单根精确排序仍能换成匹配斜面并恢复共切。
- 交互规模烟测：82 个不同长度的直切件、单一 6000 定尺料，Release 下连续两次确定性求解共约 2.4 秒；该数据只用于防止算法级性能回退，不代表真实客户订单成绩。

## 6. 验收与基准

首版上线前至少覆盖：

- 方切连续共刀、45°斜切正反向匹配、禁止共刀端；
- 标准料与有限余料同时存在，余料优先且不超库存；
- 前余量、尾部死区、最小回库长度和最后一刀；
- 多材料/多截面绝不混排；
- 超长件、无库存和非法负参数给出稳定诊断；
- 小规模随机实例与穷举结果逐项对拍；
- 大批次固定数据集记录材料成本、根数、损耗、刀数、运行时间和重复性。

建议性能基线：单兼容组 1,000 件在普通工作站数秒内给出稳定可用解；10 件以内在默认节点预算内尽量闭合精确搜索。实际阈值应以客户订单分布和机床约束回放确定，不硬编码为产品承诺。

“行业领先”必须用可复现基准定义，不能只比较界面上的利用率。每个基准同时记录：

1. 主目标与理论下界的差距，包括母材成本、标准料根数和不可回收损耗；
2. 毛利用率、扣除可回库余料后的净材料收益率，以及共切节省；
3. 首个可行解时间、限定时间内最佳解时间、总运行时间和峰值内存；
4. 真实几何复核失败率、机床姿态/夹持失败率和重排次数；
5. 与当前版本、商业软件导出结果和人工优秀方案的同订单盲测。

建议建立三层数据集：可穷举的小实例用于证明正确性；OR-Library/公开 Cutting Stock 实例用于直切横向对比；脱敏真实订单用于端面、库存、锁定母材和机床约束回放。只有在代表性真实订单上长期稳定优于对照，且最优差距可解释，才对外使用“领先”表述。

## 7. 后续演进

1. `v1.1`：输出直切组的体积/长度下界、整数下界和 incumbent gap；用聚合需求的 bounded knapsack 进一步降低大量重复件的运行时间。
2. `v1.2`：从制造 BRep 提取梯形 `centralLength/leftProjection/rightProjection`，先对单根母材接入 PSP/OPSP 精确求解，并用论文示例和几何碰撞对拍。
3. `v1.3`：把梯形单根精确子程序嵌入多根构造、交换、LNS 和锁定重排；增加锯床角度范围、翻料次数、夹钳位置和工时估算。
4. `v2`：直切采用 Arc-flow 或列生成主问题，并用 Branch-Cut-and-Price 在限定时间内持续缩小可证明最优差距；斜切定价子问题使用 PSP/OPSP，而不是普通背包。
5. `v3`：TubeOne 用真实几何、夹具与机床做验证，并把不可行姿态作为割平面反馈给排样器重算。
6. 只有当订单中非锯切毛坯占比足够高时，再引入完整三维管材套料；不要让少数复杂件拖重绝大多数锯切件的主流程。
