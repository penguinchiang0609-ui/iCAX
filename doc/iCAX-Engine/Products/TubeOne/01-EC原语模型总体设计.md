# TubeOne EC 原语模型总体设计

> 状态：设计基线，先完成文档，再进入组件和系统实现。
>
> 本文定义 TubeOne 的三层权威模型：CAD 原语、制造目标原语、Toolpath CAM 原语。三层均使用 Entity-Component 表达，不建立 `PartCadDocument`、`ManufacturingDocument` 或 `ToolpathDocument` 之类的中心化领域对象。
>
> CAD/CSG 的 Component 契约、导入识别和 BRep 缓存策略以《02-CAD与CSG原语EC详细设计》为准；完整求值 BRep 默认属于本机派生缓存，不进入项目权威保存。

## 1. 目标

TubeOne 要把管材零件转换为制造端能够理解、编辑和编译的中性模型。模型必须支持：

- 任意二维外轮廓和任意数量腔体的等截面拉伸主体。
- 参数化编辑主体、外轮廓和每一个腔体。
- 平铺、可排序、可单独编辑的几何刀具。
- 贯穿、盲、气泡、截断、锥形生成体、局部或整圈变坡、UV 法向体和复合几何兜底。
- 从 BRep 识别多个等价解释，并允许人工选择。
- CAD 修改后制造目标自动跟随，无法可靠跟随时明确进入复核或失联状态。
- 同一几何目标可以匹配激光、钻削、铣削、划线等不同加工策略。
- 排样后根据工件实例、设备、装夹和可达性生成实际 Toolpath。
- View 根据 Component 的增删自动维护成员，前端不维护第二份业务状态。

本文只定义领域数据和更新边界，不定义具体识别算法、刀路算法和 UI 样式。

## 2. 三层原语与单向依赖

```text
CAD Primitive Entity
    描述材料和几何是怎样构造出来的
              |
              v
Manufacturing Target Entity
    描述最终需要实现哪些几何结果和质量要求
              |
              v
CAM Operation / Toolpath Entity
    描述某个排样实例本次实际采用的加工方案和运动路径
```

依赖只能向下：

- CAD 原语不知道激光、钻头、铣刀或打标。
- 制造目标可以保存允许策略、偏好和约束，但不保存本次实际刀路。
- CAM 原语引用制造目标和排样实例，不反向修改 CAD 原语。
- Toolpath 是派生结果；不能作为 CAD 或制造目标的权威来源。

## 3. EC 设计硬约束

### 3.1 Entity 是稳定身份

工件、主体、外轮廓、每个腔体、每个几何刀具、每个语义结果区域、每个制造目标、每个 CAM Operation 和每条 Toolpath 都是 Entity。

Entity ID 必须随保存、打开、撤销、重做和参数重算保持稳定。不得使用 OCC Shape 指针、Face 枚举序号、数组下标或几何哈希代替 Entity ID。

### 3.2 Component 组合决定含义

不得使用一个大型 `Kind` 字段和巨型 `variant` 让所有 System 做集中分派。例如不得设计：

```text
CadNodeComponent.Kind = Extrusion | Cone | HalfSpace | ...
ManufacturingTarget.Kind = Cut | Mark | Drill
Toolpath.Kind = Cut | Drill | Mark
```

正确方式是组合正交 Component：

```text
Entity
  CCadOperatorComponent
  CSubtractMaterialComponent
  CExtrudedRegionComponent
  CThroughExtentComponent
```

组件类型表达能力，Component 字段表达参数。

### 3.3 关系也必须是 EC 可查询数据

- 不定义通用 `COwnedByComponent` 或通用领域父子组件。
- 关系属于哪个业务切面，就在该切面的 Component 中保存语义明确的 UUID 字段。
- 空间父子关系由现有 `CTransformComponent.ParentEntityID/ChildEntityIDs` 表达。
- Workpiece、生成原语、候选、来源和目标关系分别由对应业务 Component 表达。
- 需要重复或多对多的关系可以使用专门的 Relation Entity，但不能退化成通用 Owner/RoleKey 关系。
- 所有引用必须能够被 `EntityWhere.Reference` 追踪。

### 3.4 Resource 只承载重数据

BRep、二维/三维曲线、网格、图片、姿态场、事件场和轴轨迹进入 Scene Resources。业务语义、身份、引用、状态、顺序和修订必须留在 Entity/Component 中。

Component 持久化 `ResourceID`；View 输出时由资源接口把它解析成前端可读取的 URL。前端始终依据 URL 从资源池取几何并自行渲染，但 HTTP URL 不是领域身份，也不持久化进 CAD 关系。

旧的 `tube.neutral_geometry` 可以保留为交换快照或兼容格式，但不能继续作为 TubeOne 的权威可编辑模型。

### 3.5 View 不是持久化归属

EntityView 只声明“当前哪些 Entity 满足条件”。产品 View 可以组合多个 EntityView，但不拥有独立 Context 或邮件通道。Scene 才拥有 Repository、Resources、Context 和 Scene Channel。

## 4. Scene 边界

### 4.1 主 Scene

主 Scene 保存已经提交的：

- Workpiece Entity。
- CAD 原语 Entity。
- CAD 派生结果 Entity。
- 制造目标 Entity。
- 排样及 Workpiece Instance Entity。
- CAM Operation 和 Toolpath Entity。

### 4.2 CAD 编辑 Scene

打开“某某零件编辑视图”时创建独立的 Transient Scene：

- 从主 Scene 复制当前工件相关 Entity，保留原 Entity ID。
- 新建原语时立即生成最终可持久化的 Entity ID。
- 参数修改只影响编辑 Scene。
- 选中刀具时由预览 System 实时重建刀具灵体。
- 点击“应用”才执行主体和全部有效刀具的布尔重建。
- 点击“提交”才将 Entity 差异和新资源原子写回主 Scene。
- 点击“取消”直接销毁编辑 Scene。

View 不创建自己的 Scene；CAD 编辑窗口自身就是独立 Scene 的前端 View。

## 5. 通用 Component

下列 Component 被三层原语复用。

### 5.1 名称与顺序

```cpp
CDisplayNameComponent {
    string Name;
}

COrderComponent {
    long long OrderKey;
}
```

`OrderKey` 只表达编辑或展示顺序。CAD 刀具顺序不是实际加工顺序。

### 5.2 修订

```cpp
CRevisionComponent {
    uint64 Revision;
}

CSourceRevisionComponent {
    uuid SourceEntityID;
    uint64 SourceRevision;
}
```

参数修改后 Entity ID 不变，Revision 递增。

### 5.3 参数可观测性

```cpp
CParameterObservabilityComponent {
    string Observability; // Observed / Reconstructed / Underconstrained
    string ParameterReportResourceID;
}
```

识别出来但无法唯一确定的参数不能伪装成确定设计意图。

### 5.4 生命周期状态

状态采用正交 marker Component，不把所有状态揉成一个字符串：

```text
CCurrentComponent
CDisabledComponent
CNeedsRebuildComponent
CNeedsReviewComponent
COrphanedComponent
CInvalidComponent
CBlockedComponent
```

这些状态可以按不同状态轴组合。例如 Toolpath 可以同时具有 `CNeedsRebuildComponent` 和 `CBlockedComponent`。

## 6. 第一层：CAD 原语

### 6.1 Workpiece Entity

Workpiece 是产品中的工件身份，不是 CAD 文档容器。

```cpp
Entity Workpiece
  CWorkpieceComponent {
      string Name;
      uint64 Quantity;
  }
  CRevisionComponent
  CCadStateSummaryComponent {
      uint64 CadRevision;
      string EvaluationState;
  }
  CSectionMetadataComponent {
      string MatchedSectionDefinitionID;
      ObjectMap DisplayDimensions;
      double Length;
  }
```

`CSectionMetadataComponent` 是导入列表需要的摘要，不是主体截面的权威几何。

完整 BRep、Topology 和 Render Mesh 由派生 `GeometryEvaluation Entity` 在运行期或本机缓存中表达，不作为 Workpiece 的权威持久化字段。

### 6.2 主体 Entity

每个工件当前只有一个主体 Entity：

```cpp
Entity Body
  CCadBodyPrimitiveComponent {
      uuid WorkpieceEntityID;
  }
  CTransformComponent
  CExtrusionFrameComponent {
      Placement3 Frame;       // 拉伸方向标准化为 Y
      double First;
      double Last;
  }
  CRevisionComponent
```

主体由外轮廓和全部腔体共同求值：

```text
Body = Extrude(OuterProfile - Union(CavityProfiles), First, Last)
```

主体 Entity 不保存通用子 Entity 数组。System 通过 `CSectionProfilePrimitiveComponent.RegionGeneratorEntityID == Body` 查询截面原语；空间父子关系只由 Transform Component 表达。

### 6.3 截面原语 Entity

外轮廓和每个腔体必须可以独立选择和编辑，所以各自使用一个 Entity。

外轮廓：

```cpp
Entity OuterProfile
  CSectionProfilePrimitiveComponent {
      uuid RegionGeneratorEntityID;
      string ExactCurveResourceID;
  }
  COuterProfileComponent
  COrderComponent
  CRevisionComponent
```

腔体：

```cpp
Entity CavityProfile
  CSectionProfilePrimitiveComponent {
      uuid RegionGeneratorEntityID;
      string ExactCurveResourceID;
  }
  CCavityProfileComponent
  COrderComponent
  CRevisionComponent
```

参数化解释通过附加 Component 表达：

```text
CCircleProfileComponent      { Center, Radius }
CRectangleProfileComponent   { Center, Width, Height, Rotation }
CCurveLoopProfileComponent   { ExactCurveResourceID }
```

系统不得按“圆管、方管、工字钢、多腔管”分支。管型名称只来自可配置截面匹配规则。

### 6.4 几何刀具 Entity

所有几何刀具平铺在 Workpiece 下：

```cpp
Entity CadOperator
  CCadOperatorComponent {
      uuid WorkpieceEntityID;
      bool Enabled;
  }
  COrderComponent
  CRevisionComponent
```

材料作用使用互斥能力 Component：

```text
CSubtractMaterialComponent
CAddMaterialComponent
CSurfaceImprintOperatorComponent
```

这里的“刀具”是 CAD 布尔生成体，不是机床上的物理刀具。

`CadPrimitiveEvaluationSystem` 查询 Body 和全部启用刀具，按 `COrderComponent` 临时编译求值表达式：

```text
P0 = Evaluate(Body)
Pi = Apply(Pi-1, CadOperator[i])
FinalPart = Pn
```

临时表达式可以使用 CSG 求值，但不持久化一棵重复的 CSG 树。

### 6.5 三维生成原语 Component

一个实体生成刀具必须附加一个权威生成 Component：

```cpp
CExtrudedRegionComponent {
    string SectionRegionResourceID;
    Placement3 Frame;
    double First;
    double Last;
}

CTaperedRegionComponent {
    string SectionRegionResourceID;
    Placement3 Frame;
    double First;
    double Last;
    double Reference;
    Point2 ScaleCenter;
    double FirstScale;
    double LastScale;
}

CHalfSpaceComponent {
    Plane3 Boundary;
    bool KeepNegativeSide;
}

CWrappedVolumeComponent {
    uuid SupportProfileEntityID;
    string UVRegionResourceID;
    string LowerOffsetFieldResourceID;
    string UpperOffsetFieldResourceID;
}

COpeningProfileSweepComponent {
    uuid SourceOperatorEntityID;
    uuid TargetOpeningEntityID;
    string ProfileFieldResourceID;
    string EvaluatedVolumeResourceID;
}

CCompositeVolumeComponent {
    string ExactBRepResourceID;
    string AnalyticPatchResourceID;
}

CResidualBRepComponent {
    string ExactBRepResourceID;
}

CUVVectorGeometryComponent {
    uuid SupportProfileEntityID;
    string UVGeometryResourceID;
}

CUVImageGeometryComponent {
    uuid SupportProfileEntityID;
    string ImageResourceID;
    string UVPlacementResourceID;
}
```

固定方向拉伸体、共同有限锥心生成体、半空间、稳定 Side Atlas 上的法向体和坡口剖面扫掠由不同 Component 表达，不依赖 OCC 的曲面类型名称。

### 6.6 构造范围与材料关系

贯穿、盲和气泡是几何穿越事实，不是加工方式：

```text
CThroughExtentComponent
CBlindExtentComponent
CBubbleExtentComponent
CUnresolvedExtentComponent
```

动态范围约束继续使用 Component 组合，不使用 `Rule` 字段分派：

```cpp
CFixedExtentConstraintComponent {
    double First;
    double Last;
}

CThroughHostExtentConstraintComponent {
    uuid HostBodyEntityID;
    string WitnessResourceID;
}

CThroughSelectedBoundariesConstraintComponent {
    uuid HostBodyEntityID;
}

CBlindFromBoundaryConstraintComponent {
    uuid HostBodyEntityID;
    uuid OpeningEntityID;
    string TerminationConstraintResourceID;
}
```

选择多条宿主边界时，每一条边界引用使用专门的 BoundaryConstraint Relation Entity，避免使用通用依赖关系或不可观察的 Entity ID 数组。

### 6.7 CAD 依赖

CAD 构造依赖直接位于产生该关系的业务 Component：

```text
CThroughHostExtentConstraintComponent.HostBodyEntityID
CBlindFromBoundaryConstraintComponent.OpeningEntityID
CWrappedVolumeComponent.SupportSideAtlasEntityID
COpeningProfileSweepComponent.SourceOpeningEntityID
CTransformComponent.ParentEntityID / ChildEntityIDs
```

依赖校验 System 从这些明确字段建立 DAG，不解析通用 Owner 或 RoleKey。

“截断”和“开口坡口”是生成体相对母材的几何角色：

```cpp
CPenetrationRelationComponent      { uuid HostBodyEntityID; }
CTruncationRelationComponent       { uuid HostBodyEntityID; }
CBoundaryProfileModifierComponent  { uuid SourceOpeningEntityID; }
```

它们不能取代 `CHalfSpaceComponent`、`CExtrudedRegionComponent` 等权威几何生成 Component。

### 6.8 MaterialSpan Entity

同一个生成体在多腔材料中可能穿过多段不连续材料，每一段使用独立 Entity：

```cpp
Entity MaterialSpan
  CMaterialSpanComponent {
      uuid HostBodyEntityID;
      uuid SourceOperatorEntityID;
      uint32 TravelOrdinal;
      string EndpointResourceID;
  }
  CRevisionComponent
```

多个 MaterialSpan 不会把一个支管生成体强制拆成多个刀具。

### 6.9 Opening Entity

刀具在母材边界形成的稳定开口使用 Entity 表达：

```cpp
Entity FeatureOpening
  CFeatureOpeningComponent {
      uuid SourceOperatorEntityID;
      uuid HostBodyEntityID;
      string OpeningRoleKey;
      string BoundaryWitnessResourceID;
  }
  CRevisionComponent
```

坡口刀具依赖 Opening Entity，而不是依赖易变的 OCC Edge 或 Face。

### 6.10 多解释候选

同一局部几何存在多种等价构造解释时，使用候选 Entity，不使用 `variant` 数组：

```cpp
Entity AlternativeGroup
  CAlternativeGroupComponent {
      uuid WorkpieceEntityID;
  }
  CRecommendedCandidateComponent { uuid CandidateEntityID; }
  CSelectedCandidateComponent    { uuid CandidateEntityID; } // 可缺失

Entity InterpretationCandidate
  CInterpretationCandidateComponent {
      uuid AlternativeGroupEntityID;
      uuid CandidateRootEntityID;
      bool Optional;
      string EvaluationResourceID;
      string EvidenceResourceID;
  }
  COrderComponent
```

推荐候选不等于选定候选。未选择时，依赖该解释的制造目标进入 `CNeedsReviewComponent`。

### 6.11 CAD 派生结果 Entity

布尔求值后产生的语义边界不是 CAD 原语，但必须成为可引用的 Entity：

```cpp
Entity ResultBoundary
  CCadResultBoundaryComponent {
      uuid WorkpieceEntityID;
      uuid GeneratorEntityID;
      string RoleKey;
      uint64 GeometryRevision;
  }
  CBoundaryGeometryComponent {
      string SurfaceResourceID;
      string FragmentMappingResourceID;
  }
```

一条 ResultBoundary Entity 可以映射当前 BRep 中多个碎面。碎面拆分但制造语义不变时，Entity ID 不变，只更新 Fragment Mapping。

不得命名为 `CutFace`，因为它没有说明使用何种加工方式。

## 7. 第二层：制造目标原语

### 7.1 定位

制造目标表达“最终要实现哪些几何结果以及有什么要求”，不表达“CAD 是怎样构造的”，也不声称“本次一定用什么机器加工”。

因此不存在：

```text
CutTarget
DrillTarget
MillTarget
MarkTarget
```

浅文字凹槽、圆柱孔、铣出的平面和激光形成的轮廓，在这一层都只是目标几何及其质量要求。

### 7.2 ManufacturingTarget Entity

```cpp
Entity ManufacturingTarget
  CManufacturingTargetComponent {
      uuid WorkpieceEntityID;
      bool Enabled;
  }
  CRevisionComponent
```

目标几何来源使用选择器 Component。

### 7.3 动态刀具输出选择器

默认目标应绑定“某个 CAD 刀具当前产生的全部指定角色输出”：

```cpp
COperatorOutputTargetComponent {
    uuid OperatorEntityID;
    string OutputRolePattern;
}
```

例如：

```text
OperatorEntityID = 支管贯穿体 Entity
OutputRolePattern = generated-boundary/*
```

刀具参数改变、一个结果面裂成多个碎面或多腔材料跨度变化后，该目标仍然自动解析到当前输出。

### 7.4 显式结果成员

用户只选局部结果区域时，使用 Relation Entity：

```cpp
Entity TargetMemberRelation
  CTargetMemberRelationComponent {
      uuid TargetEntityID;
      uuid ResultEntityID;
      string RoleKey;
  }
  COrderComponent
```

同一个目标可以拥有多个成员；一个 ResultBoundary 也可以被多个目标引用。

### 7.5 表面信息目标

零深度 UV 曲线、区域和图片使用：

```cpp
CSurfaceInformationTargetComponent {
    uuid SurfaceImprintOperatorEntityID;
}
```

它只说明表面信息需要被实现。后续可以匹配激光标记、机械划线、喷印或其他策略。

如果文字是通过浅层减料或去除周围材料留下凸字，它必须使用实体减材 CAD 刀具及 ResultBoundary 目标，不能伪装成表面标记。

### 7.6 质量与约束 Component

要求按能力正交挂接：

```text
CDimensionalToleranceComponent
CSurfaceQualityRequirementComponent
CEdgeQualityRequirementComponent
CProtectedRegionComponent
CAllowedDirectionComponent
CCompletionRequirementComponent
```

不需要某项要求的 Target 不挂该 Component。

### 7.7 策略候选 Entity

工件层的自动匹配只产生候选，不从几何声称工艺事实：

```cpp
Entity ProcessCandidate
  CProcessCandidateComponent {
      uuid TargetEntityID;
      uuid StrategyDefinitionEntityID;
      string MatchingRuleID;
      long long RulePriority;
  }
  CCompatibleCandidateComponent
    // 或 CRejectedCandidateComponent { reason }
  COrderComponent
```

候选按配置规则顺序匹配，不使用虚假的几何“可信度”决定加工方式。

策略选择政策使用 Component 组合：

```text
CAutomaticStrategyPolicyComponent
CPreferredStrategyPolicyComponent { StrategyDefinitionEntityID }
CLockedStrategyPolicyComponent    { StrategyDefinitionEntityID }
```

三者互斥。`Locked` 只表示用户或模板的约束；最终仍必须在排样实例上验证可执行性。

### 7.8 策略定义 Entity

可匹配的加工策略本身也必须 Entity 化，不能只藏在字符串注册表中：

```cpp
Entity ProcessStrategyDefinition
  CProcessStrategyDefinitionComponent {
      string Name;
      uint64 SchemaRevision;
  }
  CStrategyParameterSchemaComponent {
      string ParameterSchemaResourceID;
  }
```

策略能力继续通过 Component 组合：

```text
CLaserContourCapabilityComponent
CDrillingCycleCapabilityComponent
CHelicalMillingCapabilityComponent
CEngravingCapabilityComponent
CSurfaceMarkingCapabilityComponent
```

`ProcessCandidate`、Preferred/Locked Policy 和 CAM Operation 都引用 Strategy Definition Entity ID。策略定义可以由产品、设备插件或用户配置创建。

## 8. 第三层：Toolpath CAM 原语

### 8.1 两级 Entity

CAM 层分为：

- CAM Operation Entity：本次排样实例上已经解析的加工方案。
- Toolpath Entity：Operation 产生的实际名义运动路径。

制造目标不能直接保存 Toolpath，因为同一工件的不同排样实例可以采用不同设备、策略和路径。

### 8.2 WorkpieceInstance Entity

```cpp
Entity WorkpieceInstance
  CWorkpieceInstanceComponent {
      uuid WorkpieceEntityID;
      uuid NestResultEntityID;
      uint64 InstanceOrdinal;
  }
  CTransformComponent
  CRevisionComponent
```

CAD 始终保持工件局部坐标；实例 Transform 只存在于排样和 CAM 层。

### 8.3 CAM Operation Entity

```cpp
Entity CamOperation
  CCamOperationComponent {
      bool Enabled;
  }
  COperationSourceComponent {
      uuid WorkpieceInstanceEntityID;
      uuid ManufacturingTargetEntityID;
      uint64 TargetRevision;
      uint64 GeometryRevision;
  }
  CResolvedStrategyComponent {
      uuid StrategyDefinitionEntityID;
  }
  CRevisionComponent
```

只有这一层可以明确出现实际加工策略 Component，例如：

```text
CLaserContourStrategyComponent
CDrillingCycleStrategyComponent
CHelicalMillingStrategyComponent
CEndMillingStrategyComponent
CLaserMarkingStrategyComponent
CMechanicalScribingStrategyComponent
```

这些 Component 描述“这一次怎么加工”，不是对 CAD 几何的分类。

设备和物理工具同样挂在 Operation：

```cpp
CMachineAssignmentComponent {
    uuid MachineInstanceEntityID;
    uuid HeadEntityID;
}

CPhysicalToolAssignmentComponent {
    uuid PhysicalToolEntityID;
}
```

### 8.4 Toolpath Entity

```cpp
Entity Toolpath
  CToolpathComponent {
      bool Enabled;
  }
  CToolpathOwnerComponent {
      uuid OperationEntityID;
      string OutputRoleKey;
  }
  CToolpathGeometryComponent {
      string CurveResourceID;
      string CoordinateSystemResourceID;
  }
  CToolpathPoseFieldComponent {
      string PoseFieldResourceID;
  }
  CToolpathEventFieldComponent {
      string EventFieldResourceID;
  }
  CSourceRevisionComponent
  COrderComponent
  CRevisionComponent
```

Toolpath Entity ID 不复用 ResultBoundary Entity ID。两者通过 Operation 和来源 Component 关联。

一条 Toolpath 可以由多个目标区域共同生成；这时使用来源 Relation Entity：

```cpp
Entity ToolpathSourceRelation
  CToolpathSourceRelationComponent {
      uuid ToolpathEntityID;
      uuid SourceResultEntityID;
      uint64 SourceResultRevision;
      string MappingRoleKey;
  }
```

### 8.5 可编辑段与采样点

只有能够独立选择、排序、设置工艺或被下游引用的段才创建 Entity：

```cpp
Entity ToolpathSegment
  CToolpathSegmentComponent
  CToolpathOwnerComponent { Toolpath }
  CToolpathGeometryComponent
  COrderComponent
```

插补采样点、姿态采样点和轴位置不能逐点 Entity 化，它们属于 Resource。

### 8.6 轴轨迹和 NC

轴轨迹是 Toolpath 的派生 Component：

```cpp
CAxisTrajectoryComponent {
    uuid MachineInstanceEntityID;
    string TrajectoryResourceID;
}
```

NC 是对有效 CAM Operation 和 Toolpath 的编译输出，不回写 CAD 原语或制造目标。

## 9. 三层之间的引用

```text
CadOperator Entity
   | GeneratedBy
   v
ResultBoundary Entity
   | Target selector / Target member relation
   v
ManufacturingTarget Entity
   | OperationSource + WorkpieceInstance
   v
CamOperation Entity
   | ToolpathOwner
   v
Toolpath Entity
   | optional source relation
   v
ResultBoundary revision snapshot
```

默认使用动态选择器绑定整个 CAD 刀具输出；只有用户明确选择局部时才固化 ResultBoundary 成员。

## 10. 身份、重算和 Lineage

### 10.1 用户创建原语

- 创建命令生成一次稳定 Entity ID。
- 参数编辑、预览、应用、撤销和重做均保留该 ID。
- 删除后撤销恢复原 ID。

### 10.2 系统生成结果

System 使用 `(GeneratorEntityID, OutputRoleKey)` 匹配重算前后的 ResultBoundary、Opening、MaterialSpan 和 Toolpath 输出。

- 角色仍存在：保留 Entity ID，更新 Component 和 Resource。
- 新增角色：创建新 Entity。
- 角色消失：增加 `COrphanedComponent`，完成依赖分析后再决定删除。
- 一个 BRep 面裂成多个碎面：优先保留同一个 ResultBoundary Entity，更新碎面映射。
- 制造语义真正拆成多个独立区域：创建新的结果 Entity，并用 Lineage Relation 表达 Split。

```cpp
Entity LineageRelation
  CLineageRelationComponent {
      uuid PreviousEntityID;
      uuid CurrentEntityID;
  }
  CReplacementLineageComponent
    // 或 CSplitLineageComponent / CMergeLineageComponent
```

### 10.3 STEP 重新识别

初次识别给所有 CAD 原语分配 Entity ID。重新导入时使用构造语义、参数、位置、邻接、材料跨度和几何证据匹配旧 Entity：

- 唯一匹配时转移旧身份。
- 多候选时保留候选 Entity 并增加 `CNeedsReviewComponent`。
- 不得仅凭 BRep Face ID 或几何哈希静默转移身份。

## 11. System 边界

### 11.1 CAD Systems

```text
ExtrusionRecognitionSystem
    BRep -> 主体、截面和初始 CAD 原语 Entity

CadIntentRecognitionSystem
    B、P、B-P 和证据 -> 几何刀具、候选、Span、Opening Entity

CadPrimitiveEvaluationSystem
    BodyView + CadOperatorView -> 临时 CSG -> BRep

CadProvenanceSystem
    OCC 历史 + 几何验证 -> ResultBoundary Entity

CadPreviewSystem
    参数变化 -> 选中原语的实时预览资源
```

导入识别不得依赖已经存在的资源 URL。识别服务接收内存 Shape 或导入会话对象；只有识别成功后才写入资源池并创建正式 Entity。

### 11.2 Manufacturing Systems

```text
ManufacturingTargetDerivationSystem
    CAD 输出 -> 默认制造目标

ManufacturingTargetBindingSystem
    CAD Revision 变化 -> 重解析 Target selector

ProcessMatchingSystem
    Target + 材料 + 策略规则 -> ProcessCandidate Entity
```

“识别”只识别几何；“匹配”才生成加工策略候选。

### 11.3 CAM Systems

```text
OperationResolutionSystem
    WorkpieceInstance + Target + 设备能力 -> CamOperation

ToolpathGenerationSystem
    CamOperation + 当前几何 -> Toolpath

ToolpathPlanningSystem
    装夹、可达性、碰撞、共边、顺序 -> 更新 Toolpath

MotionPlanningSystem
    Toolpath + 机床 -> PoseField / AxisTrajectory

NCCompilationSystem
    有效 Operation + Toolpath -> NC
```

## 12. View 设计

### 12.1 CAD 编辑 View

一个 CAD 编辑产品 View 组合：

```text
BodyEntityView
  HAS CCadBodyPrimitiveComponent

SectionProfileEntityView
  HAS CSectionProfilePrimitiveComponent

CadOperatorEntityView
  HAS CCadOperatorComponent

ResultBoundaryEntityView
  HAS CCadResultBoundaryComponent

AlternativeEntityView
  HAS CAlternativeGroupComponent OR CInterpretationCandidateComponent
```

左侧 CAD 原语树只是这些 EntityView 的分组投影，不是另一棵持久化树。

### 12.2 制造目标 View

```text
ManufacturingTargetEntityView
  HAS CManufacturingTargetComponent

ProcessCandidateEntityView
  HAS CProcessCandidateComponent
```

当系统给一个 Entity 添加 `CManufacturingTargetComponent` 时，它自动进入 View；前端不等待产品私有刷新消息。

### 12.3 CAM View

```text
CamOperationEntityView
  HAS CCamOperationComponent

ToolpathEntityView
  HAS CToolpathComponent

ToolpathSegmentEntityView
  HAS CToolpathSegmentComponent
```

View 可以组合多个 EntityView，但不拥有独立 Context 和 Channel。

## 13. 事务与编辑流程

### 13.1 修改 CAD 参数

```text
1. 在 CAD 编辑 Scene 修改原语 Component
2. CadPreviewSystem 实时重建选中刀具灵体
3. 正式零件仍显示上次 Apply 的结果
4. 点击 Apply
5. 查询 BodyView 和有效 CadOperatorView
6. 按 COrderComponent 编译临时 CSG
7. 重建 BRep、Topology、Render Resource
8. 更新 ResultBoundary、Opening、MaterialSpan Entity
9. 生成 CAD ChangeSet
10. 更新受影响 ManufacturingTarget 状态
```

步骤 7 中新增的权威资源必须先写入成功，Repository Transaction 才能提交新的 ResourceID 和 Revision。完整求值 BRep、Topology 和 Render Mesh 可以在事务成功后写入可重建缓存；任一步骤失败时不留下半套权威 Entity 更新。

### 13.2 提交 CAD 编辑

```text
1. 比较主 Scene 与编辑 Scene 的 Entity/Component 差异
2. 预览制造目标和既有 CAM Operation 的影响
3. 用户确认
4. 必要的权威资源 PUT 完成
5. 在主 Scene 单一 Undo Command 中提交 Entity 差异
6. 标记受影响 Operation/Toolpath 需要重建
7. 关闭编辑 Scene
```

### 13.3 工件层工艺匹配

```text
ManufacturingTarget
  -> 根据规则顺序产生 ProcessCandidate Entity
  -> 用户可保持 Auto、设置 Preferred 或 Locked
```

该步骤可以在排样前完成，并随工件复用。

### 13.4 排样后 CAM 编译

```text
WorkpieceInstance
  + ManufacturingTarget
  + 当前机器、材料、装夹、位置
  -> CamOperation
  -> Toolpath
  -> PoseField / EventField
  -> AxisTrajectory
```

同一 Workpiece 的两个 Instance 可以解析为不同 Strategy，但仍引用同一 ManufacturingTarget。

## 14. CAD 修改后的传播规则

| 变化 | CAD 结果 | 制造目标 | CAM Operation | Toolpath |
|---|---|---|---|---|
| 刀具参数改变、Entity ID 不变 | 重建输出 | 动态选择器自动跟随 | `NeedsRebuild` | `NeedsRebuild` |
| BRep 面碎裂、语义区域不变 | ResultBoundary ID 不变 | 不需要人工处理 | 重新验证 | 重算 |
| 语义区域真正 Split | 新建结果 Entity 和 Lineage | 动态目标自动吸收；显式目标复核 | `NeedsReview` | 阻断旧结果 |
| CAD 刀具被删除 | 输出 Orphaned | Target Orphaned | Blocked | 保留诊断后失效 |
| 候选解释改变 | 重新求值相关原语 | Target 重解析 | `NeedsRebuild` | 重算 |
| 仅改变质量要求 | CAD 不变 | Revision 增加 | `NeedsRebuild` | 重算 |
| 仅改变排样位置 | CAD、Target 不变 | 不变 | 重新验证 | 重算 |
| 工件长度或包围变化 | CAD 重建 | Target 跟随 | 排样先验证或重排 | 阻断至排样有效 |

最差策略是把无法可靠迁移的 ManufacturingTarget 或 CAM Operation 标记为 `NeedsReview`/`Orphaned`，而不是静默绑定到错误几何。

## 15. 典型案例

### 15.1 双腔管上的圆柱贯穿体

```text
Workpiece
  Body
    OuterProfile
    CavityProfile A
    CavityProfile B
  CadOperator H
    SubtractMaterial
    ExtrudedRegion(circle)
    ThroughExtent
  MaterialSpan H-1
  MaterialSpan H-2
  ResultBoundary H/*
  ManufacturingTarget T
    OperatorOutputTarget(H, generated-boundary/*)
```

`H` 仍然是一个 CAD 刀具；多个材料跨度不会把它拆成多个孔。Target `T` 也仍然是一个制造目标。

排样后可以产生：

```text
Instance 1 -> CamOperation(LaserContour) -> Toolpath
Instance 2 -> CamOperation(HelicalMilling) -> Toolpath
```

几何层没有“Drill Hole”。

### 15.2 浅文字与凸字

浅文字凹槽：

```text
CadOperator
  SubtractMaterial
  WrappedVolume 或 ExtrudedRegion
```

制造目标引用其 ResultBoundary。候选可以是激光雕刻或铣削。

零深度文字：

```text
CadOperator
  SurfaceImprintOperator
  UV Vector/Image geometry
```

制造目标使用 `CSurfaceInformationTargetComponent`。候选可以是激光标记、机械划线或喷印。

去除周围材料留下凸字：

```text
CadOperator
  SubtractMaterial
  文字外围浅层减料体
```

凸起文字是保留材料岛，不是 CAD 层的 Mark 类型。

### 15.3 贯穿体加局部变坡

```text
CadOperator A
  SubtractMaterial
  ExtrudedRegion

Opening O
  SourceOperator = A

CadOperator B
  SubtractMaterial
  OpeningProfileSweep
  SourceOperator = A
  TargetOpening = O
```

制造目标可以通过多个 TargetMember Relation 把 A 和 B 的结果组织为一个制造目标，也可以拆成两个目标。该分组是制造要求，不改变两个 CAD 刀具的平级身份。

## 16. 与现有实现的迁移关系

### 16.1 `CTubeNeutralGeometry`

现有嵌套对象迁移为：

| 旧结构 | 新 EC 表达 |
|---|---|
| `BaseNodeID` / `RootNodeID` | Body Entity + CadOperator EntityView；CSG 仅临时编译 |
| `SSolidNode` | CadOperator Entity + 几何 Component 组合 |
| `SSectionPrimitive` | SectionProfile Entity |
| `SFeatureRelations` | 引用 Component 和 Relation Entity |
| `SMaterialSpan` | MaterialSpan Entity |
| `SFeatureOpeningRef` | FeatureOpening Entity |
| `SAlternativeNode` | AlternativeGroup + Candidate Entities |
| `SUVFeature` | SurfaceImprint CadOperator Entity |
| `SurfaceEvidence` | Evidence Relation/Resource |
| `RemovalSemantics` | Through/Blind/Bubble marker Component |

该资源可继续作为识别器输出适配格式，但进入权威模型时必须实体化。

### 16.2 `IntentToolpath`

现有 `CIntentDocumentComponent` 不再作为文档根。现有数据拆分为：

| 旧表达 | 新位置 |
|---|---|
| CAD 来源 | ManufacturingTarget 的 CAD 来源 Relation |
| `CCutIntentComponent` | 删除；不能把 Cut 当制造目标类型 |
| UV Feature 意图 | SurfaceInformation Target |
| 工艺候选 | ProcessCandidate Entity |
| 微联、引入、桥接生成 | CamOperation/Toolpath 衍生 Entity |
| 实际曲线 | Toolpath Geometry Resource |

### 16.3 `CPathComponent`

旧 `PathKind=Cut`、`Operation`、`Source` 字符串字段迁移为正交 Component：

- 通用路径身份进入 `CToolpathComponent`。
- 曲线进入 `CToolpathGeometryComponent`。
- 来源进入 `COperationSourceComponent` 和 Relation Entity。
- 实际加工方式进入具体 Strategy Component。
- 路径顺序进入 `COrderComponent` 或独立排序 Relation。

## 18. 验收标准

### 18.1 数据模型

- 不存在权威 `PartCadDocument`、`ManufacturingDocument` 或 `ToolpathDocument` 大对象。
- 不存在以 `Cut/Mark/Drill/Mill` 区分制造目标的 Kind 字段。
- 主体、外轮廓、每个腔体和每个几何刀具均可独立寻址和编辑。
- 多腔材料中的一个生成体可以拥有多个 MaterialSpan，但保持一个刀具 Entity。
- ResultBoundary Entity 不依赖 OCC Face ID 保持身份。
- 大几何和高密度轨迹全部在 Resources，语义全部在 EC。

### 18.2 编辑

- 修改刀具参数时刀具灵体实时变化，正式零件在 Apply 前不变。
- Apply 失败不修改已提交 BRep、结果 Entity 或制造目标。
- CAD 修改后动态目标能自动跟随同一刀具的新输出。
- 无法唯一迁移时进入 `NeedsReview`，不得静默错绑。

### 18.3 加工

- 同一个圆柱形减料目标可以分别匹配钻削循环、螺旋铣削或激光轮廓。
- 零深度 UV 信息不被提前认定为激光打标。
- 浅层实体减料不被提前认定为标记。
- 工件层保存要求和候选；排样实例层保存最终策略和 Toolpath。
- CAD Revision、Target Revision 或 Nest Transform 变化后，受影响 Toolpath 必须失效并重算。

### 18.4 View 与 Scene

- 给 Entity 添加符合条件的 Component 后，它自动进入相应 EntityView。
- 一个产品 View 可以组合 CAD、制造目标和 CAM 的多个 EntityView。
- View 不创建独立 Context 或邮件通道。
- CAD 编辑使用独立 Transient Scene，取消编辑不污染主 Scene。

## 19. 实施顺序

1. 定义顺序、修订、状态，以及各业务切面自己的明确引用字段。
2. 将主体、截面、腔体和 CAD 刀具实体化。
3. 将现有 `CTubeNeutralGeometry` 识别结果适配为 CAD Entity/Component。
4. 实现临时 CSG 编译、Apply 和 ResultBoundary Entity 追踪。
5. 实现 ManufacturingTarget、动态输出选择器和 CAD 更新绑定。
6. 实现 ProcessCandidate 与工件层工艺编辑。
7. 实现 WorkpieceInstance、CamOperation 和 Toolpath EC 模型。
8. 迁移旧 `IntentToolpath`、`CPathComponent` 和 `ProcessPath` 数据。
9. 接入排样后策略解析、刀路生成、姿态场、轴轨迹和 NC。

这套模型的权威主线是：

```text
Entity 化 CAD 构造
  -> Entity 化制造目标
  -> Entity 化实例加工方案
  -> Entity 化 Toolpath
  -> Resource 化轨迹与几何重数据
```
