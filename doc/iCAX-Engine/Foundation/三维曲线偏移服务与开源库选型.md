# 三维曲线偏移服务与开源库选型

当前状态（2026-10-13）：用户决定暂缓刀补，优先完成其他 CAM 功能。停止本轮刀补选型与接入，保留已有研究和求值原型；不得把受限特例标为通用三维刀补已完成。后续恢复时仍按中性 `IService` 基础能力扩展处理。

此前研究：用户要求优先查找现成的开源三维刀补算法，并作为中性 IService 基础能力扩展。**SISL 已有可直接生成三维偏移 B-spline 的 `s1360`；不能因为它没有覆盖整个五轴工艺链，就说没有现成库。** 当前 OCCT 服务是已验证的求值原型，尚未接入 CAM，不作为最终选型结论。以下记录技术支持范围与许可证接入约束。

## 开源实现核查

| 候选 | 已核实的能力 | 与本需求的差距 | 决策 |
|---|---|---|---|
| OCCT `Geom_OffsetCurve` | 三维源曲线、固定参考方向的局部偏移；原生曲线/曲面微分和求交基础 | 固定参考向量；不自动去除自交；不能单独完成变方向或曲面约束 | 保留已验证求值原型，不提前定为最终后端 |
| SISL `s1360` | 三维 NURBS 曲线偏移并按公差近似为 B-spline | 输入是固定 `norm[3]`；官方明确警告切向与 norm 平行时结果可能失去偏移性质并换侧 | 已本地直接调用验证非共面曲线；AGPL/商业授权单独评估 |
| LNLib `NurbsCurve::Offset` | Tiller–Hanson 与 Piegl–Tiller 两种现成 NURBS 偏移实现 | 源码采用曲线自身法向；接口无刀轴/承载面方向输入，不能直接替代指定刀轴的补偿 | 新增候选；LGPL 2.1；已核查源码，尚未本地运行 |
| GoTools `OffsetCurveNormalDir` | 在曲面上求点并沿曲面法向偏置 | 此类是法向抬高，不是切割边界的横向补偿；源码部分导数未实现，另一分支只在平面下正确 | 不把类名中的 Offset 当作本需求已实现 |
| OpenCAMLib | drop-cutter / push-cutter；圆柱、球、圆角、锥形铣刀等 | 已核实算法针对落刀和等高加工，不直接提供本需求的变方向激光边界补偿 | 本轮不采用 |
| CGAL Straight Skeleton 2 | 平面多边形骨架、偏移轮廓 | 核查的包明确是 2D，不能直接用作空间曲线方向场补偿 | 不采用此包 |

核查来源为上游文档与实现源码，不依据库名称或搜索摘要判断支持：

- [OCCT Geom_OffsetCurve 文档](https://occt3d.com/dev/doc/refman/html/class_geom___offset_curve.html)。本地同版本 `Geom_OffsetCurveUtils.pxx` 的 `CalculateD0` 使用 `P' × D`；公共服务使用 `D × P'`，适配器因此反转传入 OCCT 的有符号距离，已有圆形与非平面曲线测试核对方向。
- [SISL s1360 手册，固定提交](https://github.com/SINTEF-Geometry/SISL/blob/e0a82b1a851e932657f3e1af25033fbbcd33e907/doc/manual/func/s1360.tex)。核查提交 `e0a82b1a851e932657f3e1af25033fbbcd33e907`。
- [GoTools OffsetCurveNormalDir.C，固定提交](https://github.com/SINTEF-Geometry/GoTools/blob/9b58396b7746ea97bfc51a8c540cee1b5c5eccdc/gotools-core/src/creators/OffsetCurveNormalDir.C)。核查提交 `9b58396b7746ea97bfc51a8c540cee1b5c5eccdc`，`eval` 为 surfacePoint + offset × surfaceNormal。
- [OpenCAMLib 官方 README](https://github.com/aewallin/opencamlib)，[CGAL Straight Skeleton 2 官方文档](https://doc.cgal.org/latest/Straight_skeleton_2/index.html)。没有将这些库的其他未核查模块判定为全部不支持。
- [LNLib 偏移源码，固定提交](https://github.com/BIMCoderLiang/LNLib/blob/20cc0fb4b22233069a5e10af32b3a34df7faf588/src/LNLib/Geometry/Curve/NurbsCurve.cpp)，[LGPL 2.1 许可证](https://github.com/BIMCoderLiang/LNLib/blob/20cc0fb4b22233069a5e10af32b3a34df7faf588/LICENSE)。`OffsetByPieglAndTiller` 对采样点调用 `Normal(curve, CurveNormal::Normal, u)` 后插值；这与任意外部刀轴方向场不同。

许可证也参与选型：OCCT 为 [LGPL 2.1](https://github.com/Open-Cascade-SAS/OCCT/blob/V8_0_0_p1/LICENSE_LGPL_21.txt) 加 [OCCT 例外](https://github.com/Open-Cascade-SAS/OCCT/blob/V8_0_0_p1/OCCT_LGPL_EXCEPTION.txt)，原型沿用已有动态库集成和许可证材料，发布仍按许可证履行相应义务。SISL 与 GoTools 源文件采用 AGPL 3，并列出商业授权路径和保留 producer line 的附加要求；这不等于算法技术上不适用。本次未将它们链接到产品。OpenCAMLib 与 LNLib 官方声明 LGPL 2.1。

补充核查：Sverchok 有 [Offset Curve on Surface](https://nortikin.github.io/sverchok/docs/nodes/curve/offset_on_surface.html) 现成节点；[源码](https://github.com/nortikin/sverchok/blob/master/utils/curve/algorithms.py) 使用局部曲面微分换算 UV 位移后映射回曲面，不能直接据文档描述宣称严格三维等距误差界，且为 GPL 3 的 Blender/Python 组件。作为曲面偏移算法研究候选，不宣称已适配本项目。

若范围扩大到商业现成组件，[ModuleWorks Laser-Aided Framework](https://www.moduleworks.com/industries/laser-aided-framework/) 官方提供包括五轴激光切割的路径计算、工艺参数、碰撞与连接运动能力。它是商业组件路线，不能归为满足“开源库”要求，也不能仅依据产品页认定特定刀补 API 已满足全部合同。

## 空间折线补充核查

空间折线是独立输入类型，不能因为上一轮重点查 NURBS 就漏掉。服务设计应直接接受 XYZ 顶点序列、开闭状态、补偿方向信息和折点连接策略，保留原折点。折线可精确表示为一次 B-spline，但这种表示转换不解决折点的切向不连续与偏移段接续；拟合成光滑样条还可能改变原轮廓，不能作为默认前处理。本节是新增选型与设计要求，不代表现有服务已实现折线接续。

| 候选 | 已核实的接口与能力 | 刀补适配限制 |
|---|---|---|
| [Euclid](https://github.com/goswinr/Euclid) | F#/.NET，[MIT](https://github.com/goswinr/Euclid/blob/d5d8cacb2f3c51931f978c7dec7a0d992a4fe6c2/LICENSE.md)。[Polyline3D.fs](https://github.com/goswinr/Euclid/blob/d5d8cacb2f3c51931f978c7dec7a0d992a4fe6c2/Src/Polyline3D.fs) 提供 `offsetWithRef`、`offsetVarWithRef`；直接接受三维折线，支持开闭、定量/分段变量偏移、参考法向 | [Offset3D.fs](https://github.com/goswinr/Euclid/blob/d5d8cacb2f3c51931f978c7dec7a0d992a4fe6c2/Src/Offset3D.fs) 用相邻线段叉积建立每个折点的局部平面；参考法向用于定向，不等于逐点工艺刀轴。已本地直接运行：偏移量 1 的非共面折线，中间输出线段的中点到原折线距离为 0.70710678；不能直接充当整段恒距刀补后端。详见后续实测 |
| [COMPAS](https://github.com/compas-dev/compas/blob/d1142516502456e0dd3f98cd2a5691924a82de80/src/compas/geometry/offset.py) | Python、MIT；`offset_polyline(polyline, distance, normal, tol)` 直接接受 XYZ 点列，支持分段端点偏移量；每段调用 `offset_line` | 使用一个共同参考法向。折点连接取 `intersection_line_line` 返回的两个点的中点；空间异面线的最近点中点不能自动视为精确等距连接，不能仅凭三维输入认定满足刀补要求 |

Euclid 的 [上游空间螺旋折线测试](https://github.com/goswinr/Euclid/blob/d5d8cacb2f3c51931f978c7dec7a0d992a4fe6c2/Test/TestOffset3D.fs#L439) 确实使用非共面点列，但该用例只检查点数及结果发生位移，注释还说明非共面折线不保证往返偏移还原。后续本地实测进一步确认其局部折点偏移与整段恒距之间的差别。COMPAS 仍只有源码核查，未本地运行。

折线刀补应分别验证线段内部与折点：线段内部按工艺定义检查补偿距离；折点按明确的延伸交接、倒角、圆角或受约束空间过渡策略检查。相邻线段分别偏移后可能成为异面线，不能总是假定延长就有交点，也不能取最近点中点后直接宣称精确刀补。

APT 是 Automatically Programmed Tool，即描述几何、刀具和加工关系的数控自动编程语言。APT360 是处理这种语言并产生刀位的程序；APT、刀位文件和最终机床 G 代码不能混称为一种刀补库。作者的 [项目说明](https://aptos.sourceforge.net/TheProject.html) 解释了 APT360 从 IBM APT 源码移植的过程；[多轴编程手册](https://github.com/smooker/aptos-apt360/blob/35d04b581a4f584c676d636c21d7cea0ccbee8ea/doc/manual/multiaxis_prog.html) 给出固定刀轴、曲面法向和倾角控制；[实际 OFFSET 实现](https://github.com/smooker/aptos-apt360/blob/35d04b581a4f584c676d636c21d7cea0ccbee8ea/src/AOFSET.c) 表明这一路线依赖加工曲面关系，不能仅将折线逐点写成 GOTO 就推定完成半径补偿。

geometry-central 的 [官方接口文档](https://geometry-central.net/surface/algorithms/signed_heat_method/) 和 [论文作者项目页](https://nzfeng.github.io/research/SignedHeatMethod/index.html) 可追溯至 2024 年论文实现。官方要求三角网格上输入折线经过的每条网格边有对应 SurfacePoint；不满足时会拆分曲线，过短片段可能被忽略。这是适配时必须验证的输入限制，不能把“接受点列”扩大为任意稀疏折线自动正确处理。

### Euclid 空间折线直接调用结果

使用固定提交 `d5d8cacb2f3c51931f978c7dec7a0d992a4fe6c2` 的未修改上游 `.fs` 源文件，按原项目源文件顺序建立独立探针项目；使用本机 .NET SDK 10、目标 net9.0 编译运行。未使用原项目的打包任务，未链接到产品。直接调用 `Polyline3D.offsetWithRef`，平面内偏移为 1、垂直偏移为 0、参考法向为 `(0,0,1)`。

| 用例 | 结果 |
|---|---|
| 平面直角折线 | 正常返回；三个输出段的中点到原折线距离均为 1 |
| 非共面直角折线 | 正常返回；三个输出段的中点距离为 1、0.7071067811865476、1 |
| 上游空间螺旋用例相同输入 | 正常返回；中间两个输出段中点的距离为 0.9486832980505133，首尾为约 1 |
| 中间共线点 | 正常返回；三个中点距离均为 1 |
| 相邻重复点 | 明确报错 |
| 180 度掉头 | 明确报错 |

非共面反例输入为 `(0,0,0) → (10,0,0) → (10,10,0) → (10,10,10)`，返回为 `(0,1,0) → (9,1,0) → (10,9,1) → (10,9,10)`。中间输出段的中点 `(9.5,5,0.5)` 到原中间段 `(10,0,0) → (10,10,0)` 的距离为 `sqrt(0.5²+0.5²)`，也等于到整条原折线的最近距离。此处测量在线段内部，不能以尖角处允许不同连接策略来解释为恒距达标。

结论只针对已测的该接口：Euclid 的结果符合该案例下的局部平面偏移语义，但该语义不满足直接用作全段恒距三维刀补的要求；不是宣称整个 Euclid 库没有价值。六个探针调用与中点距离检查也不构成任意输入的全曲线认证。原始结果在 `output/research/curve-compensation/euclid-probe-result.json`，探针入口在 `output/research/curve-compensation/euclid-probe/Program.fs`。另将参与编译的 52 个上游源文件逐个与下载归档比较 SHA-256，全部一致；构建与源文件核对证据在 `output/research/curve-compensation/euclid-probe-build-evidence.json`。

本轮选型进展：新增 APT360 的实际多轴接触算法和 geometry-central 的曲面距离计算候选；用实测收紧 Euclid 的适用范围；NCL、Raccoon 作为可查阅的加工实现线索保留，但未确认开放接入许可。仍未确认覆盖任意空间曲线、指定方向场、折点接续及误差要求的完整通用开源刀补后端。独立中性 `IService` 的架构要求保持不变，本轮没有更换产品后端。

## 能力与业务的分工

```text
CAM 工艺服务：切缝测量模型、厚度/控制面、留料语义、姿态要求
        ↓ 中性几何输入
framework/GeometryServices/ICurveOffset3DService : IService
        ↓ ServiceProvider 解析
plugins/geometry/OpenCascadeGeometryServices → OCCT
        ↓ 中性数据与明确验证范围
CAM 工艺服务形成过程路径；SDO 管理资源、版本、失效、事务
```

纯数据放 `foundation/GeometryData`，不从 foundation 反向引用框架。服务契约属于框架能力接口，算法提供者为独立 geometry 插件。服务不接收 Project/Scene/SDO、资源 ID、刀具业务对象或 UI 草稿，不写资源池或撤销记录。OCCT 类型不出插件边界。

基础能力使用“方向场曲线偏移”的中性名称，CAD 和其他 CAM 可复用。刀具补偿的实际半径、工具包络与成品尺寸含义由具体工艺决定；基础服务不能把一根三维曲线自动解释成某种刀具的中心轨迹。

## 首版已实现的合同

中性 `DirectionalCurveOffset3` 保存源 `CurveSegment3`、同参数参考方向场、有符号距离；不是强行转换成二维折线。

```text
P = 源空间曲线，D = 固定向量或参数向量场，r = 有符号距离
b(u) = normalize(D(u) × P'(u))
Q(u) = P(u) + r b(u)
```

固定方向调用 OCCT `Geom_OffsetCurve`；变方向使用 OCCT 的曲线和方向场微分，在服务内部计算 `b'` 与 `Q'`，不使用全局 XY 投影、不保留原 Z 冒充三维偏移。

首版支持 Segment、Circle、Bezier、非周期 BSpline、NURBS。方向场支持固定方向或 Bezier / 非周期 BSpline / NURBS 向量分量，要求和源曲线使用同一参数域。公共请求携带取消函数、样本预算和明确退化阈值。输出保留每点源参数、源点、偏移点、源导数、偏移导数及方向，失败不返回可误用的部分结果。

只改变 `Range.Reversed` 不改变物理几何侧。若实际反转曲线参数化，调用方同时翻转符号以保持物理偏移侧；测试覆盖这两种情况。刚体变换时源点旋转平移、方向系数只旋转。

成功状态明确为 `SamplesEvaluated`，验证范围为 `RequestedParametersOnly`。这是**基础求值能力已实现**，不是“完整三维刀补已完成”。接口不返回可加工状态，也不自动以拟合 B-spline 或离散线冒充原偏移曲线。

## 完整三维刀补仍需完成的能力

| 层 | 剩余工作 | 验收要求 |
|---|---|---|
| 几何服务 | 区间划分、拟合及偏移误差界，连续奇异检测 | 不只测采样点；能定位内部退化，预算超限明确失败 |
| 几何服务 | 角点接续、周期接缝、自交检测与按约束裁剪 | 拓扑变化明确报告；不任意改变成品留料区 |
| 几何服务 | 沿方向与控制表面求交、分支追踪、曲面域与连续性 | 返回交点参数与分支证据，多解/无解/切触不猜结果 |
| CAM 工艺 | 光束/刀具模型、测量截面、入口出口尺寸、完整厚度及姿态耦合 | 调姿后重算或重新证明尺寸；局部偏移点不直接当 TCP |
| CAM 集成 | 在工艺编译器中通过 IService 消费基础能力，形成完整来源映射 | 旧圆形特例不能充当空间曲线验收；未覆盖部分拒绝标为合格 |

对激光局部圆柱束模型，偏移点与方向定义束轴线 `L(u,λ)=Q(u)+λD(u)`。随后沿该束线求控制面交点，而非将 Q 任意正投影到曲面；否则可能改变束线与成品尺寸。这个工艺解释不进入几何数据的固有含义。

本次未将首版采样服务接入 CAM 正式编译入口。当前产品仍只支持原有圆形局部编译范围。后续全曲线验证与工艺解释齐备后再按对应支持矩阵开放，不以服务存在推断整条加工链已支持。

## 验证证据

### SISL 现成函数直接调用

已将上述固定提交的 SISL 源码下载到独立研究目录，以 VS 2022 x64 编译并直接调用未经修改的 `s1360`，未经过 OCCT 或自写偏移生成器。输入为非共面三次曲线 `P(u)=(u,u²,u³)`、固定参考向量 `(0,1,1)`、偏移距离 `0.17`、拟合公差 `1e-6`。

返回 `status=0`，结果为三维、4 阶、148 个极点的 B-spline。对 10,001 个输出样本独立检查到解析偏移曲线的几何距离，最大约 `9.45e-7`，低于所传公差；Z 最大变化约 `0.1202`。这证明该现成函数确实能生成非共面三维偏移曲线，不能将其归为“只有二维”。本地抽样检查不是额外的全区间误差证明。

实测也发现：直接用相同 u 比较源偏移定义与输出样条会得到约 `5.12e-4` 的点差，不能把拟合曲线的几何公差当作逐参数点差保证。接入服务时须显式重建来源参数映射，不可照抄输出参数作为源位置。

证据：`output/research/curve-compensation/sisl-probe-result.json`；可复现实验位于相邻 `sisl-probe` 目录。这个实验只链接 SISL 研究程序，尚未把 AGPL 依赖接入产品；固定方向、退化与全局拓扑限制仍然存在。下一步针对实际所需方向场和测量约束选后端，不提前锁定 OCCT。
