# TubeNesting

`TubeNesting` 同时包含旧锯切模型和当前生产使用的四姿态关系表模型。TubeDesigner
的排样入口只调用 `PairTableSolver`；旧 `Solver` 仅保留给尚未迁移的其他调用方，不能
作为新生产路径的隐式回退。

## 生产流程

1. 上游管型/展开服务按已经确定的 X 轴提供左右端口周期谱。谱必须声明来源质量：
   `NativeCertified`、`ApproximateCertified`、`NumericOnly` 或 `Missing`。
2. `BuildPairTable` 为每个有向类型对计算正正、正反、反正、反反四个最佳相对姿态。
   它使用连续相位的带界分支定界，不按固定角度步长扫描；四个方向组合可分别提供
   独立角度域，不能用一个组合的限制替代另外三个。
3. 表项固化净节约量、相对绕轴角和证明元数据。之后的顺序阶段只读不可变表，不访问
   BRep、不重新展开端线，也不在线试转角度。
4. `PairTableSolver` 联合决定实例顺序、每件唯一正反向、母材分段和 6000/12000 等
   有限库存。固定顺序使用两状态方向 DP 与精确分段；大组使用多起点、局部搜索和
   通用整根模式池及自适应跨根邻域，小组可交给 CP-SAT 完整模型。

## 通用整根模式池

`TubePatternMaster.inc` 对一般有向四姿态关系表建立真实可行的单根模式，不要求节约量
为常数。每个模式包含母材规格、类型顺序、每件统一方向、相对转角引用、类型数量及
占用长度；构造时调用公共方向 DP 和姿态重建，检查禁止边、容量、最大件数与订单数。
模式按“母材规格 + 类型数量向量”合并，相同数量下仅保留占用更小的真实路线。

已有完整方案的全部计数等价模式先入池，形成可行兜底。若连该集合都超过配置上限，
本轮跳过模式主优化，不截断旧方案。随后使用多起点、长件/紧排/有向配对效率等有界
构造增加模式；同一个模式按剩余类型数量和有限库存批量复用。没有初始方案时，也可
通过完整构造候选与合法单件候选尝试建立首个完整覆盖，但不保证受限池一定找到解。

Release 的计数主模型为每个模式建立一个非负整数变量，逐类型要求数量精确相等，
逐有限母材规格限制总使用量。按与原求解器相同的采购成本/名义长度、根数和占用长度
字典序优化，变量规模随模式池变化，不建立每件实例一套路由槽位。Debug 或关闭约束
后端时，使用有界模式计数组合枚举；池过大则保留完整构造候选，不把未完成枚举冒充
证明。最终仍按类型队列恢复唯一真实实例，并独立重算数量、库存、方向、转角、邻接
和容量；只有完整且严格改善的方案才替换已有结果。输出与最终校验仍需逐件实例。

模式主优化在初始构造之后、跨根邻域之前运行，新方案继续参与后续改善。当前任何
包含固定前缀续排母材的组会跳过模式主优化；该限制不关闭公共续排解码器和自适应
邻域，后者仍可在保持锁定前缀不动的条件下重排可动后缀。模式不会跨物理固定前缀
复制，也不会重复扣取库存。

`scope=restricted-pattern-pool` 及 `pool-optimal=true` 仅说明所生成有限模式池的计数
问题完成证明，不能设置整单 `FullIntegerModel`。未入池的其他类型顺序与单根模式仍
可能得到更优解。

## 自适应跨根邻域

`TubeAdaptiveNeighborhood.inc` 从余量较大、访问较少的母材开始，结合有向配对互补
关系和有限探索选择整根母材。选择同时受最大件数、剩余时间与估算模型体量限制；
停滞时适度扩大范围，连续超时或实际模型耗时超预算时收缩。不会只因有更多零件就
把整批实例交给完整 CP 模型。

对单根已经超过允许模型规模的情况，不将它整体释放进 CP-SAT，而是选择有限的弱
邻接位置及互补母材，尝试可复核的移动或交换。每个候选仍通过公共完整检查，保留
固定前缀、有限库存及唯一实例约束；一次局部模型最优只属于本次释放的邻域。

用于受控对比的设置如下：

- `PatternMasterTimeBudgetMilliseconds=0` 关闭通用模式主优化；默认预算为 1000 ms，
  `PatternMasterMaximumPatterns=2048`、`PatternMasterConstructionRuns=6` 控制池与构造。
- `AdaptiveConstraintNeighborhoods=false` 恢复原固定规模的随机整根邻域选择，不等于
  关闭所有局部搜索。默认基础邻域为 9 件/100 ms，配置最大值为 24 件/300 ms；实际
  还受模型体量和全局剩余预算限制。
- `ConstraintMode::Disabled` 始终不调用 CP-SAT；模式构造、自有有界计数枚举和原有
  表驱动启发式仍可运行。
- `TimeBudgetMilliseconds` 是表求解调用的总预算；模式准备、构造、建模、求解、恢复
  与校验都需要计入，单次 SAT 求解时限不能代替完整墙钟计时。

模式构造与单件补充使用提前截止时间，按实例规模和实测校验耗时动态预留恢复时间。
进入计数求解前，已知严格改善的完整构造会先恢复并独立验证，保存为可直接发布的
候选；新 CP 完整解也会在继续下一层目标前尝试保存验证后的检查点。后续时限耗尽
或新解恢复失败时，保留这份已验证候选或原方案，不发布未完成校验的模式计数。
这些是协作式墙钟预算，不能作为第三方求解器启动、收尾和操作系统调度的硬实时
保证；验收仍需记录实际总耗时及预算超出量。

`ResultMetrics.FirstFeasibleMilliseconds` 记录从 `PairTableSolver::Solve` 开始到主流程
首次接受全部兼容组完整方案的耗时，未找到时为 `-1`。它包含本次表校验与实例准备，不
包含调用前的 BRep 分析、端谱认证和配对表生成；应与总耗时、最终目标和终止原因
一起报告。内部模式构造、局部模型第一次产生候选的时间不自动等于该整单接受时间。

## 一维背包候选与重复模式

求解器先检查当前组关系表的全部合法方向组合：只有所有有向类型对都可相邻，且
净节约量严格等于同一个整数 `s`，才允许使用一维转换。禁止边、方向相关或类型对
相关的节约量会使该转换退出，继续使用通用表驱动搜索。判断依据是关系表本身，
不按管型名称、零件名称或近似长度分派算法。

对普通母材，设可用长度 `U = TotalLength - FrontMargin - TailDeadZone`，则：

```text
weight(i) = MaximumLength(i) - s
capacity  = U - s
occupied  = sum(MaximumLength(i)) - (partCount - 1) * s
```

要求每个权重严格大于零。正 `s` 表示互嵌节约，负 `s` 表示额外间隔，首件不重复
收取相邻损耗。数量背包只按权重 GCD 精确缩放，最多使用 32768 个容量单位；每个
候选累计 DP 工作量限制为 400 万。容量或工作量超限时生成贪心填充候选，不通过
向下取整权重伪造可放入的模式。

背包生成一个单根类型数量模式后，按剩余需求与有限库存计算可复用次数，批量取出
不同的真实实例，避免为每根相同布局重复求背包。复用仅用于构造候选顺序：顺序仍
送入公共方向 DP 和精确母材分段，重新检查每件身份、方向、容量、库存和所有边界。
同类零件不强制连排，单根模式也不冻结为不可改变的生产结果。顺序阶段仍保留每件
轻量实例，模式复用不等于消除了最终放置结果的逐件存储。

普通候选在原搜索完成后参与统一择优，使用原有采购目标，只有严格改进才替换已有
结果。独立随机源进行有限局部交换，并在 Release 的 CP-SAT 后端可用时尝试最多
两个跨根邻域；所有操作受原时间预算约束。有限库存、多个母材规格和续排仍由公共
解码器决定，模式构造过程的临时库存不修改调用方真实库存。

## 可证明的批量快速路径

当前快速出口限定为至少 32 件、单一无限量普通母材、无固定前缀、无最大件数与
订单数限制，并满足上述常数节约量和正权重条件。任何 `k` 根完整方案都必须满足：

```text
sum(weight(i)) <= k * capacity
barCountLowerBound = ceil(sum(weight(i)) / capacity)
```

若模式顺序经公共精确解码后得到完整方案，且根数达到该下界，则可立即结束搜索。
单一规格下采购成本及名义长度随根数单调，固定根数后的总占用长度又是常量，因此
当前字典序目标的所有层级均已达到最优，返回 `ProofScope::FullIntegerModel`。该证明
只针对给定整数关系表，不提升上游几何证书质量，也不证明共刀或机床可加工性。

未达到下界时继续原搜索；仅算出一个长度下界不能证明其一定可达。有限库存、混合
规格、续排或额外限制不使用此快速证明。诊断区分 `packing lower bound reached`
与普通 `packing candidates`，并记录模式数、复用根数或接受的候选数。

## 配对表缓存

TubeDesigner 使用进程内的有界 LRU 缓存，最多保留 8 张表，缓存持有容量按估算
限制为 128 MiB。相同已接纳键的并发请求共用一次建表任务；等待发生在全局锁外。
无效表、失败任务与超过预算的快照不作为长期缓存保留，容量不足时允许不缓存计算。
这是有界去重：若 8 个槽位都在建表，或待建键已用完字节预算，新键绕过缓存计算，
不保证该未接纳键的其他并发请求也能合并。待建键本身也计入缓存容量，完成任务先
发布快照再允许 LRU 淘汰。

键以完整规范化内容比较，不仅依赖哈希。失效字段包括类型 ID、兼容组、订单键、
轴向与净材料长度、正反向许可、左右端谱的来源哈希和质量、坐标约定、全部谱系数
及残差/导数界、默认与有向/四方向角度域、每个接口的工艺损耗、版本及配对求解精度
和区间预算。修改这些内容会重新建表。

需求数量不参与几何缓存键，命中后复制表快照并写入当前请求数量；母材库存、锁定
前缀、优先级层、放置结果及可变搜索状态不进入缓存。改变数量或库存仍重新求顺序
和母材方案，不会复用旧方案或扣取另一个请求的库存。缓存统计通过独立只读接口
提供，不随冷/热状态改变业务结果。128 MiB 是缓存持有容量的预算，不代表并发请求、
工作副本、BRep 和求解器的进程峰值内存。

## 已排母材续排

已经排过一部分、开放端为异形端口的母材按“固定前缀 + 虚拟前驱”处理，不把余下
部分误降级成一根平头短料。调用方为每根真实母材提供唯一实例 ID、原母材类型、
固定前缀终点 `E0`，以及最后一个已锁定零件的类型、正反向和绝对绕轴角。前缀不参与
重排；求解器只决定新零件。

若首个新零件为 `(j,b)`，最后锁定零件为 `(i,a)`，则直接读取同一张不可变关系表：

```text
firstStart = E0 - S(i,a,j,b)
firstEnd   = firstStart + L_j
firstRoll  = normalize(lockedRoll + relativeRoll(i,a,j,b))
```

之后仍按普通相邻边递推。容量检查使用绝对末端坐标，要求最终末端不超过母材总长减
尾部禁用区。续排实例数量固定为 1，已购母材在本轮目标中的新增采购成本和新增名义
长度均为 0；原库存先扣除这根实物，再把其开放尾部作为独立实例加入，因而不会重复
使用或重复采购。TubeDesigner 将新放置结果合并回原计划 ID，保留锁定前缀的位置与
姿态。

当前生产入口支持“已知锁定排样结果的最后一件形成开放端”这一场景。只有一段任意
扫描余料轮廓、却不知道其等价前驱端口和姿态时，不能伪造四姿态表；需先由识别服务
把该开放边界注册成可参与关系表的端口类型。

## 严格零件优先级

TubeDesigner 的每种零件带一个非负整数 `priority`，默认 `0`，数字越小越优先。求解器
按优先级分层：同一层的全部零件仍由完整的表驱动顺序/方向/母材模型共同优化；该层
全部排入后，结果立即冻结为物理母材的固定前缀，下一层通过上述异形端续排状态继续。
因此低优先级不能重新排列、移动或改变高优先级零件的姿态。

如果某一层存在未排零件，求解立即停止，后续层统一返回“未启动”。这不是排序权重或
候选偏好，而是硬分阶段语义。只有一个优先级时直接走原单层路径，不增加额外求解开销。

长度统一使用调用方定义的 `int64_t` 离散单位；TubeDesigner 使用 `0.01 mm`。零件
长度向上、母材长度向下、净节约量保守量化。`netSaving` 可以为负，表示相邻还需要
额外距离；禁止相邻由独立状态表示，不能用零节约量代替。

## 最优性边界

- 原生几何端谱当前增加一个限定解析入口：X 轴严格同轴圆管、完整内外圆柱壁和两个
  完整平面环形端口。由原生平面/圆柱参数直接建立一阶谐波，并检查完整实体支撑界、
  壁厚、拓扑公差和原生坐标中心；非零轴倾角、偏心、非圆或额外开口不获此证书。
  采样展开线不参与该解析证书的生成。目标包络只能保守扩张，左右谱共同平移半个
  长度增量，保持与实际刚体放置的居中坐标一致。
- `CertifiedEpsilonOptimal` 只说明端口谱及其已声明残差范围内的连续相位问题达到给定
  轴向误差；`NumericOnly` 永远不会被提升为原始 BRep 的几何证书。
- TubeDesigner 不允许 `NumericOnly` 或 `Missing` 端谱驱动生产互嵌；它们自动退到
  不重叠的轴向包络，直到识别服务提供可验证残差。
- `FixedOrderSplitOptimal` 只说明一个既定顺序的方向和母材切分最优。
- `ProofScope::FullIntegerModel` 才说明当前整数关系表模型已完成全局证明。
- 大规模 `HybridLargeNeighborhood` 通常返回高质量可行解；只有完整约束模型证明或
  上述严格下界快路成立时，才返回完整整数模型的全局最优。
- 产品的有限库存优先与严格零件优先级属于硬分阶段规则；单阶段或固定前缀下的最优
  不自动证明取消这些业务规则后的联合采购问题最优。
- 正节约量不等于共刀。关系表未显式携带共刀证据前，结果的
  `CommonCutWithPrevious/CommonCutCount` 保持为 false/0。

## 已验证单根模式复用

`TubeVerifiedPatternCache.inc` 将当前求解已验证的普通整根路线保存为有界、不可变快照，
实际接入模式主模型及持续改进。它保留类型顺序、方向、母材和数量向量，不保存物理
零件实例或最优性证明。`ReuseVerifiedPatterns=false` 可关闭读写。

缓存上下文包含表版本、类型身份/方向/订单、母材尺寸/限制及工艺标识；数量和库存
数量由每次请求重新约束。完整表项与姿态用双指纹流式读取，每次 Solve 的多轮搜索
共享分段进度，不复制或驻留整张大表。即使指纹发生碰撞，导入也必须按当前关系表
重新计算方向、容量和转角，因此不能凭缓存占用直接发布排法。

数量逐项足够的路线才可导入，并保留空间给新构造。缓存路线能按本次有限库存重复
组合，残量再由原构造补齐；完整候选仍走共同的实例恢复、独立验算和完整目标比较。
含固定前缀的组继续跳过该模式缓存。缓存与方案构造均消耗已配置时间，时限不足时
保留已有可行方案。

每个上下文还保留最多两个最终已验证的路线组合记录（模式及重复数、精确需求和
目标政策）。相同需求下，它们须重新核对当前库存、方向、姿态和容量，再恢复唯一
实例作为本次搜索的初始方案；同需求、目标和库存供给只保留更好记录，并从当前可用
记录中择优。只有同需求、同目标的记录仍适用，且在预算内成功恢复并通过验算时，
才把该记录作为本次不能退步的起点；缓存淘汰、锁冲突、数量变化或恢复未完成时没有
跨次保证。数量变化时使用单根数量支配构造。这样避免只缓存中途候选而遗漏上次最终好解。
有限总预算内预留最多 50 ms 用于最终记录发布，发布失败不影响当前已验证结果。

最多驻留 8 个上下文、估算 16 MiB；每个快照的普通模式最多 2048 个，每份最终组合
最多 2048 种不同模式，普通模式和最多两份最终组合共同受 4 MiB、20 万路线单元限制。
读者持有 shared immutable snapshot，淘汰不会使在用结果悬空；更新在锁外构造，
锁冲突则放弃可选缓存操作。核心 `PatternCache*` 指标用于验收，不序列化到
TubeDesigner 的持久化结果身份。

关系表验证也会核对实际位移 `L_A - NetSaving` 不小于所引用姿态的整数安全分离量，
该整数分离量须保守覆盖连续上界，误差区间不能被少报。额外保守间距与未认证的手工
可行表仍允许；这项一致性检查不扩大原生几何认证范围。

## 用户搜索策略与时长

TubeDesigner 的项目排样参数支持 `optimizationMode="time"|"utilization"` 和
`searchTimeSeconds`（1–3600 的整数）。旧项目缺少这两个字段时使用时间优先、5 秒；
界面为时间优先推荐 5 秒、利用率优先推荐 60 秒，用户可自定时长。

时间优先在有界初始搜索组合完成后返回。利用率优先通过
`ContinueImprovementUntilTimeLimit=true` 继续整根模式、跨根邻域及不同顺序的搜索，
每轮只接受完整目标严格改善的方案；模式构造用 `PatternMasterSearchRound` 分散候选。
已有完整方案不会被后来较差或未完成的搜索覆盖。完整整数模型已获证明时提前返回；
受限模式池最优仍不能当作整单最优。`ResultMetrics.RefinementRounds` 记录额外轮次。

总时间属于一次适配层请求，截面、严格优先级、有限/无限库存和部分缺料子集不能各自
重新领取完整预算。适配层给各阶段分配份额，保留小数量阶段的最低搜索机会，并用
同一全局截止时间限制；缺料阶段还
预留部分时间寻找可排子集。核心的持续搜索必须设置有限时间，多兼容组也预留后续组
的搜索机会。时间是软上限，包含适配层内关系表准备与搜索，不包括此前原生入口的
CAD 提取；第三方调用、完整恢复及收尾可能略超。最长时长不意味着必须等满。

搜索策略和时长随项目保存、传入求解请求，但不属于物理输入签名；修改它们不会使
已有合法排样或锁定前缀失效。零件间距、几何和库存仍按原规则校验。工艺、库存优先
及严格零件优先级不随策略改变，时间耗尽时也不把未找到方案误报为数学上不可排。

## OR-Tools

Release x64 在 `src/third_party/ortools/install/vs2022-x64` 存在已校验的官方包时启用
CP-SAT。依赖由 `src/third_party/ortools/prepare-ortools.ps1` 准备，版本和 SHA-256
固定在脚本中。官方 Windows 包使用 Release CRT，因此 Debug 构建有意使用独立枚举
后端，避免混用 `/MDd` 与 Release protobuf/STL ABI。最终 DLL/EXE 必须导入
`OrTools.Runtime.targets` 复制运行库。

表按类型而不是实例建立。1000 个类型对应 2000 个方向状态和 400 万有向表项；每种
10 件只在顺序层展开为 10000 个轻量实例。`PairEntry` 为 16 字节，构建后会对完全
