# TubeNesting

`TubeNesting` 同时包含旧锯切模型和当前生产使用的四姿态关系表模型。TubeDesigner
的排样入口只调用 `PairTableSolver`；旧 `Solver` 仅保留给尚未迁移的其他调用方，不能
作为新生产路径的隐式回退。

## 生产流程

1. 上游管型/展开服务按已经确定的 X 轴提供左右端口周期谱。谱必须声明来源质量：
   `NativeCertified`、`ApproximateCertified`、`NumericOnly` 或 `Missing`。
2. `BuildPairTable` 为每个有向类型对计算正正、正反、反正、反反四个最佳相对姿态。
   它使用连续相位的带界分支定界，不按固定角度步长扫描；四个方向组合可分别提供
   独立角度域，不能用一个组合的限制替代另外三个。
3. 表项固化净节约量、相对绕轴角和证明元数据。之后的顺序阶段只读不可变表，不访问
   BRep、不重新展开端线，也不在线试转角度。
4. `PairTableSolver` 联合决定实例顺序、每件唯一正反向、母材分段和 6000/12000 等
   有限库存。固定顺序使用两状态方向 DP 与精确分段；大组使用多起点、局部搜索和
   动态大邻域，小组可交给 CP-SAT 完整模型。

## 已排母材续排

已经排过一部分、开放端为异形端口的母材按“固定前缀 + 虚拟前驱”处理，不把余下
部分误降级成一根平头短料。调用方为每根真实母材提供唯一实例 ID、原母材类型、
固定前缀终点 `E0`，以及最后一个已锁定零件的类型、正反向和绝对绕轴角。前缀不参与
重排；求解器只决定新零件。

若首个新零件为 `(j,b)`，最后锁定零件为 `(i,a)`，则直接读取同一张不可变关系表：

```text
firstStart = E0 - S(i,a,j,b)
firstEnd   = firstStart + L_j
firstRoll  = normalize(lockedRoll + relativeRoll(i,a,j,b))
```

之后仍按普通相邻边递推。容量检查使用绝对末端坐标，要求最终末端不超过母材总长减
尾部禁用区。续排实例数量固定为 1，已购母材在本轮目标中的新增采购成本和新增名义
长度均为 0；原库存先扣除这根实物，再把其开放尾部作为独立实例加入，因而不会重复
使用或重复采购。TubeDesigner 将新放置结果合并回原计划 ID，保留锁定前缀的位置与
姿态。

当前生产入口支持“已知锁定排样结果的最后一件形成开放端”这一场景。只有一段任意
扫描余料轮廓、却不知道其等价前驱端口和姿态时，不能伪造四姿态表；需先由识别服务
把该开放边界注册成可参与关系表的端口类型。

## 严格零件优先级

TubeDesigner 的每种零件带一个非负整数 `priority`，默认 `0`，数字越小越优先。求解器
按优先级分层：同一层的全部零件仍由完整的表驱动顺序/方向/母材模型共同优化；该层
全部排入后，结果立即冻结为物理母材的固定前缀，下一层通过上述异形端续排状态继续。
因此低优先级不能重新排列、移动或改变高优先级零件的姿态。

如果某一层存在未排零件，求解立即停止，后续层统一返回“未启动”。这不是排序权重或
候选偏好，而是硬分阶段语义。只有一个优先级时直接走原单层路径，不增加额外求解开销。

长度统一使用调用方定义的 `int64_t` 离散单位；TubeDesigner 使用 `0.01 mm`。零件
长度向上、母材长度向下、净节约量保守量化。`netSaving` 可以为负，表示相邻还需要
额外距离；禁止相邻由独立状态表示，不能用零节约量代替。

## 最优性边界

- `CertifiedEpsilonOptimal` 只说明端口谱及其已声明残差范围内的连续相位问题达到给定
  轴向误差；`NumericOnly` 永远不会被提升为原始 BRep 的几何证书。
- TubeDesigner 不允许 `NumericOnly` 或 `Missing` 端谱驱动生产互嵌；它们自动退到
  不重叠的轴向包络，直到识别服务提供可验证残差。
- `FixedOrderSplitOptimal` 只说明一个既定顺序的方向和母材切分最优。
- `ProofScope::FullIntegerModel` 才说明当前整数关系表模型已完成全局证明。
- 大规模 `HybridLargeNeighborhood` 返回高质量可行解，不伪装成全局最优。
- 正节约量不等于共刀。关系表未显式携带共刀证据前，结果的
  `CommonCutWithPrevious/CommonCutCount` 保持为 false/0。

## OR-Tools

Release x64 在 `src/third_party/ortools/install/vs2022-x64` 存在已校验的官方包时启用
CP-SAT。依赖由 `src/third_party/ortools/prepare-ortools.ps1` 准备，版本和 SHA-256
固定在脚本中。官方 Windows 包使用 Release CRT，因此 Debug 构建有意使用独立枚举
后端，避免混用 `/MDd` 与 Release protobuf/STL ABI。最终 DLL/EXE 必须导入
`OrTools.Runtime.targets` 复制运行库。

## 规模和内存

表按类型而不是实例建立。1000 个类型对应 2000 个方向状态和 400 万有向表项；每种
10 件只在顺序层展开为 10000 个轻量实例。`PairEntry` 为 16 字节，构建后会对完全
相同的姿态元数据做有界去重；若姿态确实高度多样，去重会提前退出，不会再建立一个
无界的百万项哈希表。

完整设计、状态语义、性能数据和接入边界见
`doc/Apps/tube_nesting_implementation_plan_2026-09-20.md`。
