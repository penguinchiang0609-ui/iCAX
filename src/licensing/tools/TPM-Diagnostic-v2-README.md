# TubeDesigner TPM 证书诊断 v2

日期：2026-10-24。此包是独立诊断工具，无需重装 TubeDesigner，产品仍为 0.2.0，授权验证规则不变。

## 客户使用步骤

1. 将 ZIP 完整解压到一个文件夹；不要在压缩包里直接运行。
2. 在取不到证书的客户电脑上，右键 `Run-Diagnostic.cmd`，选择“以管理员身份运行”。电脑需能联网。
3. 等待完成，通常 1–3 分钟。将桌面新生成的 `TubeDesigner-TPM-Diagnostic-日期时间.txt` 发回。

无需知道刷 BIOS 的历史，无需先重启或清除 TPM。窗口出现“未以管理员身份运行”时，报告仍会保存，但部分项目缺失，须按第 2 步重跑。如果出现“Missing adjacent diagnostic executable”，请重新完整解压。

## Fix

- 区分 Windows 命令返回“权限不足”与有效的 TPM 状态，不把缺失数据当成正常。
- 自动预配状态同时记录枚举文字与数值，避免误读 `AutoProvisioning=0`。
- Windows ECC 公钥同时处理 P-256 普通格式和完整曲线参数格式（包括实际观察到的 P-384）。

## Add

- 比较 Windows RSA 背书公钥和产品当前标准模板生成的 RSA 背书公钥。
- 检查 RSA/ECC 证书、厂商模板与 nonce 的公共 NV 索引。
- 读取主板型号及版本、BIOS 版本及日期、TPM 固件、Intel ME 驱动版本、最近启动时间和近 30 天有限数量的 TPM 事件。ME 驱动版本不是 ME 固件版本；BIOS 日期不是刷写时间，历史刷写行为未必能从日志还原。
- 在客户当前网络下，用公开的已知有效证书作对照，记录 Intel HTTPS 服务的 HTTP 状态、错误正文、服务器时间及 TLS 证书信息。
- 分别查询标准 RSA、Windows RSA（相同时只查一次）、Windows ECC、标准 ECC P-256 的公开密钥摘要；每项失败独立记录。

## 数据和操作范围

仅向固定 `https://ekop.intel.com/ekcertservice/` 发送背书公钥摘要及公开对照摘要；正常 TLS 验证保持开启。不会上传私钥、授权文件、模型、主板序列号或报告。报告本地保存，含安装路径、设备版本、公开密钥摘要及有关系统事件，请仅用于本次排查。

本工具不激活软件，不改变授权规则，不安装或缓存证书，不清除 TPM，不改变 BIOS、TPM 所有权、背书种子或 NV。公钥对照过程中会创建临时 TPM 对象，结束后释放，不创建持久密钥。只尝试读取允许公开空授权且不计入字典攻击计数的模板/nonce 索引；不尝试主所有者密码。授权文件只检查存在和可读性，不读取内容。

## 如何判断结果

| 观察 | 下一步 |
| --- | --- |
| 已知有效对照请求也失败 | 先排查该电脑的网络、代理、系统时间及 TLS，不能据此判断本机证书未签发。 |
| Windows RSA 与产品 RSA 不同 | 继续核对厂商模板/nonce、Windows 公钥和各自查询结果，定位是否选错了背书公钥。 |
| 某个 ECC 查询成功，RSA 失败 | 核对该证书的真实算法和公钥对应关系；不自动改变产品授权算法。 |
| 对照成功，Windows/产品 RSA 一致，本机返回明确的未找到，且本地无证书 | 进一步向主板/电脑厂商核实证书预配及固件/背书种子历史；这些结果仍不能单独证明假 TPM 或确定刷机导致。 |

`containsCertificateField=true` 只是服务响应的诊断标记，不表示证书已验证或可用；诊断工具不会授予授权。某次在线查询 404 也不能证明设备从未拥有厂商证书。

## 本次工具验证范围

已在开发机真实 Intel TPM 上验证公钥读取、RSA 一致性、ECC P-384 与标准 P-256、公有 NV 查询、Intel 已知有效对照及 404 错误正文记录。打包后的 Windows PowerShell 5.1 流程另有本地验证记录。客户硬件原因须等客户新报告，开发机结果不能替代客户实测。
