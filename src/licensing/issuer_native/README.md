# iCAX 原生授权签发器

纯 C++ / Win32 程序，交付文件为一个 iCAX-License-Issuer.exe。
使用 Windows 自带加密组件，无需 Python 或额外运行时。

## 首次授权

1. 打开 iCAX-License-Issuer.exe，在右上角选择产品。
2. 点击“选择申请或授权”，选择客户导出的 .tdreq。
3. 在“授权选项”中选择页面和功能。需要多个产品时，逐个切换产品，选择其申请文件并勾选“本次包含”；各产品的设置分别保留。
4. 点击“生成授权文件”，输出一个包含本次所有产品的 .tdact。客户在各软件的“关于”页导入同一文件，各软件只启用自己的权限。

已有同名文件时另取序号，不覆盖文件。正式申请、试用申请自动识别；
试用申请可设置 1 至 30 天。客户名称仅用于签发记录，可留空。

## 客户付费升级

1. 客户在“关于”页点击“导出授权文件”，发来最近一次的完整 .tdact。
2. 选择这个文件。签发器自动读取全部产品、勾选并锁定已有权限。
3. 切换需要升级的产品，勾选新增功能。需要增加新产品时，选择该产品自己的申请文件。点击“生成升级文件”，把新 .tdact 发给客户。
4. 客户在原电脑的“关于”页导入，原有权限保留，无需重新申请。

试用转正式时可勾选“转为正式授权”。仅追加试用权限会保留原来的期限
和 TPM 计数器，不重新开始试用。再次升级选择最新授权文件；重复导入
同一个升级文件不会改变授权。完整多产品文件包含首次激活及历次升级链，
同一原电脑可以直接导入最新文件，无需逐次导入中间版本。已升级的旧文件只能重新导出相同的升级，
不能另建分支，旧授权也不能覆盖升级后的权限。

读取旧授权需要签发库中的签名记录，不能仅凭加密的初次激活文件恢复
全部权限。备份各产品签发库时须同时保留 native-ledger、native-upgrades 和 native-bundles。
记录缺失时恢复完整备份后再操作。

## 签发设置

本机自动发现所选产品对应的签发库，并读取当前 Windows 用户保存的口令。
读取申请时，如果口令尚未就绪，会再次检查本机保存的配置；仅刷新同一产品、
同一签发库的凭据，不改变尚未保存的目录选择。生成按钮置灰时，按钮旁直接
说明缺少申请、签发口令、授权选项或“本次包含”，不再仅凭申请验证成功提示可以生成。
换签发电脑时，在“签发设置”中选择签发库、输入口令并保存。
口令用于解锁加密私钥，由当前 Windows 用户加密保存；私钥不放在 EXE 内。

当前注册的产品为 TubeDesigner，支持产品、下料、加工、仿真页面及其操作
分别授权。取消一个页面会取消并禁用其下级操作。

## 添加其他产品

include/ProductCatalog.h 是编译产品注册表，每项声明产品 ID、名称、功能目录、
申请/证书格式、设备证明域、固定签发公钥及设置/签发库目录。
每个产品使用自己的功能声明与信任配置。同一个 .tdact 可包含多个产品，
每份内部证书仍绑定一个产品；同一客户、同一 TPM 电脑的产品才能合并。
每个产品必须提供自己的申请或已有授权，不能用另一产品的申请替代。
整份文件由其中所有产品分别签名，修改时需要每个产品对应的签发库和口令。
新增真实产品时添加声明并重新构建签发器；不能通过客户文件或可写配置替换公钥。

## 源码与构建

- IssuerWindow.cpp：产品选择、文件选择、功能勾选与后台生成。
- IssuerCore.cpp：申请验证、升级策略、签名台账和输出。
- IssuerCrypto.cpp：加密私钥内存解锁、签名和初次激活包。
- IssuerSettings.cpp：产品签发库发现和当前用户口令保存。
- include/LicenseActivation.h：桌面与命令行共同的客户端导入入口。

运行 src/licensing/build-issuer.ps1，默认输出 output/tools/iCAX-License-Issuer.exe，
同时执行全部七组原生软件测试。--self-test 使用模拟服务，不签发正式授权；
--check-settings 只读检查配置；--capture-ui <bmp> upgrade 使用合成授权显示界面。
--check-selection <申请或授权文件> <报告路径> 只读验证所选文件与当前界面就绪状态，
报告仅包含验证结果、权限掩码、凭据是否可用和按钮状态，不输出口令或私钥，也不签发授权。

多产品容器为 ICAXB001，内部初次激活包为 TDACT001，升级包为 TDUPG001，统一使用 .tdact 后缀。
客户端按内容识别；升级包与内证书分别验签，精确绑定原证书摘要和设备。
整个导入序列持有目录独占锁，完成原电脑 TPM 证明后原子替换授权。
单元测试使用隔离临时密钥与目录，硬件激活需另外实机验收。
