# TubeDesigner

TubeDesigner 是 iCAX 上的管材产品参数化设计、制造拆单与排样准备产品。

它按使用频率组织为“产品 → 下料 → 管型 → 草图 → 关于”。产品完成设计后执行拆单，拆单成功时由用户选择“导出零件”或“进入下料”；制造零件仍是领域数据，但不再作为独立的顶层页面。下料页左侧归集零件清单，中间显示真实三维几何，右侧说明当前选择，下方承载原材排样结果。草图支持直接绘制管型截面，以及在当前管件侧面绘制切割图；截面草图保存为“我的管型”，侧面草图随产品保存并在拆单后继续保留到制造零件。TubeOne 继续负责加工编程与机床执行准备。

## 产品分类、款式预设与板件（新增能力）

产品目录按“防盗窗 / 护栏 / 楼梯”分别展示；直跑楼梯护栏归入“护栏 / 楼梯护栏”，完整钢楼梯仍归“楼梯”。当前 9 个实际模板展开为 30 个目录入口，只有成功加载的可用模板才显示：

| 一级分类 | 目录入口 | 当前构成 |
| --- | ---: | --- |
| 防盗窗 | 6 | 单面窗的普通格栅、中间封板、下部封板 3 款，以及两面、三面、五面窗 |
| 护栏 | 21 | `modular-guardrail` 的 20 款预设，以及原直跑楼梯护栏 |
| 楼梯 | 3 | 直跑、L 形、U 形钢楼梯 |

组合护栏的 20 款包含二横档、三横档的直式、左/右 L 形、U 形、转角双立柱和中间大立柱，以及圆管、整板、下封板上竖杆款式。款式由 `extensions.catalog.presets` 提供初始参数，目录卡片使用独立预设标识，生成与保存仍使用真实模板 ID；选择后可继续修改尺寸，重复点击当前卡片不清空输入，编辑已有实例不会重新套用预设。缩略图由本项目代码生成。

板件是具有厚度的真实实体，不是显示贴图或伪装成管材。单面防盗窗可配置封板净宽、净高、板厚及相对可用区中心的水平/垂直偏移；启用开启口时封板位于窗扇内，否则位于主格栅内。封板带独立管框，相交格栅杆件分段。组合护栏支持板填充及可选带孔安装底板；板尺寸、厚度、材料等属性随制造零件保留。

板件随产品进入装配预览和拆单，纳入零件清单及 STEP / Excel 导出，并按板件显示宽、高、厚等信息。下料页明确提示板件另行下料，前后端均将板件排除在管材排样之外；**当前不包含板材二维排样**。

原直跑楼梯护栏的竖杆改为逐个柱间净空布置，按截面实际朝向计算净间距，避免竖杆与中间立柱重叠；手动竖杆总数分配到各跨，实际最大净间距超过设定值时给出提示。这是几何布置改进，不代表完成全部连接工艺或结构安全认证。

以上为当前已实现的类型与流程，不代表覆盖参考网站的全部产品、参数和制造工艺；也不包含板材二维套料或完整第三方 CAM 功能。下文保留此前各阶段的范围与架构说明。

## 当前范围

- 产品 ID：`icax.tube-designer`
- 工程扩展名：`.tubedesigner`
- 模板发现：运行时自动发现 `templates/*/template.json + template.py` 模板包，新增行业和管型不再修改 C++ 注册表
- 管型边界：产品的 `template.json` 选择管型；`templates/_shared/profiles/<id>/profile.json` 描述管型参数，`profile.py` 校验参数并一次生成 `[外轮廓, 内轮廓…]`。C++ 只按轮廓数组构造带孔二维截面并执行一次标准拉伸，把 `tubeDesigner.profile` 作为不透明模板数据传递
- 内置管型包：`rect` 与 `round` 已从各产品脚本迁移为独立管型包；新增标准等截面管型时，增加同结构目录并在目标产品 `template.json` 的选项中引用其 ID，无需修改 C++
- 正式 Python 模板包括防盗窗行业的 `single-face-security-window@3.0.0`、`two-face-security-window@2.0.0`、`three-face-security-window@2.0.0`、`five-face-security-window@3.0.0`，以及楼梯行业的 `straight-stair-railing@1.0.0`、`straight-steel-staircase@1.0.0`、`l-turn-steel-staircase@1.0.0`、`u-turn-steel-staircase@1.0.0`
- 防盗窗尺寸、开启口、装配规则、公开资料与尚未验证的连续折弯构造，见 [防盗窗模板依据](templates/SECURITY_WINDOWS.md)。默认样例及几何测试通过不构成安装安全认证。
- 楼梯行业：直跑楼梯护栏负责单独栏杆；直跑、L 形双跑和 U 形双跑钢楼梯负责完整多踏步产品，生成梯段边梁、逐级踏步横梁、休息平台骨架、扶手和立柱，并进入统一拆单与 STEP/Excel 导出流程
- 楼梯常用默认值：层高 3000mm、总级数 18、踏步宽度 260mm、梯段净宽 1100mm、休息平台长度 1200mm、护栏高度 950mm；模板会对踏步高度大于 175mm 或踏步宽度小于 260mm 的住宅常用尺寸给出提示
- 多面结构：两面为 L 形，三面由左侧、正面和右侧组成，五面在三面基础上增加上面和下面，形成背面敞开的箱式结构；相邻面共享转角立柱
- 制造开孔：多面模板按真实杆件相交关系给外框立柱、上下横梁及五面后梁生成减料孔，内部圆管穿过矩形横杆；这些布尔加工仅属于生产输出，装配显示不做布尔运算
- 截面：外框和横杆为矩形空心管，竖杆为圆形空心管
- 输入：界面手工参数
- 草图：截面图与管件侧面切割图可随时切换，两边各自保留绘制状态；截面未形成闭合轮廓时不生成三维预览
- 用户常用参数：产品 manifest 以 `template/parameter-preset/template-definition` 声明这种用户记录；具体模板 ID 作为 Subject，客户通过 `customer` 显式关系关联，不藏在 Payload 中。模板内置方案与“我的常用方案”在同一选择框中使用；保存时排除产品编号、主宽高等实例专属数据，模板升级后只应用当前版本仍存在的参数
- 基础版流程：定义管型 → 添加产品实例并生成装配预览 → 单实例拆单 → 在该产品的零件清单中复尺 → 导出 STEP + Excel 给第三方 CAM
- 高阶版流程：产品拆单 → 选择导出零件或进入下料 → 在下料页仅按截面归集零件 → 设置母材与零件间距 → 开始排样 → 导出所选或所有母材结果；“下料”使用独立商业授权 `tube-designer.production-workflow`
- 输出：装配预览、显式连接意图、分层制造零件清单、选中零件 STEP 与 Excel 零件清单；排样导出为每根母材一个真实零件装配 STEP，以及汇总的 Excel 下料清单。
Excel 批量订单解析、安装孔和吊装孔属于后续阶段。

母材与排样参数随项目保存，可撤销。每种零件截面初始母材长为 6000 mm，数量 -1 表示不限量，0 表示停用，正整数表示有限库存。用户可追加不同长度；有限库存先参与排样，剩余零件再使用不限量母材。当前仅提供零件间距参数，按最终制造几何的轴向包络保守锯切排样，不启用共边切割。

当前保存链路限制：设置已写入可持久化的项目场景字段，但公共顶部“保存”按钮仍是占位；包含制造几何的项目调用底层保存时，还会被缺少 `geometry.brep` 持久化编解码器阻断。完整图纸保存后重开尚未贯通，本次不修改该公共保存链路。

排样结果列表包含独立复选框，默认全选；“导出所选”只输出勾选母材，“导出所有”忽略勾选范围。选择导出范围不改变当前三维视图。结果列表不显示“已排样”状态列；零件或设置变化后禁止导出旧结果，需重新排样。每次导出新建独立子目录，Excel 保留原母材编号并映射 STEP 文件。三维零件采用高对比配色，右侧切割顺序色标与之对应。

“生成预览”和“拆单”是两个独立数据库命令。预览只创建装配构件与渲染资源，并通过装配 Transform 将二维设计平面竖立到世界 XZ 平面；拆单根据已提交的模板版本和参数快照创建制造实体、制造 BRep 及缩略图 Mesh。撤销拆单不触发三维 View 等待，只有预览资源引用、版本或姿态变化才同步新的 View revision。

拆单结果会作为制造领域数据保存在工程中，但不维护独立的“是否已拆单”布尔状态。界面只在产品实例当前 `GenerationRunID` 下存在数量完整的制造零件集时显示“已拆单”；修改参数并确认重新生成后，实例切换到新生成批次，因此自然回到“未拆单”。基础版零件清单按单个产品实例打开，并保留逐件复尺。高阶“下料”页跨产品仅按截面分组：左侧选择零件，主视图显示最终几何，右侧说明当前选择，下方显示排样结果。

## 领域边界

### 模板声明的基础拉伸体共享

防盗窗模板通过 `_shared/shared_tube_geometry.py` 在每次模板生成内部显式声明共享的基础截面及拉伸体。完整局部截面参数一致时共用 `profile2d` 节点；完整局部拉伸参数也一致时共用 `extrude` 节点。每根管子仍保留自己的稳定零件编号，并使用 `transform` 节点引用基础体、指定独立的位置和朝向。

共享仅适用于模板明确选择的裸管，孔刀具、钻孔、槽口和斜切仍按各零件独立定义。求解器不根据零件名称、材料、近似尺寸或外形自行合并；不同长度不会共用同一个完整拉伸体，非对称截面也不通过镜像冒充一致。布尔运算采用非破坏模式，不能修改其他实例所引用的基础体。

主流程在 Python 请求的 `context.geometryPurpose` 中说明需要显示还是生产。Python 据此生成不同的中性表达：防盗窗显示请求不构造孔刀具、布尔或展开槽口节点，生产请求才构造完整加工操作。每次响应只有一个通用 `result` 输出及对应几何，不向 C++ 传递包含 `display/export` 两套分支的完整图。原生求解器直接执行收到的整份表达，没有“显示时跳过布尔”的规则；中性表达有布尔节点就执行，没有就不做。

防盗窗默认、连接工艺和证据边界见 [模板说明](templates/SECURITY_WINDOWS.md)。单面默认四边框分料拼焊，多面可选择通长立柱直拼或上下框45°拼角，并分别设置正面/侧面格栅。插入定位和贴合焊接会改变真实杆长与开孔。显示仍为原管装配近似，斜切毛坯转角可能重叠；生产图才是含实际切角的零件，不把预览或模板校验标为安装合格证明。

生成产品时只请求并保存显示表达与模板身份、参数快照；首次拆单时，用该快照重新向 Python 请求生产表达。若磁盘模板版本或包摘要已经变化，拒绝用新模板悄悄补算旧产品，需重新生成。生产表达与制造零件在同一事务提交，之后恢复制造 BRep 使用该生产表达，不拿显示体替代。`tubeDesigner.manufacturingPartCount` 由 Python 返回制造项数量，不要求为了预览先生成生产几何。无用途参数的旧模板调用仍保留双输出合同；已有项目中的旧完整中性图继续使用其原有 `export` 输出。

共享范围是一次求解内，不引入显示与生产之间、不同产品之间或不同生成批次之间的几何结果缓存。同一次求解中多个实例引用的基础节点只计算一次。生产表达快照与已经生成的制造资源沿用现有生成批次生命周期，不会跨批次复用。更新模板和原生求解器必须配套部署。

### 领域组件

- `CProductInstanceComponent`：模板实例与参数快照。
- `CAssemblyMemberComponent`：装配语义、位置、预览几何及不透明模板属性，不定义具体管型字段。
- `CManufacturingPartComponent`：实际下料对象、制造几何及不透明模板属性，不解释具体管型。
- `CJointIntentComponent`：目标构件、插入构件、连接模式和间隙。
- `CGenerationRunComponent`：一次可追踪的模板求值结果；`NeutralModel` 保存生成时的显示表达（兼容旧完整图），`ManufacturingModel` 在拆单成功时保存独立的生产表达。

装配构件和制造零件使用不同实体与不同几何资源，避免在 V 槽折弯、拼焊、合并下料等场景中错误假设两者始终一一对应。
